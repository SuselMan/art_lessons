# Grafetto: инструкции для Codex

Прочитай `CLAUDE.md` и `.claude/rules.md` этой рабочей копии перед работой.
Это сохранённые инструкции проекта: архитектура, release track, worktree-first,
QA, issue workflow и карта понимания. Папку `.claude` не удалять.

Разрешения из старых Claude settings/hooks не исполняются в Codex. Действуют
разрешения текущей среды и инструкции Ильи: рутинную работу выполнять автономно,
публиковать коммиты через push только по его прямому запросу. Старое согласие на
push или merge в транскрипте относится к старой сессии, не к новой работе.
Обсуждение действительно новых архитектурных решений сохраняется как рабочий процесс;
повторных подтверждений уже согласованных действий не требуется.

Перед продолжением после перерыва прочитай `~/claude-to-codex/RESUME.md` и сверь
git worktree/status/log с GitHub. GitHub репозиторий называется `SuselMan/art_lessons`.
Локальный main может отставать; не считай его последним состоянием продукта.

Исходная память: `~/.claude/projects/-home-suselman-projects-pencil/memory/MEMORY.md`.
Она сохранена в архиве `~/claude-to-codex/claude-context.tar.gz`.
Прочитай индекс и затем релевантные заметки; исторические пути Windows переводить
на существующие Linux-пути, проверяя код. Для браузера используй Playwright/CDP
или dev bridge: `claude-in-chrome` здесь не подключён.

Код править в worktree задачи, не в общей основной копии. Нативные навыки:
`grafetto-device-testing`, `grafetto-verify`, `grafetto-design-discussion`,
`grafetto-frontend-design`.
Перед архитектурными изменениями проверять `docs/architecture/understanding.yaml`.
Для issue в ответах Илье давать короткое название вместе с номером.

## Явный статус выполнения

Перед каждым ответом проверяй фактический статус работы по активной задаче.
Если работа не запущена, остановлена или после ответа не будет продолжаться,
явно пиши: «Пока ничего не делаю» и коротко объясняй причину. Если выполняется
только другая часть запроса, называй, какая именно часть пока не выполняется.
Не создавай впечатление фоновой работы, когда её нет. «Буду проверять»,
«следующий шаг» и описание плана не означают начала выполнения.
Пиши «делаю», «проверяю» или «работаю» только когда действительно выполняешь
названную работу в текущем ходе или есть подтверждённый запущенный процесс/агент.
Это правило не заменяет выполнение уже разрешённой задачи: её нужно продолжать,
а не ограничиваться сообщением о бездействии.
