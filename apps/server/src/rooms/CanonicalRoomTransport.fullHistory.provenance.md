# Explicit mixed full-history read receipt

The existing transport accepts an explicit `fullHistoryFormat: 'mixed-v2'` server policy; omission preserves the frame-only V1 lane. No startup/join callback requests this mode by default. The same full-range indexed query supplies all operations and ordered rows under the captured cut, floor zero, no stored layer state, pending-write fence and repeated read authorization/context checks.

Source frames bind through the existing ROOM descriptor resolver. Each close is paired with its actual indexed row and checked by `readRecordedPrefix`, preserving the distinction between material end and a metadata close seal. One shared attachment preparation and the full-history verifier then validate source context and chronological close/undo/redo dependencies. Query evidence remains with the private original receipt; the pure shared fold cannot create that authority.

Only the original receipt with exact operation pointers can produce `full-room-prefix-v2` metadata. Copied, foreign, stale, suffix and metadata-only prefixes fail closed. Close-bearing ordinary suffix reads and preparePrefix remain unsupported. Existing V1 default behavior and snapshot coverage are unchanged; this does not enable a producer, renderer, join or physical database guarantee.

Tests reuse actual source author/adapter/encoder and real persistence receipt machinery with a mocked indexed database. Seven new cases first failed against the old transport. Further witnesses cover authorization revocation, storage owner replacement and cut advancement during the real query await, and a close without its complete source prefix. Legacy soft transport, full-range query and snapshot loader regressions run together. No hardware or online activation claim follows from these host tests.


## Indexed metadata candidate prefilter (#807 / ADR017)

The explicit indexed lane now passes its authenticated `undo`/`redo` action to the existing actor-root keyset query. A single metadata-only SQL filter follows actual original target edges, seeded by **all** source frames of each actor/stroke, with same-actor, increasing-sequence and fixed-cut restrictions. It excludes metadata-ineligible roots before source bodies/prefixes are fetched. Redo uses the first undo after the latest redo, and only an own frame-zero original after that first undo invalidates the hidden branch. Repeated undo does not move the branch boundary; peer roots and continuations are not new own gestures.

SQL eligibility is only a candidate predicate. It does not expose a visibility boolean or mint read/paint authority. The same actual root/source/terminal/U4 evidence, fixed original cut, fresh authorization and owner checks remain mandatory in `Transport.select`. OPEN roots can pass the undo metadata filter and must still be rejected by actual terminal evidence. The descending keyset advances only over returned rows; scalar64, uncompressed body4MiB, short transaction limits and default-OFF policy are unchanged.

A meaningful actual-PostgreSQL counterfactual, using only TEMP rows, first returned64 hidden roots against the old unfiltered SQL instead of the older eligible original. The production query then passes1025-hidden-root selection and actual-edge vectors for middle-frame aliases, metadata chains, repeated undo, branch invalidation, redo reset, peer roots, own continuation and fixed-cut boundaries. The TEMP body adapter deliberately avoids Prisma's schema-qualified public table: these are SQL/data tests, not valid brush/material grants. TEMP objects are dropped and the owned client disconnected. Source-only mocked database tests separately exercise the real source author/encoder,70 hidden ended roots and a newer OPEN original, proving only OPEN plus the actual chosen eligible root build evidence; selected attachment/first/terminal come from actual originals. Scalar/body tests retain byte-prefix, keyset, revocation-before-body and oversize-before-body guarantees.

The ignored HOST benchmark at commit4b61 used1025/4097 completed synthetic roots. All baseline loops were deliberately incomplete after6s; the candidate-only query completed in17–198ms with one data statement. These are core SQL measurements excluding production short-transaction setup/commit, fresh authorization, CAS/material decoding and UI work. They do not establish an end-to-end speed ratio, native pixel compatibility, or device latency.
