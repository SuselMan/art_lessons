# Trusted mixed full-history join bootstrap

One immutable `CanonicalRoomTransport.fullHistoryFormat` policy selects the read mode and is captured on the original read owner. Its default remains frames-v1. Only explicitly constructed mixed-v2 transports permit reading stored straight room metadata through the join raster check and cold loader. Default callers, create_room and server startup remain unchanged; this is not permission, source admission or a client-selected flag.

For a straight mixed read, join requests the original full indexed receipt at floor zero and passes zero to BOTH snapshot construction sites, regardless of the client cursor. The existing authorized join preparation checks read permission/lifetime, every query await rechecks the same owner, and finish binds exact full-tail operation pointers. The same-turn finish -> seating -> channel join -> room_state ordering is retained. Missing rows, unsupported sources, snapshot coverage or stale context fail before seating/publication.

Tests first failed for the stored straight gate and missing full bootstrap. Following the real cold path exposed a second legacy-only guard in roomLoader, which now accepts the SAME trusted format parameter; there is no second opt-in flag. Actual Socket.IO/mocked database tests cover a genuinely cold stored straight board with a high client cursor and real cut-zero terminal query, a persisted source/close tail despite lastKnownSeq=999, and omitted history refusing a new participant before seating. Loader and raster tests retain the default legacy-only contract. This is host integration, not physical Postgres durability or an enabled production/ordinary Room deployment.
