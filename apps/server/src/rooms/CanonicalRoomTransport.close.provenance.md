# Typed own-session durable close writer

`CanonicalRoomTransport.close` consumes the existing closed typed request and requires the actor's existing admitted V2 session on the same layer. It does not create a target session or invoke BEGIN. It flushes the durable source tail, obtains the actual indexed gesture prefix at a captured cut, binds that prefix through the ROOM resolver and derives the server timestamp, first frame, close sequence and seal. The final synchronous owner/cut checks precede the existing append/receipt and admission-ticket commit; ACK waits for durable success and current paint policy.

Exact same-ID receipts are resolved before the ended cursor shortcut. Pending callers share the existing write attempt; a failed write repairs only its immutable ID, without a second sequence or pin. An indexed duplicate under an existing current session is verified against the real row and complete prefix without adopting a receipt. Cold requests without a session fail closed; a future full-read session rebind is separate.

An actual resident close blocks fresh live/recorded ordinals at or beyond its recorded cursor, even if an unexpected internal admission commit throws after append. Previously recorded duplicates remain available. A known resident seal also rejects a different close ID before querying. That regression failed before the additional guard. The exact same-ID retry can verify the durable seal and repair that cursor. This uses the existing room operations, not a new poison registry or queue.

Host tests use the existing author/adapter/encoder, real persistence receipt machinery and mocked indexed rows. They cover durability wait/failure/repair, immutable duplicate body, prefix/actor/count/last-frame/cut/layer authority, absent session, accessor refusal, post-write policy change and injected admission commit failure. The initial tests-first run was stopped after the missing API left a deferred fixture write pending; it is not claimed as a completed red gate. No socket listener, producer, default policy or ordinary Room activation is enabled, and no physical database/device durability is claimed.
