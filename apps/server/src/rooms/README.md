# server/src/rooms — комнаты и релей

Сердце сервера: комнаты в памяти, подкреплённые Postgres, ретрансляция операций всем
участникам, живые штрихи и курсоры, undo/redo, заморозка. Сервер никогда не рендерит — он
пересылает операции. Внизу реестр (`roomRegistry.ts`): запись комнаты, Map, правило урок/доска,
очередь записи в Postgres; над ним — какие строки комната пишет по ходу (`roomPersistence.ts`).
Поверх него отдельно: структурный лог, проверка операций, правило покрытия снапшотом
(`snapshotCoverage.ts`), хранилище снапшотов (`snapshotStore.ts`), рычаги владельца — заморозка,
инструменты, закрытие, доступ, блокировки слоёв (`ownerControls.ts`) — и живой класс: доски,
задания, подсветка, руки (`classroom.ts`). Холодная загрузка из Postgres — `roomLoader.ts`;
журнал операций — `operationLog.ts`; взгляды для здоровья, сторожа и админки — `roomStats.ts`;
кто может войти в комнату по сокету — `roomAccess.ts`; проводной вид сущности комнаты —
`roomMapper.ts`. В `rooms.ts` остаются создание, вход и выход, выселение и room_state. Сокетный
протокол целиком — `socketHandlers.ts`.

## Заметки

- Работа в классе (ADR 015): личная доска — доска урока с владельцем-учеником. Кто её видит,
  решает одна функция canSeeBoard (`lessons.ts`) — и для join_room, и для REST, и для
  LessonState, который собирается под получателя и шлётся событием lesson_state.
- Map остаётся источником правды для всего живого; запись в Postgres — fire-and-forget, её не
  ждут на горячем пути. Плата: операция, проигравшая гонку падению сервера, выпадает из истории,
  хотя уже была ретранслирована.
- Комната, которая читается как стёртая, — это испорченная строка RoomLayerState, а не
  потерянные данные.
- `rooms.ts` разбирается по доменам (#612).
