# Частичное закрытие pointer source

Обычный `PointerData.cancelled` останавливает SAME author FIFO без синтетического END. Только этот путь сохраняет здоровый recorded/coordinator owner. Lock/tool/size/visibility/context loss и CPU/GPU ошибки сохраняют прежний poison/recovery путь.

Source session хранит только first/last handed-off operation ID, число frames и флаг фактического encoder-ended для последнего переданного envelope. Encoder cursor не используется: encode может опережать callback при backpressure. Close issued ставится до SAME onLocalOperation callback; metadata отправляется один раз через существующие Outbox→typed sender. Это не recorded/source grant. После cancellation original confirmed frames и seal поступают через существующий original-read receiver.

Reentrant cancellation использует один внутренний Error identity, чтобы только ожидаемая остановка generator подавлялась; callback/release/прочие ошибки остаются fail closed, включая throw undefined при отсутствующем cancellation sentinel. Late close callback failure retires layer and releases CPU. Source release ждёт завершения активной `.next()` по существующему FIFO.

Tests-first: partial pointer cancellation RED (3 outgoing frames, expected fourth close); zero-emission/normal END controls passed. Новые host tests покрывают original BEGIN/prepared room→actual pointer→frames→cancel→original confirmations/seal, eight-frame backpressure с девятым encoded-but-not-handed-off envelope, callback reentry и throwing frame/close callbacks. One existing native author test migrated from pointercancel to tool change to retain its fault-cleanup witness; other 15 cases unchanged. Mock GL/host execution, не device/native pixel proof.

При интеграции обнаружен и отдельно подтверждён реальный конфликт cold target admission. Перед подтверждением coordinator не имел presentation work/commit plan/raw ownership, но SAME executor удерживал stable ticket с buffer=false/storagePins=1. Original confirmation вызывал orderEntries→invalidate, после чего приоритет presentation пытался повторно зарезервировать этот target. Детерминированный actual-engine тест принудительно завершает turn после cold ticket preparation, передаёт original confirmed frames+seal и воспроизводит ошибку до исправления (73527 RED).

Executor getter выводит pending layer-target preparation только из существующего head Work.physical/targetCursor, без нового состояния/authority. Coordinator находит в SAME bounded queue именно владельца такого ticket и выполняет один его существующий turn до presentation/commit. При отсутствии pending preparation порядок неизменен. Детерминированный тест и обычный cancel→seal проходят после исправления; 156 tests/3 suites PASS14869; после усиления undefined-throw witness 157 tests/3 suites PASS18434 и окончательные 10 cancellation tests PASS22432 (16 native author +132 executor/coordinator без дальнейших production изменений). Pixel/device/performance claims не добавляются. Отдельный потенциальный paused-commit + later unconfirmed gesture сценарий требует собственного воспроизведения; данное доказательство относится к executor cold preparation.

Дополнительный constructor guard допускает только уже реализованные native/generic author profiles до origin callbacks/canvas allocation. Новый browser-highp read profile сам по себе не даёт engine execution grant.
