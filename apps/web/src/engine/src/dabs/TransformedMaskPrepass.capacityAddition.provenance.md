# O2: retained prepass capacities

This leaf adds explicit retained-capacity participants and additive capacity preparation to the existing prepass. It does not activate engine/executor integration (O3), alter mask arithmetic, duplicate shaders, or promise a measured runtime memory reduction.

A retained participant captures the actual workspace, slot dimensions, UV denominator, source bindings and reset lifetime. Old slots and an explicitly captured pending auto cursor remain attached to their original record after publication of a larger default record. A bare legacy pending cursor prevents capacity addition before allocation; its existing completion path remains available. Destructive G1 replacement continues to reject borrowed records. Additive source publication changes only the default record; nondefault maps, slots and pending cursors remain unchanged.

Brush GL turns acquire participant lifetime holds before capture and release them after restoration, attempting every cleanup while preserving the first error, including `undefined`. Forced context-loss reset invalidates tokens without deleting lost names; the outstanding turn still releases its original hold rather than decrementing a new lifetime.

Accounting uses the existing CPU owner and cache ledger. Capacity metadata (1024 plus 192 bytes per slot) is reserved up front. Each retained facade reserves 2048 bytes before creating its closures; this is a conservative accounting allowance, not an exact JavaScript heap measurement. Source-map metadata is charged in full and resized when the default pinned source map grows. Candidate, retained and companion GPU keys form one unique-byte union before allocation/publication. Temporary construction inventories remain charged until cleanup. Failed first pins, cancelled additions and constructor failures restore prior reservations and pins.

`BrushTextureCache.leaseRequired` uses the existing lease ledger, captures own data metadata and rejects conflicting charges or an over-budget combined union before admission. It permits future staging keys: it is a budget pin, not evidence of physical allocation, cache readiness or epoch. Prepass publication and use independently revalidate actual cache entries and the captured lifetime. Existing optional `lease` behavior remains unchanged. Closed facades should be released by callers; no garbage collection or physical RAM claim is made.

Tests cover old/new actual image UVs and cache reuse, retained cursors, wrong receivers and participants, rollback, loss, cleanup reentry, source-map accounting, required-pin competition and source-construction reentry. The first six-test run failed because the new API was absent (`R52/o2-capacity-addition-red.log`). Intermediate test-fixture errors (missing work limits, recording-GL upload methods/protection and one metadata expectation) are not claimed as production regressions. The upfront metadata reservation fixed genuine mid-operation budget regressions without relaxing existing tests.
