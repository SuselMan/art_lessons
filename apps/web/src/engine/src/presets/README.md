# engine/src/presets — пресеты инструментов

Числовые характеры инструментов: карандаш и его грифели, уголь, маркер, линер, кисть-перо,
акварель с пигментами, цифровая кисть и её набор — вместе с формой даба по инструменту
(`dabShaping.ts`), растровыми кончиками и текстурами кисти, которые генерируются на CPU
одинаково на любом устройстве (tipMasks), наклон и его кривые, тактильное зерно, зерно
растушёвки.

## Заметки

- `dabShaping.ts` и пресеты кисти-пера, маркера, цифровой кисти и акварели импортируют друг
  друга (цикл по файлам известен и лежит в базе нарушений); внутри одного модуля это
  терпимо, а по разные стороны границы модулей — нет, поэтому `dabShaping` живёт здесь, а не
  в `dabs`.

Цифровые встроенные и импортированные кисти нормализуются через `brushNormalization.ts` в один stamp/mixer контракт. Старые встроенные токены используют актуальный набор по решению владельца до релиза. `brushBehavior.ts` отвечает за логическое состояние, динамики и независимый вторичный интервал, `wetMix.ts` — за расход/подбор пигмента. Vendor reference QA не заменяется тестами детерминизма.

Анимированные bitmap-кончики (`tip.animation`) выбирают кадр до scatter, один
раз на логический даб. Incremental начинается с нулевого кадра и циклически
перебирает кадры; random использует отдельный воспроизводимый поток Grafetto,
не меняя существующие соли jitter. Счётчик принадлежит `BrushBehaviorState`,
поэтому сохраняется между чанками, в scratch snapshots и копиях preview.
У независимой второй кисти собственный счётчик после её resampling. Точная
последовательность случайных кадров исходного приложения не обещается.
`importedBrushAssets` перечисляет кадры обеих кистей для загрузки до replay.

`tip.maskBounds` задаёт только UV-прямоугольник внутри POT-текстуры: геометрия,
радиус и spacing не масштабируются. Отсутствующее поле эквивалентно
`{x:0,y:0,width:1,height:1}`. Эта адресация применяется также к Bleed и второму
bitmap-кончику в обоих общих stamp/mixer шейдерах.
