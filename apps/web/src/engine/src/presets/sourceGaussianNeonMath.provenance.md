# Gaussian explicit NEON numerical CPU reference

This unused CPU module provides the numerical pieces needed by the separately selected Gaussian vector reference. It does not select the GUI factory, activate a brush profile, claim physical execution or promise hot rendering performance.

The reciprocal-square-root estimate is constructed from the ARM8fraction-bit mathematical law, using a binary search on integer squared thresholds; it is not a reciprocal lookup or copied pseudocode body. Normalize subnormal exponent/mantissa, select the parity-dependent upper mantissa bucket, use its midpoint, find the integer square threshold and encode8fraction bits. Integer products stay below2^31 and are exact in binary64. Inputs are positive finite binary32 or canonical+0; −0/negative/nonfinite and unrounded inputs reject explicitly. This is a closed Gaussian norm API, not all ARM exception/NaN semantics. ARM specification origin is DDI0596 shared FPRSqrtEstimate/RecipSqrtEstimate; the official endpoint was unavailable during retrieval. The mathematical law was cross-checked against the primary QEMU ARM implementation and, independently of this CPU model, original ARM instructions under Unicorn.

Actual Gaussian code at542a00..542a1c executes FRSQRTE, norm*estimate, FRSQRTS, estimate*step, norm*refined, a second FRSQRTS and **product*secondStep**. It is not host Math.sqrt, nor a rearranged norm*(refined*step). The implementation preserves this order. At the positive Newton domain, a*b is in[.5,2], its exact product needs48bits and subtracting from3 fits binary64; rounding only after halving models the fused step exactly. Zero is handled before the Newton sequence, matching the final zero mask for nonnegative Gaussian squared norms.

Independent instruction proof:6144 original sequences, all upper-mantissa bins at both exponent parities, exponent extremes, subnormals and random positive raw inputs. All estimate/step/refined/final result bits match. The fixture records the pre-zero-mask sequence; zero's NaN intermediate is not misrepresented as a final Gaussian distance. Instructions were register-renamed from the unchanged installed kernel, executed at FPCR0; no arithmetic hook. This is instruction emulation, not physical Samsung FRSQRTE validation.

Vector erf is **Krita VcExtraMath**, pinned `bd6e8d061d2f0388c5b10278786cf0fe62e3135f/libs/image/vc_extra_math.h` and `kis_brush_mask_processor_factories.cpp`: AS-style F32 polynomial,9.3 saturation and exp, with source F32 operations/FMA preserved. The closed exp reduction/polynomial constants are from primary xsimd13.2 generic math sources. That version is a reading aid, not a recovered APK dependency version; original instructions and independent whole-mask outputs remain the conformance authority. No host Math.exp is used. Common `sourceFmaF32`, refined divide and RNE byte math are reused.
