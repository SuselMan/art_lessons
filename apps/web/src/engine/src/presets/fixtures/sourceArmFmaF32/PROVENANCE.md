# Exact finite-binary32 fused value baseline

`arm64FusedMultiplyAddF32Bits(aU32,bU32,cU32)` accepts ONLY finite binary32 bit
patterns and returns the correctly rounded RNE/gradual-underflow value of the
EXACT real product plus addend. Output may overflow to signed infinity. Raw NaN/
Inf inputs are rejected, not partially emulated. Signed zero follows RNE: an
exact cancellation is+0 except when both zero product and zero addend are-0;
a nonzero negative exact value rounded below the subnormal threshold becomes-0.
`arm64FusedMultiplyAddF32` first narrows numeric inputs to F32, then uses the raw
primitive; malformed/nonfinite/narrowed-overflow inputs are rejected.

This is authored integer-significand mathematics, not copied ARM pseudocode and
not a clean-room claim about the surrounding project. Decode normals as24-bit
integer significand times2^(biasedExponent-150), subnormals as fraction times
2^-149. Multiply integers EXACTLY; align addend at the smaller power of two and
add signed BigInts EXACTLY. Choose either24 significant bits or the fixed2^-149
subnormal quantum. Compare discarded integer remainder with half-quantum and
increment only above-half or odd-quotient ties. Handle significand carry into the
next binade and overflow only AFTER the one final round. No IEEE/double product
or add occurs before that round. Intermediate exact integers are bounded by the
finite-binary32 exponent range; no unbounded external precision is accepted.

It is deliberately a BigInt VALUE reference, NOT a hot-renderer fast path,
GLSL implementation, FENV/trap/NaN-payload emulator, alternate FPCR mode,
installed factory selection or proof of a complete fused compositing graph.
Source-specific operand ordering/rounding points must still come from actual
kernel mapping; substituting FMA into every lerp is incorrect.

## Independent host oracle

`native.cpp` is an authored tiny C++ driver calling the real
`std::fma(float,float,float)` overload. Existing /usr/include/c++/13/cmath2193–2195
maps this to __builtin_fmaf; binary disassembly independently verifies a call to
`fmaf@GLIBC_2.2.5`, not a separate multiply/add expression. The oracle sets
FE_TONEAREST and MXCSR0x1f80 explicitly. Compile flags disable OTHER compiler
contraction and fast math; they do not disable the explicitly requested fmaf.
No original ARM/Krita/Qt function bodies, SDK or dependency runtime is copied.

`host-fma.native.json` contains11200 actual native output bit tuples, including
8192 deterministic random raw-finite triples. Adversarial grids cover signedzero,
maxfinite, cancellation of rounded products, product overflow cancelled back to
finite, normal/subnormal boundaries, exact half-ULP ties, overflow midpoint and
its adjacent neighbors. All11200 match the integer reference exactly.

Meaningful double-round witness, also in native data:
fma(bits3fc00000,bits3f800001,bits80000001) =bits3fc00001. The exact product is a
binary32 midpoint; subtracting2^-149 chooses the lower neighbor. Binary64 loses
that tiny addend and rounds the same expression to3fc00002. A binary64 product/
add cannot substitute for this general finite F32 fused value primitive.

Reproduce with ONE registered minimal compiler resource:

```
g++ -std=c++17 -O2 -fno-fast-math -ffp-contract=off -frounding-math native.cpp -o <registered>/fma-oracle
<registered>/fma-oracle > host-fma.native.json
```

`native-proof.json` pins driver/expected output/compiler/libm/header/binary SHA.
The host std::fma oracle is not a claim of actual ARM FMA instruction execution.
