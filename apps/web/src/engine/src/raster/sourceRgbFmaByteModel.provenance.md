# Specialized RGB fused byte operation: CPU proof model

The unused model computes native `RNE_integer(F32(FMA(t,sourceByte-destinationByte,destinationByte))) mod256`, with finite binary32 t in[0,2]. The three-channel entry decomposes the coefficient once. It neither replaces general alpha FMA nor activates a renderer/profile. Raw U32 coefficient bits are CPU serialization, never a value carried in one GLSL highp float.

The range includes actual scalar Over FRECPE overshoot. A source search found srcA255,dstA1,opacity=f(.95),S242.25,alpha242.30001831054688,blend1.0017356872558594. Eight original whole-kernel executions independently validate RGB outcomes around that witness and the endpoint. Alpha coefficients remain in[0,1]. For Over's nontrivial D in[1,254], alpha>=S*(1-2^-15): if S<1 the nonnegative fused add gives alpha>=D>=1; otherwise the separately rounded product and final FMA lose less than2^-15 absolute (the reciprocal constant is above exact1/255), and S>=1 turns this into that conservative relative bound. The closed FRECPE estimate satisfies estimate*alpha<=1+2^-8 on alpha in[1,256). Thus the rounded blend is at most (1+2^-8)*(1+2^-24)/(1-2^-15)<2. D0/D255 already use separate branches. This is not a claim of arbitrary native extrapolation controls.

## Exact double rounding

Let y=k+.5. It is an exact F32 with even low significand bit across the relevant integer range. If k is even, F32 y rounds to integer k; the output first exceeds k only for exact x>y+halfULP. If k is odd, the integer tie rounds upward and the output exceeds k for x>=y-halfULP. Inclusion at the shifted boundary is essential. At y=+.5 (k0,even), the relevant **upper/outward** neighbor has spacing2^-24. At y=-.5 (k-1,odd), the relevant **lower/outward** neighbor also has spacing2^-24; one must not use the smaller inward spacing below absolute .5. Other half-integers are not powers of two. Thus the shared exponent formula is valid for these particular outward transitions, including negative k.

Using j=floor(log2(abs(2k+1))) as a mathematical notation only (the implementation uses bounded comparisons), halfULP=2^(j-25). The threshold relative to destination is exactly `[2*(k-destination)+1]*2^(24-j) +/-1`, scaled by2^(j-25), with sign chosen by integer parity. Both odd coefficients are nonzero. The ±1 correction is applied as integer carry/borrow, including negative thresholds; no float epsilon is used.

The exact product has at most32 bits:24-bit coefficient significand times an absolute8-bit channel difference. It is formed using byte limbs whose multiply/carry intermediates are <=65280, exact highp integers. Threshold magnitude has at most33 bits across correlated k/destination bounds; five bytes suffice. Its carry/borrow sign cannot flip because the uncorrected magnitude is at least2^15. Compare signs, physical leading-bit positions, then exact normalized leading24+fraction16 words. Each normalized word is within highp's exact integer range. No full32-bit numeric product, BigInt or float64 product is used by the decision model.

The separate F32 multiply/add approximation only selects a candidate integer. With t in[0,2], correlated byte channels give exact x in[-255,510]. Each separate F32 round has absolute error <=2^-16, and the fused F32 result has <=2^-16 error; their difference is <=3*2^-16<2^-14<1. Flushing a subnormal numeric coefficient adds only a negligible bounded term below2^-118, still within this strict bound. Nearest-integer outputs can therefore differ by at most one. Two exact threshold comparisons select the correct neighbor. The candidate is never clamped; negative/extrapolated integers retain native low8-bit wrapping.

## Independent and broad tests

Original installed FMADD at0x302ca0 and FRINTI/FCVTNS at0x302cac/0x302cb0 run under the previously ISA-gated Unicorn A72, FPCR0, with no arithmetic hooks. The independent7961-case corpus covers all765 relevant half-integer boundaries with neighboring coefficient bits, random finite coefficients, tiny values and t>1. The full output/model comparison has zero differences;1031 compact records are retained with input/code/tool/output hashes. This is original instruction emulation, not physical CPU or active GUI execution. No SDK/library copy/resource was created. Original whole Over8 cases retain their own library/input/runner hashes.

The source RGB model is also compared against the separate exact BigInt FMA + correct native RNE at391680 RGB-pair boundary-neighbor triples,30000 deterministic random triples and coefficient edges. The adjacent negative-RNE regression was fixed separately in commit d68546937: the old positive-only helper used JavaScript signed remainder, incorrectly mapping -.5 to -2. Its negative result is not used as an oracle.

The current JavaScript array/threshold model is deliberately a proof baseline, not a CPU hotpath speed claim:4000 three-channel points measured about190ms versus18–23ms for the BigInt-based reference. GPU static integer arithmetic has a different cost model; only an actual GLSL mixed-texture A/B proof can establish a speedup. General80-bit alpha FMA and all accepted shader declarations remain unchanged in this unit.
