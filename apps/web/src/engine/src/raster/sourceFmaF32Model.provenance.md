# Finite FMA shader-operation model

This unused diagnostic CPU model has no GLSL, GPU, renderer or dispatch activation. It accepts canonical finite binary32 components. All significand operations use integer-valued highp-compatible operations, byte limbs and exact power-of-two shifts, without BigInt, JS double products, bitwise operators, log2 or exp2. Raw-bit input decoding and final numeric U32 serialization are CPU-only adapters: a future shader must retain separate sign/exponent/significand/class fields, never place a full U32 bit pattern in one highp float.

The independent expected values are the previously retained unchanged host `std::fma(float,float,float)` oracle and physical Samsung finite FRECPS outputs. The separate BigInt FMA is an additional random/edge oracle. The operation model does not generate or edit those fixtures. It reuses the byte-split arithmetic principle of the existing affine16 shader, without importing unrelated transform code or copying a native implementation.

## Full-span baseline

A finite input significand has at most24 bits, with value `significand*2^exponent`, exponent -149..104. The product has at most48 bits. The widest exact combined bit span is at most554 bits (lowest product bit exponent -298, largest product top255).72 byte limbs (576 bits) therefore preserve the complete exact signed sum including carry. Three-byte convolution sums are at most195075 before carry; normalized shifted bytes are at most32640. Add/subtract/carry operations are exact binary32 integers. Round once using guard/round-sticky/parity at the binary32 normal or subnormal quantum, then handle significand carry/overflow. Exact cancellation is +0; two negative zero terms preserve -0.

## Compact aligned window

Retain80 bits below the maximum physical operand top, plus an extra byte for carry. The largest operand has at most48 bits and therefore has no discarded tail. At most one smaller operand has a tail. If a48-bit product crosses the lower window edge, its top is at least33 bits below the larger top; a24-bit addend needs at least57 bits separation. Such a smaller operand cannot cancel the retained high word. When the signs differ and the discarded residual opposes the result sign, decrement the retained magnitude by one window unit and mark a positive fractional sticky residual. This is a floor+sticky representation; merely OR-ing a negative residual into sticky would be wrong at rounding boundaries. Same-sign discarded residual only marks sticky. With tail present the result remains within one bit of the larger top, leaving more than enough guard bits for final24-bit rounding. Without tail the result is exact, including arbitrarily deep cancellation and subnormal outcomes.

CPU tests compare both models on11200 host-native triples, retained physical reciprocal-step samples,12000 deterministic raw finite triples, and1331 combinations of zero/subnormal/normal/maximum exponent edges. This is mathematical/value conformance, not shader compiler size, hardware execution, FENV, nonfinite input semantics, NaN payload or responsive hotpath proof. A GLSL implementation and size/compilation assessment remain separate work.
