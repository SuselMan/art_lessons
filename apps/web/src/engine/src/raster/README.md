# engine/src/raster — шейдеры и растровые операции

GLSL-программы движка и растровые алгоритмы поверх них: заливка, маска выделения, матрицы,
геометрия фигур, цепочка превью, мелкие утилиты. WebGL1 — никаких возможностей только из
WebGL2.

Здесь же первые куски, вынесенные из `PencilEngine` (#494): `BlitPasses` — четыре прохода
пересэмплирования (трансформ, выделение, маска, картинка); `AreaOps` — трансформация слоя,
выделение, вставка и заливка, которые движок зовёт через узкий `AreaOpsContext`;
`LayerPreviews` — плавающие превью, которые композит рисует вместо тайлов слоя;
`ImageImport` — импорт картинки с кэшем декодированных изображений (сам DOM-`Image`
остаётся в движке и приходит через контекст); `ShapePass` — программа фигур, запекание
операции `shape` и её живое превью; `cameraFrame` — неизменяемое значение «куда композит
кладёт мир на цель» (центр, масштаб, угол, видимый прямоугольник), которое каждый проход
композита получает аргументом; `Camera` — сама камера: поза (мировая точка в центре
экрана, зум, угол), кэш экранного прямоугольника холста и вся математика от неё —
размер буферов рендера с запасом под поворот, целочисленный отступ сборочного буфера,
кадр живого композита, матрицы финального прохода и экран→мир, преобразования указателя
для обоих видов комнат, начало координат буферов превью. DOM в файле нет: единственный
`getBoundingClientRect` — функция, которую передаёт движок.

## Заметки

- Шейдерные программы независимы: константа, объявленная не в той программе, роняет приложение
  в чёрный экран. Это ловит shaders.test.ts.
- Симптом «шейдеры компилируются, программа не линкуется, лог пуст» уже случался — причиной была
  функция, вызванная из двух мест.

`RibbonPasses` держит низкоуровневые проходы отпечатка, полос и композита
ленты, а также программу полос и её вершинный буфер. Четыре стадии инициализации
сохраняют порядок вызовов GL в движке, включая восстановление контекста.
Общие программа отпечатков и шум принадлежат `StampPainter` и приходят через
контекст. При `destroy()` программа полос и её буфер явно удаляются, даже если
холст остаётся в документе при смене доски.

`WatercolorPasses` держит шесть примитивов GPU-обработки акварельного поля
и восемь программ, включая отдельные программы переноса воды и цвета для
мобильного GPU. Порядок операций задаёт `WatercolorSettlePlan`, буферы поля принадлежат движку; проход
получает их аргументами. Пять этапов инициализации оставляют GL-вызовы на прежних
местах, `destroy()` освобождает программы. Общий шум принадлежит `StampPainter`.

`WatercolorSettlePlan` подготавливает список операций фронта, диффузии,
переноса кистью и общего края залива, а также возврат результата в тайлы.
Выполнение списка поручается очереди сушки. План использует `WatercolorPasses`,
поле и пул буферов из контекста; собственные текстуры движения и чужой воды
забывает при потере контекста и удаляет при завершении работы движка.

`LayerCompositor.ts` — порядок наложения слоёв, выбор обычных и уменьшенных
тайлов, подстановка превью и сборка кадра через кэш ниже/выше активного слоя.
Временный reveal акварели рисуется через callback движка; его время и
ресурсы композит не меняет. Три этапа инициализации программы сохраняют
прежний порядок GL-вызовов.

`GpuBudgetFence` — принадлежащий движку отдельный FBO 1×1 для экспериментального GPU budget clock; физические проходы его не читают. По умолчанию выключен, scope ограничен canonical continuations.
