# engine/src/oplog — операционный лог и снапшоты

Лог операций внутри движка, кодек снапшотов, аудит покрытия снапшота, gzip, хранилище
чекпойнтов (бюджет, вытеснение, закреплённый снапшотный чекпойнт, поиск по префиксу — первый
шов декомпозиции движка, #494), учёт публикации снапшота (что нового публиковать, что уже
покрыто восстановлением, что публиковать нельзя), и `SnapshotIO` поверх них — запекание слоя в
снапшот и контрольное запекание полным реплеем, восстановление слоя из скачанного снапшота с
аудитом, вливание страницы истории в лог без отрисовки (#494). `StructuralOps` — слияние и
дублирование слоёв: живой путь с немедленным чекпойнтом, структурный путь для операции, уже
покрытой снапшотом, и реплей из пересобранных источников (#494). Можно ли печь слой прямо сейчас
(очередь чужих операций, открытый залив акварели, пересборка) решает движок. То, из чего комната собирается заново после
перезахода и с чего начинается пересборка слоя при отмене.

## Заметки

- Полные логи операций хранятся сознательно, как актив для обучения моделей (#375). Сырой ввод
  пера при этом не сохраняется.

## М70: вода отменённого мазка

`watercolorUndo.ts` вычисляет представление истории для материала, не изменяя исходные
операции. Если после отменённого жеста в ту же историческую мокрую компоненту внесён
активный чужой мазок, возвращается проекция всего жеста с нулевым пигментом. `strokeId`
объединяет пользовательскую отмену сетевых частей; `washId` не задаёт границу жеста.
У `gone` различается причина: `branch` сохраняет защищённую воду без возможности redo,
а `revoke` удаляет материал целиком. Историческое восстановление воспроизводит причину
из исходных операций, дополнительного поля протокола не требуется.
После отмены удерживающих мазков вода исчезает автоматически; redo возвращает исходную
операцию. `OperationLog.watercolorEffectiveOperations()` кеширует представление по revision,
а `layerPixelOps()` использует его для пересборки слоя. `doneOperations()` сохраняет прежний
контракт исходной истории; счётчик pixelOpDoneCount считает done, а не проекции воды.

Геометрическое правило v1 — консервативная капсула между соседними центрами dabs с радиусом
внешнего диска наконечника (`size / 2 * max(1, aspectRatio)`); координаты и радиусы округлены
до 1/256 мировой единицы. Это семантическая область воды для undo, а не точный силуэт
эллиптической кисти или симуляция растекания. Связные компоненты существуют только внутри
одного слоя и исторического мокрого периода. Границы задают активная послойная `paper_dry`,
скрытие, очистка/удаление слоя и разрыв записанного времени больше 120 секунд отдельно
для каждой связной лужи. Рисование в другом месте не продлевает мокроту старой лужи.
Части одного жеста по разные стороны сушки не соединяют мокрые периоды. Высыхание после
взаимодействия не снимает историческую защиту воды. Нулевая вода может использовать лужу,
но не соединяет две лужи. Удаление неподдерживаемых отменённых перемычек повторяется до
стабильной связности. Клиентские часы, морфинг и GPU-пиксели не читаются.

Для поиска пересечений используются только ещё мокрые компоненты и AABB-фильтрация
на уровне компоненты и операции; объединение списков членов выполняется по размеру.
Поддержка воды вычисляется по последнему активному вкладу каждого автора в компоненте.
При удалении неподдерживаемой перемычки связность пересчитывается, пока набор сохраняемых
жестов не перестанет уменьшаться. Представление кешируется на revision журнала.
