# engine/src/watercolor — модели и очередь сушки

Модели акварели на CPU: цвет смеси пигментов (`pigmentOptics.ts`), диффузия пигмента в стоячей
воде (`wetDiffusion.ts`) и водный домен операции — куда растекается вода и где встаёт фронт
высыхания (`waterFront.ts`). Диффузия и водный домен — эталоны для GLSL-проходов в
`raster/shaders.ts`, по которым алгоритм проверяется без GPU. Но это не только эталоны: фасад
движка берёт отсюда в работу расписание и коэффициенты диффузии (`WET_DIFFUSE_*`) и поглощение
пигмента (`pigmentAbsorption`) — правка этих файлов меняет картинку у всех.

`foreignWater.ts` строит компактную CPU-маску предшествующей мокрой области из геометрии
дабов. Записанные мокрые контакты выбирают область, по которой фронт нового штриха может
идти, даже если у мазков разные `washId`. Маска передаётся в GPU-проход фронта; краска
старого залива в новый при этом не копируется.

`brushDrag.ts` строит последовательность компактных мокрых контактов по записанным
дабам и пройденному расстоянию. GPU переносит мокрый материал по ним по порядку
после смешивания при settle; возврат кисти действует на результат предыдущего
контакта. Цвет и доза используют одинаковые донорские доли, вода ограничивает
перенос. Среднее направление хранится отдельно от силы контакта, встречные
направления не нормализуются по длине вектора (ADR 011 §17.98).

## Заметки

- `waterFront.ts` пока ни откуда не импортируется (предупреждение no-orphans): это эталон для
  GPU-порта водного домена (ADR 011 §17.24), который ещё не подключён.

`WatercolorSettleQueue` выполняет один план сушки за раз: первый шаг сразу,
остальные по кадрам или синхронно по запросу движка. При рисовании поздние кадры
пропускаются не более трёх раз подряд; когда перо поднято, очередь учитывает
накопившиеся операции и публичный лимит. До повторного использования общего поля
движок завершает текущий план; отмена и потеря контекста его отбрасывают.
`settleResolution.ts` содержит общие пороги половинного разрешения для плана
сушки и разделения длинного штриха на части.
