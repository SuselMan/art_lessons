# Local canonical control delivery classification (U2a)

This is a nonactivated Outbox storage/settlement leaf. No engine command, Room emitter, history replacement, socket protocol, renderer or server policy changes. The optional outer `OutboxEntry.deliveryLane = 'canonical-control-v1'` is local durable data, **not** a read, membership, paint or append grant. Historical entries with no own marker keep the previous legacy behavior and callback arity. IndexedDB version, keys and indexes are unchanged.

The explicit enqueue option accepts only the one own data property. Its accessor is rejected before invocation. Only bounded undo/redo scalar bodies are captured: at most six allowed own fields, no accessors or extra keys, then an immutable scalar copy preserving the original descriptors/property order. This local capture is not the server metadata validator. It supplies no missing sequence and does not alter operation JSON: sender receives only the original-valued operation body, never the outer lane. The actual server still owns validation and durable placement.

The same pending entry retains its lane through persistence, backoff and manual retry. Hydration captures the marker descriptor once. PRESENT unknown/undefined/accessor markers and invalid marked bodies stay pending, visible as stalled, unsent and unchanged in durable storage; they do not fall back to legacy or get rewritten without their marker. A derived scalar on that same entry prevents repeated malformed-lane notices during resend, while pending/stalled counts remain accurate. No second queue or registry was added.

For a marked ID, equal body/lane reuses the existing pending or settling attempt; differing body or classification throws without replacing the first entry or durable copy. The old unmarked/unmarked enqueue behavior is retained. Rehydration cannot resurrect an ID while its existing attempt is finishing durable deletion.

Settlements and terminal retry stalls receive a frozen context from the SAME Attempt's captured lineage, not the latest mutable Room read. The context is captured before asynchronous durable deletion. Hydrated work may have no lineage: this is retained classification, not permission to reconstruct an original delivery. Disposal prevents stale ACK callbacks and keeps durable entries. Malformed records have an explicit invalid-context signal so their stalled notice never takes the legacy transform path.

Marked undo/redo ACKs advance the durable server watermark and notify the canonical control callback. They never call legacy confirm/discard, clear pending IDs, resolve transform previews, recover lost pixels or trigger snapshot capture. Missing settlement owners request the existing resync callback once per settlement. Unmarked undo/redo remains legacy. No producer supplies the new lane yet; U2b/U1/U3 pairing remains separate.
