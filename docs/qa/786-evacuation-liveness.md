# #786 — актуальность участника после ожидания эвакуации

06.11.2026. База `3dff6f1ef59658bbec82cbc99796ceb39a35c078`.
Worktree `786-release-evacuation`, ветка `agents/786-release-evacuation`.

`evacuateBoard` больше не использует снимок сокета/имени, сделанный до
`prepareSnapshotReplay`. После await сервер берёт сокет из своего живого реестра:
соединение существует, connected, доска всё ещё удаляемая, урок совпадает.
Имя участника также читается заново. Протокол и правила доступа не изменены.

## Регрессии

Настоящий Socket.IO, управляемое ожидание запроса snapshot metadata:

- Disconnect: после release не возникает ghost participant.
- Успешный переход B→C во время ожидания: следующая paper_dry сохраняется на C,
  отсутствует в main, участник остаётся на C.
- B→C→B: участника всё равно надо эвакуировать с удаляемой B, используя обновлённое имя.
- Незавершённый переход C во время эвакуации B может завершиться после неё;
  операция попадает на C, а не на main.

На исходном runtime: 3 FAIL / 48 (disconnect, move, обновлённое имя).
После изменения: 48 / 48 PASS, 5.38 с. Первые два запуска нового тестового файла
имели отсутствующий импорт evacuateBoard; они не считаются доказательством бага.
Валидный baseline: `temp/786-release-evacuation/baseline-valid.log`.

Браузерный тест `e2e/specs/boardEvacuation.spec.ts` проверяет обычную эвакуацию
занятой доски через настоящий DELETE: независимый участник получает main room_state,
рисует через CDP, штрих сохраняется в PostgreSQL и приходит владельцу.
Точные гонки выше проверяются Socket.IO-регрессиями, браузер не подменяет ответы
и не заявлен как воспроизведение управляемого snapshot-await.

Компактные логи/SHA256 runtime сохраняются в игнорируемом temp. Собственные QA
процессы, PostgreSQL/volumes, trace/video и dependency views убираются после проверки.

Результаты: браузер PASS (95.8 с); rooms/routes 602 / 602, 24 файла (51.20 с).
Typecheck, lint:fix, map:check и map:rules: exit 0. Собственные QA-процессы,
контейнер/volume, trace/video и временные представления зависимостей убраны.
