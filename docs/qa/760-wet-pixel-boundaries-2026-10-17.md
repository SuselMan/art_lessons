# #760: обычные операции поверх мокрой акварели

Аппаратный baseline: мокрый мазок слева → независимый красный прямоугольник
справа. Сразу после shape красных пикселей10000; после естественных кадров
завершения цели —0. Oracle до замера не вызывался. Морфинг переписал целый слой
из своего прежнего материала. Восемь lifecycle unit-сценариев также показали
отсутствие закрытия источника перед обычной записью пикселей.

Перед shape, selection clear/transform, fill/paste/image, layer transform/filter
теперь материализуется канонический M70 target этого слоя и закрывается его
источник. Операция применяется к этому результату и больше не попадает под старый
морфинг. Live и replay используют одну границу. Ластик остаётся отдельным путём:
стирает только сухую базу, мокрый источник не закрывает.

Если чужая операция приходит под удерживаемое M70-перо, обычная очередь ждёт UP.
Даже принудительный drain не уничтожает активный scratch: после записи хвоста
делается rebuild в порядке журнала, как для Dry посреди мазка.

Убрать source недостаточно: связанные с ним M70 PaperWet контакты очищаются;
wetReplayOperationIds и snapshot water gate учитывают такие границы только
для M70. Старый lifetime legacy watercolor не переопределён. При Undo границы
мокрая история снова восстанавливается. Геометрический resolver Undo также
не переносит зависимости через обычную пиксельную операцию.

close() не вызывается на слое без M70 source: он отменяет общий solver, поэтому
пустой вызов для чужого сухого слоя был бы лишней отменой работы другого слоя.

53 целевых теста проходят; отдельно61 тест обычных операций/слоёв проходил
до последних отрицательных проверок (наборы перекрываются). Web typecheck,
scoped lint. Аппаратный повтор с полным actual raster проводится на кандидате.
