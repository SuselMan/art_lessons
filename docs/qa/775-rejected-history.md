# #775 — отказ сервера не становится событием истории

Основа: `c02cecaa8d5a323836d299e9096cf702ffc508f9`. Исправление относится к
обычным операциям общего журнала из функционального трека #825. Экспериментальная
акварель и её отдельная семантика Dry сюда не перенесены: текущий `paper_dry`
остаётся глобальной meta-операцией, которую нельзя отменить.

## Причина и исправление

Локальный отказ помечался как законный revoke. Это теряло исходное состояние
цели revoke и ветки redo, а историческая свёртка могла заново исполнить отказанный
контроль. Теперь `goneReason=reject` отличается от принятого revoke/ветвления.
Журнал сохраняет скалярное состояние целей перед оптимистическим контролем и
состояния реально отброшенной ветки. Отказ пересчитывает известную историю без
причинного эффекта отказанного события; принятые последующие действия остаются.

Историческая страница сворачивается вместе с уже известным журналом: контроль
может предшествовать загрузке своей старой цели. Порядок принятых событий задаёт
server seq, pending остаются в хвосте. Новая свёртка не объединяет дополнительные
ID слайдера или принятые ID чанков. Авторитетная страница/поздний ACK того же ID
сильнее локального отказа. Движок восстанавливает все цели с изменившимся состоянием,
включая структуру и ветки, через существующий механизм rebuild; защита живой
незавершённой краски из #770 сохраняется.

## Проверки

- На исходной базе public-engine набор воспроизводит 5 отказов из 9 сценариев:
  revoke, Undo с последующей собственной веткой, legacy redo, поздняя история/ACK.
- Прямые проверки журнала: отказанные Undo/Revoke инертны в исторических срезах,
  принятый revoke необратим, отказ среднего чанка сохраняет остальные ID,
  авторитетное подтверждение побеждает отказ, отдельные ID слайдера сохраняются.
- Независимая проверка причинности: 6 фиксированных seed, по 100 действий двух
  авторов. Случайные отказы приходят в перемешанном порядке. Итог и срезы 10/30/60/100
  совпадают с новым журналом, в который отказанные события никогда не поступали.
  Проверяются состояния, порядок видимых ID и счётчик pixel operations.
- Загрузка одной более ранней записи в журнал 30 000 подтверждённых мазков:
  первоначальная полная свёртка 1901 мс, после индекса авторов с redo — 88 мс
  на этой VPS. На выходе 30001 запись, 30000 pixel operations. Это локальный
  CPU-замер, а не обещание времени восстановления на каждом устройстве.

- Полный движок: 1910/1910, 174 файла, 352,18 с. Room: 690/690, 68 файлов,
  76,02 с. Финальная выборка после правок: 22/22. Typecheck всего workspace и
  финальный e2e typecheck, lint, map:check/map:rules — exit 0 (обычные warnings).
- Реальный браузер: baseline на исходном main FAIL, после отказа darkness
  0,4641 → 0,0340 и ID мазка отсутствует. Финальный фикс: Chromium + Samsung
  SM-T970, 2 PASS, 42 с с подготовкой. В каждом случае darkness 0,4641 до отказа,
  после отказа и после backfill; поздний авторитетный ACK отмены даёт 0,0340.
  Сценарий использует публичный API standalone движка с реальным WebGL.
  Начальные невалидные стенды (не заданы composite order, ожидание кадра и
  paperReady) не являются доказательством регрессии. Финальный сценарий ждёт
  реальную загрузку бумаги и кадр; проверки цвета снова строгие внутри устройства.

## Ограничения

Отдельная #761 (ошибочная карантинизация уже запечённого старого контроля) здесь
не закрывается. Доставка отказа до API движка проверяется существующими сетевыми
наборами; отдельный браузерный сценарий вводит отказ через публичный API и проверяет
реальные пиксели. Исторический M70-кандидат адаптирован к нынешнему done-only replay,
без переноса water-preserving resolver и другой семантики Dry.

Артефакты: локальный игнорируемый `temp/775-release-rejected-history/`.
