# №728: запрос Dry для отложенного материала

Эксперимент `_wcExpeditedDry` выключен по умолчанию. Он не вызывает синхронный drain из обработчика Dry и не меняет список, порядок или коэффициенты физических операторов.

Dry сохраняет cutoff жеста каждого удерживаемого scratch, включая текущую удалённую задачу. `_startSettle` передаёт планировщику `lifecycle.isExpedited()` с захваченным номером жеста. Следующий жест того же scratch не наследует приоритет. Переход drawing → solver сохраняет ticket до завершения solver; завершение, отмена и потеря контекста очищают его. Задачи без lifecycle остаются вне этого seam.

Существующая очистка PaperWetness сразу убирает блеск. Для progressive reveal двухсекундный clock запускается только после появления настоящего рассчитанного pending target. Это отдельный presentation clock: `startedAt` остаётся null до канонического завершения. Если solver не завершился за две секунды, последующие реальные промежуточные состояния продолжают мягко догоняться существующим фильтром, без скачка к несуществующему финалу. Новый `_revealWash` создаёт новый объект и сбрасывает оба поля Dry.

Это не доказательство полного окончания сушки за две секунды. Ускоренная cadence реализуется отдельно в WatercolorSettleQueue, тоже default OFF; её аппаратный бюджет и отзывчивость ещё требуют проверки. Долгие GPU units могут превышать JS budget, поэтому CPU тесты не являются performance gate.

Регрессии проверяют реальный engine: отсутствие синхронного material advance на input, неизменность canonical pixels при pending reveal, cutoff старого/нового жеста, remote continuation, drawing → solver, отмену, новый reveal. Clock tests покрывают future timestamps, dt=0, отсутствие target, позднее промежуточное состояние и overdue actual final. Существующий async suite сохраняет проверки журнала, экспорта, очереди и context loss.
