# Копирование совместной лужи до отложенного восстановления порядка

Кампания #745, sourcefreeze8680f05f, реальный Vega AMD, два независимых автора.

1. Два автора одновременно рисуют перекрывающиеся М70 мазки в одном слое.
2. После подтверждений у B `_unsettledLayers=[source]`, resettleCount0;
   legacy `_wash` удерживает восстановление порядка до WASH_JOIN_MS100000.
3. До явной сушки B дублирует слой.
4. Actual копии читается до независимого full replay.

У A actual=oracle; у B23отличающихсяRGBAбайта, maxDiff3. Оба oracle совпадают.
Снимки/report: temp/device-runs/745-layers-concurrent-copy/. Ошибок JS/GL нет.
Таким образом чтения уже рассчитанного goal недостаточно, если источник ещё
содержит материал в оптимистическом порядке локального ввода.

Отдельный concurrent-dry: та же ситуация B_unsettled/resettle0, затем штатная
записанная послойная сушка — actual обоих авторов сходится с oracle побайтно.
Предыдущая pre-dry проверка11байт/max1 поэтому не доказывает постоянного
расхождения после сушки, но вариант с копией закрепляет ошибочный порядок.

Ожидаемое: структурная операция читает материал в серверном порядке на своей
границе, даже если живая анимация/открытый wash ещё допускает отложенный replay.
Нельзя сушить оригинал неявно только ради совпадения копии.

Обе неудачные disposable комнаты оставлены для целевого повторения после fix;
owner-auth внеGit, точные пути в private-fixture-path.txt. Все свои contexts
закрыты; source edit окно передано root.
