# #747: ограничения двух мокрых слоёв и квадратного тайла

Read-only review текущего М70 адаптера. Код не изменён. Нельзя считать план
подтверждением аппаратной пригодности или уже реализованной поддержкой.

## Почему два слоя

`PuddleRoomController.layers` — обычный Map; каждый Layer содержит свой canonical
scratch и представление. Один `createNativePuddleTarget` последовательно обслуживает
слои, отменяя устаревший расчёт. Математической зависимости от числа 2 нет. Guard
в source() защищает память QA-кандидата. Дополнительный `<2` есть в prewarm index.ts.

На 1024² один RGBA8 buffer занимает 4 MiB без overhead драйвера:

- raw/next/goal: 3 полных buffer = 12 MiB на слой;
- presentation current/next/target/wet/anchor: 5 = 20 MiB; feature/flow ещё ~0.19 MiB;
- минимальный scratch original/coverage/inkLoad/inkColor: 4 = 16 MiB;
- solvent и film добавляют новые полноразмерные текстуры; типичная конфигурация
  может приблизиться к 76 MiB на мокрый слой до самого изображения слоя;
- solver имеет общие output/contour/background и временную копию scratch;
  их цена добавляется отдельно, не умножается на число мокрых слоёв.

Это оценка allocations из исходников, не GPU-замер. Guard нельзя просто удалить:
полные заливки N слоёв дают линейно растущий неограниченный GPU working set.
Существующий spill() упаковывает области scratch на GPU и может сэкономить память
маленьких мазков, но на полноразмерной заливке не задаёт верхней границы.
ScratchSnapshot тоже хранит GPU-копии: это checkpoint, а не выгрузка из GPU.

## Реальный bounded memory путь

1. Отделить логическое мокрое состояние слоя от resident GPU кэша. Все операции
   сохраняются; вытеснение не добавляет сушку и не меняет материал.
2. Считать фактически выделенные байты, а не число слоёв. Ограничить resident
   source/presentation slots и один solver общим бюджетом.
3. На границе жеста освобождать временный film. Неактивные источники сохранять
   побитно в CPU-буферах либо восстанавливать из журнала с канонической границы.
   Исходный original, P/C/coverage/solvent и scalars обязательны; одного target
   недостаточно, поскольку следующий мазок должен продолжить мокрое смешение.
4. Показывать последнее изображение вытесненного слоя. Морфинг допускается
   перезапустить после восстановления; материал и target не менять.
5. При новом вводе сначала принять операцию в упорядоченную очередь, затем
   асинхронно восстановить source и продолжить. Нельзя рисовать в старые пиксели
   или терять жест, пока слот занят.
6. CPU readback требует отдельной измеренной процедуры/fence и может зависать;
   нельзя выполнять произвольный readPixels на pointer hot path. Полный replay
   избегает CPU-cache, но требует ограниченного по времени восстановления.
7. Выбирать dirty-layer jobs справедливо. Сейчас find(first dirty) и глобальный
   cancelCurrent способны откладывать поздние слои при непрерывном вводе.

Это контракт residency/rehydration, а не одно удаление guard. В ночной версии
разумно оставить защиту, пока не реализован и не проверен этот контракт.

## Неквадратный холст и несколько тайлов

Single rectangular tile — отдельное, значительно более узкое расширение.
Presentation уже принимает width/height. Controller/Target/BackgroundMix и index
пока используют size×size: размеры buffers, bounds, texel stride и worldSize
нужно согласованно обобщить. Нужны реальные GPU-проверки 320×512 и 512×320,
побитовое отсутствие изменения квадратного reference и сходимость после rejoin.

Мультитайловый рисунок не эквивалентен независимому solver на каждом тайле:
вода/пигмент должны пересекать границы, а низкочастотные contrast/background
операции используют общую область. Потребуется общий domain/atlas или сборка
страницы и перенос результата обратно. Простая итерация по тайлам создаст швы
и изменит target. Это отдельная архитектурная работа с памятью и границами GPU.

## Checkpoint для ускорения Undo

Самая узкая правильная оптимизация — checkpoint на завершённой границе сушки
и использование его при отмене только более поздней мокрой порции. Необходимы:

- проверка идентичности effective material prefix, включая пигмент проекций и
  границы сушки: id исходного мазка при water-only undo остаётся прежним;
- invalidation до самого раннего реально изменившегося вклада: отмена чужого
  держателя может убрать воду значительно более раннего мазка;
- учёт `washId=m70:<layer>`: текущий crossesWash считает этот id одним span через
  несколько сушек и отвергает корректный dry checkpoint без epoch-aware проверки;
- отсутствие безусловного удаления всех checkpoints слоя при любом undo.

Для checkpoint внутри мокрой порции имеющегося ScratchSnapshot недостаточно
подключить к `_replayRibbonChunks`: М70 читает source через PuddleRoomController.
Нужен явный adopt/restore в controller с logical timestamp, boundary, wire gesture,
source/scalars и заново вычисленным raw/goal. Snapshot должен быть на полной
границе жеста (snapshot() отказывает при coverageFilm). Кэшировать только
презентационные пиксели нельзя. Все source snapshots должны входить в byte budget.
