## Что построено для следующих проверок

Native bounded scene проходит цепочку input → canonical source preparation →
настоящие native GPU phases → тот же generic settle → live/final composite.
Один тайл1024, один слой, одна сохраняемая мокрая группа; последовательная
вода→пигмент поддерживается. Нет полноценного Room API, сетевых ACK, multiuser,
нескольких слоёв/wash, undo-log, lost-device recovery, произвольной камеры или
готового морфинга. Выход за поддержанный контур должен явно отказывать.

[End-to-end harness](harness/728-native-end-to-end/README.md) сохраняет оригинальные
packed операции из настоящего native gesture и отдаёт их production PencilEngine
для GL replay. Fine baked, страница1024, source policy проверяется на равенство;
финальный whole RGBA сравнивается после правильного разворота GL строк. Owners
последовательны, canonical1536 не уменьшен. Сценарии: zigzag100 и вода→пигмент400
с отдельным soft memory guard. Не подменяет hardware проверку или Room.

Software zigzag100 не вернул финальный readback за бюджет10 минут. Остановлены
только собственные browser/driver; GPU process RSS около352 MiB оставался стабилен.
В конце работал ещё один SwiftShader процесс, поэтому это не изолированный
performance benchmark. **Parity неизвестен**, это timeout, а не pixel mismatch.
400 после этого не запускался. Артефакты остаются на диске в
`temp/native-end-to-end/{software-budget-report,software-progress,failure-100}.json`.
Следующий gate — аппаратный запуск root последовательно после Samsung UI.

GPU timer harness использует EXT_disjoint_timer_query с проверками validity,
disjoint/loss и без finish fallback. Samples — выборка вызовов, не полный счётчик.
CPU submission/inclusive time и интервалы Skia/Viz не называются GPU elapsed;
вложенные inclusive totals нельзя суммировать. Изолированный MRT brush benchmark
около42% не переносится на весь движок: [MRT prototype](728-engine-webgl2-mrt-prototype.md).
Storage reuse/film hoist и sparse-support proposals без whole hardware gate не
объявлены общим выигрышем: [storage](728-gpu-flow-storage.md),
[front invariant](728-gpu-waterfront-invariant.md),
[support regions](728-gpu-pass-support-regions.md).

## Открытые направления

- **Каёмка.** Старый Surface live water→pigment случай показал причинное улучшение
  weighted phase и native→rebuild exact; это не закрывает весь архив, Samsung,
  плотные спирали и художественное качество. Нужен широкий same-tape визуальный
  gate без потери ореола: [Surface ring](728-ring-native-surface.md).
- **Загрузка комнат.** Standalone replay экономия не равна ordinary Room load.
  Clear-prefix/author/watermark/snapshot guards и контроллеры подготовлены; полная
  новая ordinary OFF/ON цепочка ACK→Undo/Redo→snapshot→reentry остаётся отдельным
  доказательством: [first-load wiring](728-firstload-clear-prefix-wiring.md).
- **Multiuser и Undo/Redo.** Ограниченные standalone и CPU lifecycle проверки есть;
  late join, peer arrival во время rebuild/settle, разные слои и реальные сохранённые
  ACK требуют совместного Room gate. Native bounded runner этого не реализует.
- **iPad.** Новые ускорения/native backend этой ночью на Safari не объявлены
  проверенными; поддержка GPU, компиляция, память и отзывчивость остаются открыты.
- **Плавность и морфинг.** Быстрый старт и ускоренный replay — разные вопросы.
  Самый тяжёлый GPU/driver/Viz остаток не локализован полностью. Native preview
  интеграция и текущий Samsung UI ещё проверяются; финальный статус не назначен.
- **Сухая кисть и рваный кончик.** Отдельная отложенная работа по указанию Ильи;
  ночные оптимизации не являются их художественным исправлением.

Итог среза: есть несколько точных локальных CPU оптимизаций, подтверждённые
аппаратные scheduling кандидаты и реальная bounded native цепочка. Обещание
«кисть400 плавно в совместной комнате на всех устройствах» пока не подтверждено.
