# Автоматическая проверка оптимизаций этапов

Скрипты используют один frozen build на вариант, настоящие устройства и одинаковые записанные операции. В stdout — одна короткая строка на комбинацию; изображения, SHA, подробные интервалы и проверки остаются на диске.

1. Зарегистрировать одноразовый QA_OUTPUT через qa-cleanup.py. Сборки: build-stage-optimization.cjs (QA_OUTPUT, QA_PAPER). Зависимости существующие, npm ci не нужен.
2. Подключить собственный CDP endpoint. Samsung: проверенный serial R52RB0JXVSY, собственный ADB forward. Vega: собственный headed Chrome, профиль и SSH forward. Экран должен быть включён, страница видима.
3. stage-optimization-run.cjs: QA_OUTPUT — результаты, QA_BUILD_ROOT — сборки; QA_ARMS и QA_SCENES — списки через запятую. QA_VEGA=1 выбирает Vega. QA_CDP_PORT задаёт собственный порт. Для Samsung QA_ADB_DEVICE задаёт подтверждённый endpoint. Большую матрицу запускать по одному fixture на команду и возобновлять: успешные неизменённые сборки пропускаются.
4. До каждой комбинации проверяется остаток аккаунта, при расходе 70% новые случаи не запускаются. Для Samsung до/после проверяется Awake, до измерений также нужны visible и минимум четыре кадра UI. Не заменять это одной проверкой доступности ADB: уснувший планшет остаётся доступным и продолжает выполнять CDP/GPU-запросы, но эти времена не представляют работу интерфейса.
5. Один прогрев, три обычных и три поэтапных прогона. Каждому результату проверяются исходные семь карт, метаданные и P/C/покрытие. Поэтапные чтения обязаны оставить тот же результат. Начальное/конечное PNG экспортирует настоящий Mini. Отдельная повторная серия может выполняться в обратном порядке, в другом QA_OUTPUT.
6. package-stage-optimization.cjs принимает результаты, повторную серию, исходный пакет пояснений и выходной пакет. Он запрещает склеивать разные входы, проверяет SHA PNG и не допускает Samsung без подтверждённого Awake. verify-stage-optimization.cjs проверяет все устройства/сцены/версии/методы на 320/390/1440, картинки, удержание и переполнение. Это headless проверка UI, не GPU-замер.
7. publish-stage-optimization.cjs обновляет только существующие приватные статические QA-пути. Отвергнутые по картинке варианты остаются в сравнении/схеме с пометкой, но исключены из рисуемого Mini. Никаких push или production deploy.
8. Живой опубликованный Mini проверить настоящими pointer events: verify-live-stage.cjs (QA_BUILD_ROOT, QA_OUTPUT, QA_CDP_PORT). Закрыть все собственные вкладки, Chrome/профиль Vega, forwards; оставить компактные измерения, SHA и нужные картинки, завершить disposable resource.

Обычный полный C-read включает ожидание GPU и передачу. Поэтапное чтение одного пикселя из каждой выходной карты вставляет остановки и меняет время исполнения; это диагностическая локализация, а не чистый GPU timer. Складывать обычные CPU-интервалы с контрольными GPU-ожиданиями нельзя.
