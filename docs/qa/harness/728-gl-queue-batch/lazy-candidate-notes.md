# #728: отложенная подготовка контактов — диагностический кандидат

Первый UP на Surface занимает 95,5 мс; prepare — 49,6 мс (вложенная часть, не складывать). В этот интервал нет uploadFlow: контакты и их CPU-растр строятся заранее. Полное ускорение не следует из этих чисел.

Генератор создаёт отдельный файл в temp, исходник движка и стенд 5352 не меняет. Кандидат включается только при переданных captured finishMetadata. Скалярные brushTravel копируются до возвращения prepare; последующая мутация вызывающего массива не меняет ленивый растр. Это не разрешение переиспользовать GPU lease и не подмена presentationOwnerLocked. Используется существующий генератор CPU-порций и последовательность физических проходов.

CPU gate: 12 тестов — потреблённые байты flow, аргументы и порядок физических операций для half/full, single/mixed и film/no-film; отрицательный контроль мутации метаданных; отсутствие метаданных сохраняет прежнюю полную последовательность. Ресурсы сравниваются по реальной роли upload, поскольку момент создания flow сдвинут. Это проверка CPU-команд, не GPU-пикселей.

Первый запуск 11/12: один byte-loop превысил стандартные 5 с на 123 мс. Повтор последовательно с явным пределом 20 с: 12/12, 7,03 с суммарно. Аппаратный gate отдельно: обычная Room кисть 400, queue/mixed/deferred ON в обеих ветках; затем одинаковый fixed tape, 24 роли, RGBA, packed material и meaningful undo/redo. До прохождения этих проверок ускорение и совпадение GPU результата не заявляются. Defaults OFF.
