# Проверка больших листов M70: промежуточные результаты

На Samsung исходный paged-расчёт расходился с монолитным уже внутри solver. Начальные P/C, включая нулевое поле за листом, совпадали. Замена вычисления координат на gl_FragCoord и обход ускоренного front не устранили причину.

Чтение целочисленных front/fieldOp-входов через NEAREST убрало основное расхождение. Остаточный канал удалось локализовать в дробном mode6.d. QA-вариант с явной билинейной интерполяцией mode6 дал побайтное совпадение ВСЕХ полных стадий для связной полосы и компактной лужи. Это сравнение с исправленным QA-reference: его target отличается от прежнего, поэтому утверждать сохранение старой модели нельзя. Runtime-policy ещё не утверждена.

Публичный A4-прогон сохранён отдельно в `../747-public-a4-20261017/`: настоящие pen-события пересекли обе границы 1024, actual-пиксели после Dry совпали с полным replay. UndoDry и RedoDry заняли примерно по 58 секунд между контрольными точками. Это время включает ожидание и чтение пикселей, не является изолированным временем solver; причина задержки пока не установлена. После Redo исходные actual-пиксели восстановились. По указанию оператора длинный прогон остановлен. A3/A2 и полный набор controls этим не проверены.

Сырые поля в Git не сохранены. JSON содержит параметры, SHA входов/выходов, различия, ошибки и измерения. Контексты Samsung после каждого прогона закрывались. Служебные ADB-mappings, QA-service override и свежие QA-комнаты пока оставлены для продолжающейся проверки; удалённая вкладка Vega ожидает восстановления SSH и не объявлена закрытой.
