# Porous water transport, QA candidate

New id `alternative-porous-water-transport`; ordinary/v9 kernels unchanged. Two full1024 presets: 8steps/36passes mobile.6 dt.16 terrain.18 stride4→2→1, and10steps/44passes mobile.8 dt.2 terrain.25 stride2→1. Nine RGBA8 textures36MiB plus CPU input aux4MiB; no CPU downsample. All compile/allocate before timing; upload before timing; run resets water/mobile/fixed. No GPU performance/quality claim.

Four-face flux uses H=W+βpaper, symmetric path-min raw wet gate and pair coefficient k=dt·gate·min(1,Wi/(5dt·positiveΔH+ε),Wj/(5dt·negativeΔH+ε)). Fij=kΔH. Since k≤dt≤.2, each H_new is a convex combination of H_i and its ≤4 neighbours: maximum H cannot grow in ideal arithmetic. Perface donor fraction≤.2, total≤.8. Thus W remains positive and ≤max(initialH)≤1+β≤1.25; pair water flux cancels globally. This is porous diffusion driven by water/terrain potential, not momentum CFD. Fixed wetdomain: cannot spread into originally dry pixels; dry gaps block all integer intermediate stride cells.

Pigment transports by donor concentration C·positiveF/max(W,ε), with extra symmetric .01 diffusion per face. Outgoing bound≤.84 ensures positivity. Pair pigment flux cancels in float arithmetic. Byte-partitioned fixed/mobile split and paper-dependent adsorption are inherited fromv8; adsorption is NOT an evaporation simulation. Water evolves, while total water is not deliberately evaporated.

RG16 stores W range0..4, highp sampler and byte decode; nearest rounding error≤2/65535 each producer. Convex maximum proof plus ≤12step accumulated quantization slack leaves a large capacity margin (<1.251 before implementation floating error). This does not prove portable bit equality. Pigment still uses RGBA8: concentration can exceed1 and clamp, fixed deposition can saturate, and rounded flow can lose/gain mass. Metadata explicitly declares capacity1 and no conservation certificate for quantized outputs. Device evaluator must report observed total pigment mass ratio/premul invalids and images; do not interpret ideal oracle as blessing saturation. No extra readback is hidden inside run.

CPU: porous-math.cjs tests900 random float face schedules, positivity, mass conservation (<7.2e-14 water error), H maximum, dry barriers. Sample maximum pigment .455 is only observed for dilute random fixtures, NOT a universal bound. Existing FakeGL full registry/allconfigs lifecycle/pass counts and strict standalone TS pass. These tests do not compile/execute GLSL. Required device controls: dry byteidentity (explicit final original guard), zero pigment, isolated-pools/no dry-gap crossing, deterministic repeat, water-stroke/variable-wash/fine-detail PNG comparisons and measured mass/capacity behaviour. No production or device changes.
