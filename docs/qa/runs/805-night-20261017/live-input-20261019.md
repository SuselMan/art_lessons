# Живой мазок без растекания — Samsung, 19.10.2026

Реальный SM-T970, Mini 1024, combomask, кисть 320, вода 95%, пигмент 34%. Три волнистых мазка по одному месту: 32 события пера, пауза 16 мс между отправками через CDP. Это диагностический сценарий, не замер реальной частоты S Pen. CPU-профилирование добавляет небольшой собственный расход.

Расчёт и морфинг выключены: во всех шести прогонах solvesStarted=0. Переключатель доступен в опубликованном Mini как в 1024, так и в A2. Полная проверка выключения/включения A2 ранее прервалась таймаутом CDP; успешной не считается.

## Второй мазок: основной поток

Это суммы CPU-времени за весь мазок, не задержка одного кадра. Вложенные этапы ниже разделены по собственному времени, чтобы не складывать их дважды. GPU исполняется асинхронно и отдельно здесь не измерен.

| Работа | CPU, мс |
|---|---:|
| Прочитать влажность под кистью | 58,3 |
| Забрать воду кистью из существующих ячеек | 177,3 |
| Добавить воду мазка в ожидающее поле | 55,7 |
| Подготовка/прочая работа построения материала внутри paintDabs | 125,3 |
| Отдать GPU отпечатки кисти | 25,0 |
| Отдать GPU полосы между отпечатками | 44,1 |

Последняя строка подготовки ещё объединяет несколько задач; это не установленная стоимость одной геометрии. Композиция и показ кадра отдельно занимают 28,3 мс за 33 вызова display, включая вложенные вызовы построения изображения. Их нельзя прибавлять к таблице без вычитания вложений.

Наиболее долгий обработчик движения: 27,6 мс в основном потоке; 29,0 мс в воркере. Воркер переносит работу, но не устраняет её стоимость. Время учёта воды во втором мазке воркера: 59,3 + 180,3 + 58,9 мс.

## Куда смотреть дальше

1. PaperWetness.drain использует строку layerId|cellKey и Set<string> для каждой ячейки каждого отпечатка. Map по слою с Set<number> убирает повторное создание строк, сохраняя запрет повторного забора воды за один жест. Требуется проверка равенства состояния и замер.
2. sampleUnderNib, drain, deposit каждый обходят круг ячеек под каждым отпечатком. Нужны сокращение повторных обходов и пространственная индексация с сохранением границ круга и порядка обновлений.
3. Подготовку материала paintDabs разобрать отдельно: геометрия, вычисление подачи краски и проходы полей. Сейчас её остаток 109–125 мс на прогретом мазке.
4. QA-контроллер дополнительно пересобирает полную картинку raw, копирует её и накладывает воду при обновлении. Это отдельный кандидат для GPU-профилирования и ограничения областью изменений. По текущим CPU-цифрам объявлять его главной причиной нельзя.

Новых художественных упрощений в этом изменении нет. Профилировщик пока только в локальной диагностической сборке; опубликованный стенд получил только переключатель расчёта. Production не менялся.
