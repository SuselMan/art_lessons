# Точное ускорение целочисленного переноса

18.10.2026, исследование #805. Это ограниченный поиск вариантов программы,
не доказательство оптимальности и не формальная superoptimization.

Сравниваются те же физические шаги Macro9 и тот же PACK:

- program0: исходный shader.
- program1: один поток считает всю непересекающуюся пару и пишет обе ячейки.
- program2: пять ограниченных делений материала заменены f32 оценкой с точной
  u32 коррекцией частного. Условия и численные границы — exact-division.md.
- program3: оба преобразования.
- exact-fused: две последовательные фазы X/Y в одном запуске. Рабочая группа
  10×10 загружает ядро8×8 с полем1ячейка. Два shared массива Cell занимают9600B.
  Между фазами стоит workgroupBarrier. Поля пересчитываются независимо;
  в глобальную память записывается только ядро, каждый адрес ровно один раз.

У core Y-соседа все X-соседи находятся внутри поля, поэтому обрезанные расчёты
на внешнем краю shared tile не влияют на ядро. Границы самого листа сохраняют
исходное правило одиночной ячейки. Чётность глобального буфера зависит от числа
двухфазных запусков, а не от исходного числа фаз; отдельно проверяется126шагов.

CPU: деление3310699входов; однократный расчёт пары65872адреса и8192фазовых
материальных ячеек; fused10752двухфазовых ячейки, включая границы листа и групп.
Все PASS. TypeScript strict PASS. Это не заменяет реальную компиляцию и сравнение
GPU. V10 отправлен на Samsung для полного raw RGBA равенства, затем ABBA замеров.
Ускорение пока не заявляется: дополнительные halo расчёты и shared barriers могут
оказаться дороже сэкономленных dispatch.
