# Macro4: динамическое смачивание — другой контракт

`webgpu/macro4-capillary.ts`, export `capillaryDefinitions`. Это отдельная модель `wetDomain:'dynamic'`. **Исходно сухая бумага не является твёрдой стеной.** Поэтому прежние static-domain проверки сухой полосы не являются физическим oracle для этого solver. При необходимости непроницаемой стены нужен отдельный immutable wall input, которого общий вход сейчас не имеет.

Храним четыре состояния: поверхностная вода W, поглощённая бумажная вода S, подвижные carriers M и закреплённые carriers D. Исходный пигмент там, где W=0, сохраняется отдельным literal fine-resolution слоем и не поднимается обратно водой. Модель допускает проникновение новой воды на этот участок, но не выдаётся за моделирование rewet/desorption существующего сухого рисунка.

На каждом шаге:

1. Darcy-подобный четырёхгранный поток рассчитывается из напора `W − suction*(1−S/capacity)` и бумажной проницаемости. Сухой получатель разрешён; отправитель обязан иметь воду выше порога. Сумма исходящих объёмов ограничена запасом W до переноса.
2. Gather переносит W и концентрацию M/W. Затем ограниченная доля поверхностной воды поглощается: W→S, не превышая бумажную capacity. Соответствующая доля пигмента закрепляется M→D. Ничего не исчезает в evaporation: он пока отсутствует, чтобы ledger воды можно было проверить.
3. Отдельный симметричный обмен концентраций смешивает подвижные carriers только между уже смоченными клетками. Коэффициент≤.24 обеспечивает положительность при четырёх соседях.

Это **phenomenological Darcy + absorption + concentration mixing**, а не полный MoXi или Navier–Stokes. Поглощённая S пока стационарна; отдельной диффузии воды внутри капиллярного слоя нет. Основание разделять surface/deposited/paper-water состояния есть у [Curtis et al., §4](https://grail.cs.washington.edu/wp-content/uploads/2015/08/curtis-1997-cgw.pdf), но наши параметры и дискретизация не воспроизводят весь их материал. Начальная вода общего benchmark задана в нормированных условных единицах; это не калибровка PB15/бумаги.

Пигмент после coarse расчёта распределяется по положительным fine-paper весам, нормированным внутри каждой ячейки. Fine dry-initial слой добавляется без движения и без пересоздания через coarse grid. Все каналы сохраняются в идеальной арифметике; окончательный RGBA8 может потерять массу при насыщении/округлении. В финальном pack есть явные counters отрицательных/переполненных fine values, а не молчаливое объявление такого результата правильным.

## Состояние доступно оператору

`run()` только отправляет вычисления. В `readback()` после измерения копируются итоговый RGBA и coarse W/S/M/D; дополнительный map не попадает в GPU completion timing. `metadata.finalState` содержит surface/absorbed/total water sums, mobile/adsorbed alpha-code суммы, число **coarse** клеток, которые стали мокрыми, minima и pack-guard counters. Для сопоставления с входом суммы coarse states умножены на fine-cell area. Initial water sum — нормированная вода на fine pixels; alpha — code-based carrier proxy, не физическая масса. Expanded coarse cells нельзя назвать точным числом fine wet pixels.

CPU oracle использует f64 и проверяет сохранение W+S и M+D на96 шагах; это не сертификат WGSL f32. Water front имеет ограниченную причинность: не более одного coarse-neighbor hop за шаг, без мгновенного глобального смачивания. Coarse reconstruction добавляет геометрическую погрешность размера ячейки.
