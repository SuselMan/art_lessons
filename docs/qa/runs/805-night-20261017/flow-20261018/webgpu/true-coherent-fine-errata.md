# Исправление регрессии композиции fine в V23

**Уточнение первоначального вывода:** проверка истории замороженных исходников root/operator доказала, что **V17–V22 использовали настоящий coherent pair shader**. Тогда macro14 безусловно компилировал `coherentSource`, игнорируя forwarded mobility override. Первоначальное утверждение, что все исторические fine18/22/23/24/26 были mobility, было ошибочным: оно экстраполировало текущий код назад без проверки истории.

Коммит **c2110521**, добавивший `options.pairSourceOverride ?? coherentSource(gain)` для gated-exchange, сделал ранее неиспользуемый override значимым. Macro17 передавал default mobilitySource, macro18 распространял options в macro14. Это создало **регрессию V23**, а не объяснение старых картинок или старых тестов. Исторические V17–V22 coherent physics claims не отзываются. CPU/mass/memory proof остаются в своей фактической области.

Исправление macro18 явно задаёт `basePairSourceOverride=coherentSource(mobilityGain)` до createSmoothFine. Это восстанавливает прежний намеренный shader и поведение V17–V22, сохраняя новый override API для gated/limited кандидатов. Новый ID macro29 остаётся самостоятельным явно защищённым вариантом, **не новой физикой относительно V22**. CPU actual factory тест требует pair==coherentSource у macro18 и macro29, равенство остальных shaders/всех uploads/ψ при одинаковых config. Curl0/128 используют один shader, но разные uploaded fieldSHA.

Обязательный GPU baseline — wholeRGBA относительно замороженного V22 при одинаковых настройках. Curl0/128 на неплоской воде должны реально различаться; shader/field CPU proof не заменяет GPU. Macro27 использует тот же явный coherentSource; его strength0 сравнивается с neutral fine той же coherent-модели. Нет обещания coarse stateHash или универсальной меж-GPU точности F32 fine-init.
