# Smooth fine: точная граница массы и подписи для просмотра

## Единицы

Coarse/fine carrier хранит0..65535, то есть257 carrier-кодов на один байтовый код и65535 на непрозрачный pixel-area. Не путать сумму байтовых кодов с площадью непрозрачной краски.

Для одной компоненты и одной плоскости идеальная clamped half-pixel bilinear реконструкция128→1024 имеет сумму64*sum(coarse). Это верно и на краях: столбцы/строки интерполяционных весов суммируются в8. Для M и D отдельно floor каждой fine величины теряет меньше1 carrier-кода на fine-пиксель. Поэтому combined loss:

`0 ≤ L_M + L_D < 2*N`, N=1024².

Верхняя граница:2,097,152 carrier-кода, то есть <8160.125 суммарных байтовых кодов **на канал**, или <32.001 непрозрачного пикселя площади. Это НЕ «30 byte-alpha кодов». Для mobile отдельно граница вдвое меньше. Для разреженного поля сильнее считать только ненулевые дробные интерполированные величины. На слабом/разреженном мазке даже малая абсолютная потеря может быть заметна в относительных процентах.

Более точно floor loss — сумма остатков weightedM%256 и weightedD%256, делённая на256. Здесь `%` — CPU математическое описание, shader использует floor integer division256; ошибка GPU constantmod257 к этому доказательству не относится.

## Локальный stationary fallback

Пусть S — множество fine-пикселей с literal stationary alpha>0, K=|S|. Вместо smooth floor там берём безопасное nearest M/D. Изменение знакопеременно:

`Δ_S = Σ_S ((M_nearest+D_nearest) − (floor(M_bilinear)+floor(D_bilinear)))`.

Итог до8bit для каждого канала:

`sum(new) = 64*sum(coarse M+D) − L_M − L_D + Δ_S`.

При каждом combined coarse/fine значении0..65535 имеем `|Δ_S| ≤ K*65535`, то есть ≤255*K суммарных байтовых кодов. Это грубая worst-case граница; конкретное Δ может быть положительным или отрицательным. Literal stationary добавляется неизменённым отдельно. Таким образом, global conservation нельзя объявлять для нового init на основании column sums: floor и local fallback — явные отдельные изменения.

## Проверка actual null0 vs12

Для одинаковых inputSHA, params, coarse finalstateSHA и reconstruction:

1. fineSteps0/paperGain0 и fineSteps12/paperGain3 должны иметь одинаковую начальную mobile матрицу: affinity ещё не влияет на init. Сравнить все4 `fineLedger.mobileRGBA16Codes` после расчёта. Парный перенос меняет расположение, но должен сохранить четыре суммы точно.
2. Fine D остаётся read-only после init, literal тоже. Pair shader пишет только mobile. Сравнение всех4mobile сумм является отдельной проверкой нового оператора; оно не доказывает отсутствие потери в initial reconstruction относительно coarse/input.
3. `initialFineMobileAlphaExpected=null` намеренно:64x absolute claim для smooth init неверен. Численная гарантия nearest-варианта к нему не переносится.
4. Проверить init/pack guards0, premul0, actual GPU ошибок0, повтор fullRGBA SHA. После этого сравнить PNG/пигментный итог и скорость; different fine12 image ожидаем, так как это реальный перенос.
5. FinalRGBA8 rounding/dither — ещё один отдельный источник изменений массы. Само сохранение16bit pair ledger не доказывает точную сумму PNG.

Новый reproducible CPU тест `macro17-reconstruction-mass.test.cjs`:3PASS. Независимые целочисленные bilinear weights проверяют точную global identity/floor loss включаяclampededges, signed local delta и корректные единицы1024bound. GPU действия не выполнялись.

## Короткие русские подписи (предложение, assembler не менялся)

| Контроль | Название | Пояснение |
|---|---|---|
| smooth fine0 | Гладкое растекание | Непрерывная основа пигмента, без мелкого бумажного переноса |
| smooth fine12 gain3 | Растекание с мелкой бумагой | Пигмент локально перемещается по бумажным впадинам |
| smooth fine12 gain0 | Локальное выравнивание | Те же шаги без влияния бумажной фактуры |
| safe dither | Округление для показа | Меняется перевод в8бит; вода и движение пигмента прежние |

Общая подпись: «Эксперимент1024×1024. Время включает подготовку входа и ожидание результата; компиляция и чтение картинки измеряются отдельно. Сравнивайте форму растекания, смешение, край и фактуру. Художественное качество ещё проверяется».

Сильные оси без новых моделей: coarse mobility/steps задаёт дальний перенос; absorbed fraction задаёт долю неподвижного D и выраженность запечённого края; fineSteps меняет только локальный горизонт; paperGain влияет на локальное направление/концентрацию; dither влияет на видимость ступеней цвета. Сравнивать одну ось при неизменном input/coarse state, иначе бумажное зерно и новый макро-перенос будут смешаны в одном выводе.
