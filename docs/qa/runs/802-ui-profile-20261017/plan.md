# #802: откуда берутся провалы RAF в Worker-стенде

Вопрос Ильи: при последовательных мазках UI RAF приближается к200мс. Нужно отделить занятую mainJS от задержки кадров/браузера, а также найти фазу: рисование, расчёт цели, морфинг.

Основной поток прототипа не вызывает WebGL в Worker-режиме. Он принимает PointerEvent, вычисляет координаты через getBoundingClientRect, отправляет сообщения; принимает статус/обработку/цель от Worker, пишетDOM. На каждом сообщении сериализует полный диагностический snapshot с двумя историями до256событий и записывает textContent даже в закрытом details. RAF двигает индикатор и обновляет текст максимума. Это подозреваемые затраты, а не установленная причина200мс.

Worker: вся математика/рисование/морфинг. Живой контроллер первые5с запрашивает показ примерно60раз/с, затем30раз/с. На показе: один полноразмерный morph-проход1024, копия в слой, композиция рисунка с бумагой и blit в OffscreenCanvas. tick(0) из present возвращает существующую картинку и не создаёт дополнительного morph draw. Поле соответствия для морфинга строится на128, не1024. В этих функциях нетCPU readback каждого кадра; это не исключает ожиданиеGPU/драйвера.

Проверка: реальные Samsung ownedcontexts,3одинаковых последовательных мазка320/PB15 с ожиданием готовности каждой цели и отдельным окном морфинга. Early observer измеряет RAF timestampgap/actualcallbackstartgap/callbackwall, main messagehandlerwall, diagnosticJSON/stringify/textContentwall, LongTasks и независимый таймер10мс. Контроль меняет в собственном HTTPresponse только одну запись диагностическогоJSON, с проверкой исходногоSHA/единственногоanchor. Модель, Worker, анимация и пользовательский стенд неизменны.

Если RAF200мс совпадает с нормальными таймерами и отсутствием mainLongTask, это не доказательство200мс mainJS. Это сужает область до выдачи кадров/render scheduling; само по себе ещё не доказывает конкретное времяGPU. Скриншоты/PNG/скачивание не выполняются в измеряемом интервале. Профили/trace — только если первого сравнения недостаточно, компактный итог сохранять, расходные дампы убирать.
