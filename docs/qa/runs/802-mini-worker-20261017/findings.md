# #802: результаты эксперимента

Первый запуск на Samsung выявил `ReferenceError: document is not defined` при создании диагностического overlay областей (`mini-puddle/diagnostic-regions-v69.ts`). Сам движок загрузил бумагу и WebGL; ошибка произошла при установке интерактивного контроллера. Это DOM-подсветка для диагностического режима, которая в живом морфинге скрыта; для обоих live-only вариантов эксперимента она заменяется локальным пустым адаптером. Оригинальная подсветка, модель и действующие старые стенды не меняются.

Метрика «цель» на странице — время от приёма pointerup главным потоком до JS-сигнала контроллера после подготовки целевой картинки. Она включает очередь ввода в Worker, но не является отдельным измерением завершения GPU. Плавность main проверяется RAF-интервалами и кнопкой-счётчиком; очередь рисования — временем между пересылкой события и его обработкой движком.

Запуск второго штриха «во время расчёта» должен подтверждаться фактическими временными метками. Последовательность команд CDP через VPS сама добавляет задержку и может не попасть в короткое окно; такое прохождение не доказывает мгновенный отклик нового штриха.

## Первый успешный парный прогон Samsung

Оба режима загрузились и нарисовали два мазка; GL0, ошибокJS/async нет. Сушка, экспортPNG текущего вида и пересоздание чистого листа прошли. Изображение Worker проверено по скриншоту реального Samsung.

В Worker кнопка-счётчик обработана через153.6мс после UP, при этом JS-цель первого мазка готова через254.7мс: кнопка действительно работала до окончания расчёта. В main кнопка обработана через434.2мс, после готовности JS-цели216.0мс. Это один парный прогон, не статистическая оценка скорости.

Первые итоговые maxRAF/maxInputLag нельзя использовать для сравнения целого прогона: UI сбрасывал максимум при каждом pointerdown, в том числе после блокировки первого мазка. Исправление: максимум накапливается от первого мазка до очистки листа, а история приёма/обработки начала мазка сохраняет временные метки. После этого нужен один повторный парный прогон.

## Повтор после исправления метрик

Samsung SM-T970, Adreno650/ANGLE, один парный прогон с одинаковым вводом и общим кодом. Оба режима: GL0, ошибок нет;2начала/2конца штрихов,2готовые цели, сушка, очистка и PNG с валидной сигнатурой прошли.

| Метрика | Worker | Main |
|---|---:|---:|
| Первый большой мазок: UP→JS-цель |193.8мс|217.2мс|
| UP→получение сигнала на UI |203.0мс|220.3мс|
| Второй короткий мазок: UP→JS-цель |96.3мс|89.5мс|
| Максимальный RAF-интервал за оба мазка до скриншота |133.6мс|183.9мс|
| Максимум пересылка→конец обработки события |48.5мс|55.5мс|

Кнопка в Worker обработана через145.6мс после UP первого штриха, раньше готовности цели193.8мс. В main — через284.6мс, после готовности цели217.2мс. Следовательно, перенос позволяет main принимать взаимодействия во время расчёта; полной плавности этот эксперимент не доказывает. UI-RAF всё ещё имеет заметные провалы; их причина отдельно не установлена. Время самой цели не является отдельным GPU-fence измерением.

Второй DOWN в Worker был принят главным потоком всего за3.8мс до готовности первой цели и разобран воркером через8.1мс, обработка заняла ещё2.8мс. Проверка попала в самый конец расчёта. Худший случай ввода сразу после начала длинного расчёта **не проверен**; архитектурно синхронный воркер продолжает ставить такой ввод в очередь.

Два успешных Worker-прогона дали193.8 и254.7мс до первой JS-цели. Цель «стабильно меньше200мс без заметной задержки ввода» не достигнута. Следующий шаг — планирование расчёта с приоритетом ввода и отменой устаревшей цели, плюс уменьшение затрат отдельных операций. Здесь этот новый scheduler не реализован.

Непроверено: Surface/Vega/iPad, A2, комнаты/онлайн, undo/redo, межустройственное совпадение, потеря контекста и блокировка/возврат вкладки. Это локальный live-only Mini1024 для визуальной оценки Worker/Main.

Статическая страница оставлена для проверки Ильёй. Новых серверных процессов нет. Приватные rawJSON/скриншоты и manifest сохранены вне TTL в project-services/gl1-review/worker-802/evidence; в Git сохраняется компактный итог без приватных входов.
