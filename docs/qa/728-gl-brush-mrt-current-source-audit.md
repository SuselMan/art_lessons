# Текущий GL paired brush: доступность и границы

Source audit после `3913aea9`, без устройства/новой сборки/изменений рендера. Default canvas по-прежнему `webgl`; существующий paired shader не использует WebGL1 `WEBGL_draw_buffers`. `diagnosticWebgl2Raw` возвращает underlying native GL2 только для диагностического адаптера. Поэтому применимый путь — свежий canvas с `wcGl2=1&wcMrt=1`, а не включение MRT на нынешнем GL1 контексте.

Цепочка: строгий DEV `Room/diagnostics/watercolorQaOptions.ts` → `PencilEngine` validation/context construction → `adaptDiagnosticWebgl2` → `_initGL` → `configureWatercolorDiagnosticOwners` → `WatercolorPasses.diagnosticBrushMrt` → `CanonicalWatercolorSettlePlan.contactOps.exchange` → `brushPair`. Production query игнорируется; без `wcGl2` флаг MRT отвергается. GL2 недоступен — constructor бросает, без тихого выбора GL1. Warm проверяет MAX_DRAW_BUFFERS/MAX_COLOR_ATTACHMENTS>=2 и компилирует GLSL300; framebuffer completeness проверяется при первом pulse. OFF на том же GL2 выполняет исходные два single draws.

`brushMrt300.ts` (фактическое имя файла `brushMrt.ts`) берёт прежний shader helper body, меняет лишь main/output. Для четырёх направлений outgoing/incoming integerFraction вычисляются один раз по OLD P/C/flow/coverage. Отдельные resultP/resultC сохраняют исходные subtract-floor/add-floor в том же порядке. Оба RGBA8 outputs записаны на прежней Q8 границе. gain/step/scissor/flowRect прежние, contacts/substeps не сокращены; обе прежние copybacks выполняются после pair, `present` остаётся после них. Это уменьшение2draw→1 и повторных fraction samples, не fusion последовательных pulses. Compiler/precision не доказываются одним source равенством.

Историческое доказательство есть: `728-optimization-forecast-2026-10-08.md` фиксирует ordinary Room Surface frozen97e31b45/400/water→pigment/exact fields/material/whole/Dry/Undo/Redo/rejoin, MRT87pairs/fallback0. ## Текущие узкие admission gaps перед свежим paired gate

- `WatercolorPasses.brushPair` проверяет aliases через buffer object identity. Два wrapper объекта с одной texture не отвергаются. Нужен exact texture read/write set, output-output texture comparison.
- Outputs логически сравниваются с field.w/h, но input P/C/coverage dimensions/GL owner не проверяются. `AccumulationBuffer.gl` доступен для pure same-owner guard. Физический storage может отличаться от логического после unequal-size copy; этот контракт нужно проверять без дополнительных driver queries.
- Flow имеет output texture alias check, но GL owner/liveness не доказан самим методом (нужен existing owner registry/контракт upload owner).
- Один cached FBO completeness check не является проверкой всех последующих pooled attachments. Предпочтительно pure format/physical extent/owner guards известных RGBA8 buffers, а не sync `checkFramebufferStatus` на каждом pulse.
- Parser допускает одновременные native и GL2/MRT diagnostics; отдельный эксперимент должен отвергать несвязанные backend flags и подтверждать actual constructor/context/pair counts. Не смешивать front batching, contact hoist, carry MRT при оценке brush MRT.

Это список рисков допустимости входов, не доказанный пользовательский баг: ordinary planner выдаёт разные свои scratch buffers. Новый runtime не внедрён. Следующий минимальный шаг при выборе этого направления — укрепить pure guards/negative tests, затем current-source GL1→GL2 syntax-only exact material gate и GL2 two-single→paired exact gate с одинаковой immutable лентой/бумагой и actual pairs/fallback counts. Runtime lifecycle/context-loss/history gates нужны отдельно; hardware только по allocator.

## Узкое исправление текущих guards

DEV GL2 `brushPair` теперь проверяет texture identity всех read/write буферов, их общий `gl`, logical и tracked physical storage extents. Размеры доступны через read-only getters существующей buffer storage authority; новых ownership registry/driver texture parameter queries нет. При смене flow handle `raw.isTexture` отвергает foreign/dead texture; этот cached owner check не является новой общей lifetime-системой — optional MRT state уничтожается существующими restore/destroy путями, upload lifecycle остаётся прежним.

FBO completeness cache теперь относится к exact output texture pair +physical extent. Новые attachments требуют нового check; повторные pulses по той же паре не добавляют status sync. Обычный GL1/OFF возвращает прежний fallback до новых guards. Shader/gain/step/pulse/copyback и production flags не изменены. CPU negative tests отвергают distinct wrappers с общей texture, cross-owner каждого record, неправильный logical/physical extent и invalid flow; actual mocked brushPair проверяет recheck на смене attachments, отсутствие draw при incomplete и отсоединение обоих targets в finally. Existing GL1 no-compile fallback/diagnostic owner tests прошли; app TypeScript PASS. Аппаратной проверки/обещания выигрыша нет.
