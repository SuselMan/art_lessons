# Каталог QA Grafetto

Единая библиотека повторяемых проверок: #793 (продолжение #689).
Определения кейсов и результаты конкретной версии хранятся раздельно.

1. Выбрать [набор: smoke, full, devices или long](catalog/suites.md).
2. Выполнить [подготовку и инструкции запуска](catalog/execution.md).
3. Открыть кейсы по стабильным ID и пройти шаги с проверяемыми ожиданиями.
4. Сохранить [результат по шаблону](catalog/result-template.md) в `runs/<run-id>/`;
   обновить [последние известные результаты и пробелы](catalog/results.md).

## Значение статусов

| Статус | Однозначное значение |
|---|---|
| PASS | Все обязательные ожидания конкретного варианта на указанной версии и lane подтверждены доказательствами |
| FAIL | Есть воспроизводимое нарушение хотя бы одного обязательного ожидания; expected failure тоже FAIL |
| BLOCKED | Выполнить проверку нельзя: недоступное устройство, неподдержанный размер, нет seed/export или другого предусловия |
| NOT RUN | Для выбранной версии/lane нет результата запуска; существование файла теста не меняет статус |
| INCONCLUSIVE | Запуск начат, но оборван либо доказательств недостаточно/контроль некорректен для вывода |

Повтор после сбоя не стирает предыдущий FAIL. Записывать retries/flake отдельно.
Функциональный PASS и performance FAIL — два gate, а не средний итог. Отсутствие данных
не равно PASS. Результат на одном устройстве/модели/размере не переносится на другие.
Socket identity не равно browser context, physical GPU или физическому перу.
SwiftShader — программная растеризация, MockGL — вообще не растеризация.

## Как пополнять библиотеку

Найденный дефект → воспроизводимый сценарий → стабильный свободный ID и проверяемые шаги →
регрессия, падающая на дофиксном коде → повтор исправления и отдельный run с доказательствами.
Переиспользовать кейс при том же смысле; сохранять отдельный порядок, если он меняет результат
(ACK после ухода, Dry до/после продолжения, UP до disconnect). При объединении оставить alias
и старую ссылку; не перенумеровывать ID и не переписывать исторические отчёты.

Добавить определение в тематический файл, запись в `catalog/cases.json`, suites по смыслу,
автоматизацию в `e2e-map.json`/`night-cases.json`, последний результат по версии/device в индекс.
При изменении ожидания указать модель и причину; продуктовую семантику не придумывать тестом.
Связать defect issue. Исправленный локально дефект остаётся открытым до мержа и проверки.

Проверка целостности без установки зависимостей и запуска продукта:

```sh
python3 scripts/qa/check_catalog.py
```

Компактные SHA/параметры/ошибки/вход и минимум картинок сохранять в runs; сырые trace/video,
сборки и временные комнаты убирать по lifecycle. Приватные URL, cookies и auth в Git не входят.
Каталог не заявляет полного перебора сочетаний; дополнительные варианты записывать явно.
