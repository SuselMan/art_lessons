# #759: Undo поздней части жеста и снимок ранней части

База: `0c005fee77da35c261f739b2ee0a4fbfa4a57314` (main 06.11.2026).

Сценарий: chunk1(seq1,G), Dry(seq2), snapshot2, chunk2(seq3,G), Undo4(chunk2).
Undo/Redo применяются ко всему жесту одного автора; revoke — только к указанной
операции. Снимок2 нельзя использовать после Undo4, хотя его coverage меньше seq3.

Сервер выбирает снимок по всем существовавшим перед control частям жеста. При
холодном входе недостающие части получает отдельным запросом по room/author/
strokeId с ограничением watermark. Обычный вход не загружает покрытые strokes.
Разрешение зависимостей повторяется после загрузки структурного/послойного prefix.

Клиент инвалидирует покрытые части всего жеста, сохраняя одиночную семантику
revoke. Границу control сравнивает с локальным порядком журнала, не с serverSeq.
Если batch replay пропустил позднюю часть как undone, ранняя уже нарисованная
часть всё равно требует rebuild. Полностью пропущенный жест сохраняет быстрый путь.

## Воспроизведение и проверки

- Сервер до изменения: 4 FAIL / 24 теста (selection + cold loader).
- Клиент до изменения: 2 FAIL / 3 теста (закреплённая ранняя часть, два слоя).
- Дополнительный batch replay: отдельный FAIL до изменения и PASS после.
- После изменения: 30 точечных тестов прошли, затем добавлен batch case (5/5
  клиентских). Смежные server snapshots / coverage / OperationLog / engine
  snapshots: 260/260 до последнего batch изменения.
- Playwright использует отдельный Postgres, API и frontend, offset759. В новом
  cold room напрямую сохранены реальные пиксели нарисованного в браузере stroke,
  оригинальный журнал и snapshot2. Ранняя часть отсутствует в resident tail:
  проверяется настоящий Prisma JSON запрос, HTTP index и Room restore.
- На старом сервере HTTP index неверно возвращал снимок2 (FAIL). На исправленном
  сервере обнаружен и исправлен клиентский batch ghost: журнал обеих частей был
  undone, но реальный WebGL framebuffer всё ещё показывал раннюю часть.
- Финальный сценарий проверяет отсутствие alpha-пикселей после Undo, возвращение
  рисунка после Redo и сохранение результата после ещё одного холодного входа.
  Chromium/SwiftShader — проверка логики и пикселей, не физических GPU.
- Ожидаемые HTTP отказы проверяются по URL/status/JSON body и аннотируются:
  `thumbnail`429/rate_limited (штатный throttle3s), `snapshots`400/
  not_a_checkpoint_seq (bootstrap уже существующего покрытия). Остальные HTTP,
  JS и console errors считаются ошибками. Bootstrap refusal не исправляется в #759.

Финальный браузерный прогон: PASS, 123.4s, реальное отсутствие пигмента после
Undo, возвращение после Redo и повторного входа. Typecheck (все workspaces,
e2e, scripts), lint:fix, map:check, map:rules: exit0 (имеющиеся предупреждения).
Полный финальный прогон движка: **1876/1876 тестов, 171 файл, 290.68s, exit0**.
Последний клиентский набор: 5/5. Серверные selection/loader: 26/26.
