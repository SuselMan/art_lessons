Путь акварельного штриха

Кисть создаёт материал, расчёт перераспределяет его, а экран показывает переход. Разбираем эти звенья отдельно, чтобы понимать, где меняется рисунок и где теряется плавность.

Нажми на этап: ниже откроется описание, ссылка на код и вопрос для измерения. Нумерация показывает основной путь; повторные порции и новые мокрые штрихи могут проходить часть этапов снова.

Что с чем связано

Синяя линия — материал и расчёт. Отдельные ветви ведут к экрану и журналу. На телефоне схему можно прокрутить вбок.

Разбор каждого звена

Три состояния, которые нельзя смешивать

Материал

Рабочая краска, вода, покрытие и цвет в scratch. Это входы и состояние расчёта, распределённые по тайлам.

Результат

Канонические пиксели, от которых зависят экспорт, replay, снимки и последующие операции.

Показ

Кадр, который пользователь видит сейчас: слой, промежуточные представления, переход к сухому и тон мокрой бумаги.

Разные пути одного рисунка

ПутьЧто исполняется
Рисую самПеро → дабы → вода/пигмент → живой показ → захват → очередь растекания → результат. Журнал отправляется серверу.
Рисует другой участникЖивые сообщения дают предварительный показ. Подтверждённая операция несёт записанные входы; порядок задаёт сервер.
Вход в комнатуСнимок слоя, если доступен, затем необходимые операции. Без снимка клиент заново исполняет историю.
Undo / RedoМеняется активность операций, нужное состояние восстанавливается через checkpoint/rebuild. Это не просто скрытие последнего отпечатка.

Что хранится в дабе и операции

Даб: x/y, нажим, наклон X/Y, размер, вытянутость, угол, итоговая непрозрачность и время относительно первого даба. На сервере обычно хранится упакованный массив dabsPacked.

Операция: слой, инструмент, preset, цвет, автор/id/время; общий strokeId для порций жеста, washId для мокрой заливки и wet — записанная влажность под каждым дабом, 0…f. Даб не содержит готовую картинку, полное поле жидкости или результат симуляции.

Изменение алгоритма может менять replay старых мазков. Но уже сохранённый снимок содержит прежние пиксели: открыть старую комнату и заново исполнить её полный журнал — разные проверки.

Как дальше разбирать производительность

Для кисти400 фиксируем одну временную шкалу: физическое касание → обработчик → GPU-команды → первый видимый кадр → отрыв → захват поля → завершение расчёта → окончание визуального перехода. Быстрый JavaScript может оставить длинную очередь GPU, поэтому время вызова и время готовности пикселей измеряются отдельно.

Сначала проверяем сухой лист и повторный штрих по воде, затем смену цвета, чужую лужу, нескольких участников, Undo/Redo и перезаход. Меняем одно звено за раз и проверяем одновременно живой опыт и сухой результат.

Схема описывает выпущенный код, а не новую архитектуру. Числа относятся к указанным тестам и устройствам; переносить их на все сценарии нельзя. Экспериментальные async/material/deferred/band-оптимизации в production выключены.
