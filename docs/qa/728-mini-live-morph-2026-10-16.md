# Живое рисование на цели М69/М70

Запрос Ильи16.10 14:15, база0d15e939, #728. Существующий Mini QA, без комнат/production.

## Пользовательский режим

В разделе «Растекание» для М69/М70 появился выбор «Контуры и сухой результат / Живое рисование · морфинг». Переключение не очищает лист. Параметры и библиотека наборов общие. Выбор отражается в URL `view=live`; это не смена старого технического `mode=morph/material`.

В живом режиме кисть продолжает формировать исходные P/C/coverage/solvent. Один видимый flush добавляет только изменение сырого RGBA через optical input transfer существующего presentation.ts. Материальные P/C не заменяются показанной картинкой. На новом DOWN текущая цель отменяется, presentation сохраняет изображение и забывает старую цель. После UP60мс покоя запускается единственный новый расчёт по исходной лужe. Ползунки меняют эту цель после180мс покоя, без сброса картинки. Очереди по числу мазков нет.

Чтобы не анимировать промежуточные физические поля как окончательную цель, presentation получает только полностью готовую сухую цель. До её готовности показанная картинка остаётся на месте. Это означает задержку начала движения на время расчёта цели — её устранение не заявляется.

Морфинг пока прежний: matching-flow между изображениями, нелинейный быстрый старт, естественная шкала120с с длинным хвостом; кнопка «Высушить» ускоряет часы ×100. После завершения слой получает готовый результат, мокрый scratch закрывается; следующий мазок начинает новую лужу поверх сухого backing. Промежуточный морфинг не фиксируется как канонический результат. Возврат к контурам до полного высыхания показывает исходный материал.

М69/М70 теперь используют общий interactive-controller с соответствующим native target factory. Буферы/программы presentation создаются только при включении живого режима и уничтожаются при выходе. В диагностике добавлен один RGBA rawNext буфер; чистые настройки/контуры не компилируют morph pipeline заранее.

## Найденный дефект отмены и исправление

Первый тест: сырые P/C/coverage и wet volume совпадали, split refs совпадали, но native-финал сразу после отменённого prefix-расчёта отличался от повторного расчёта. Последующие завершённые пересчёты возвращали baseline. Трасса сохранена в `temp/device-runs/mini-live-20261016/*-trace.json`.

Причина — WatercolorFrontPaths кэширует prefix edges по identity поля и параметрам, без версии содержимого coverage. Обычно следующие unit passes инвалидируют cache. Отмена между prefix passes оставляла его пригодным по ключу для следующей цели с другим coverage. М69/М70 адаптеры явно вызывают invalidate существующего front-path cache при resetFromScratch. Внутри одного расчёта кэш остаётся включённым; дополнительная полная симуляция не добавлена. Вызов пока использует private API прототипа; production engine поведения не менял.

## Проверки на Samsung

SM-T970/Adreno650/WebGL1. `mini-live-morph.cjs`: фиксированы PRNG, логическое время и события. Проверены М70 и М69 отдельно.

- Четыре соприкасающихся мазка. Второй приходит до инициализации цели; третий после начала морфинга; четвёртый отменяет частично выполненную цель третьего.
- Исходные SHA и конечные SHA P/C/coverage совпадают между контурным и живым режимами. Это проверка на одном устройстве, не межустройственная гарантия.
- Изображение меняется при морфинге, исходный материал остаётся неизменным.
- Возврат к контурам/обратно сохраняет raw SHA и epoch. Изменение силы фона меняет цель, возврат значения восстанавливает тот же goal SHA.
- Ускоренная сушка сохраняет goal SHA. Затем отдельный пятый мазок/повторная сушка оставляет старую область x<650 побайтно неизменной.
- GL0, context not lost, page errors[].

`mini-native-input.cjs`, М70 view=live: пять быстрых доверенных CDP pen-жестов, все приняты. DOWN handler38.4мс холодный,2.8–5.6мс следующие. Это CPU обработчик, не физическая задержка пера или гарантия FPS; интервалы последующих display вызовов заметно больше, поэтому производительность движущегося пера ещё требует человеческой оценки. Есть screenshot живого состояния.

Регрессия `mini-presets-preview.cjs` пройдена: контурный предпросмотр не мигает линиями при пересчёте, raw/epoch сохраняются, библиотека наборов сохраняется после reload. Scoped tsc и статическая сборка Mini прошли.

## Что ещё оценивать

Илья ещё не проверял художественное поведение этого живого режима. Matching-flow может искажать детали гребёнки и создавать изломы; он намеренно не заменён в этой задаче. Задержка до первой готовой цели, поведение частых новых мазков и промежуточный вид — следующие предметы настройки. Онлайн-совместимость новых настроек/события Dry не доказана, переноса в production нет.

Собственные вкладки и ADB forward/reverse закрыты после проверки; временные генератор/trace harness/tsconfig удалены. Компактные JSON, логи и необходимые PNG сохранены. Новых сервисов/агентов нет; действующий Mini QA и его зарегистрированная сборка оставлены для Ильи. Push/галерея не затронуты.
