# Быстрая сушка с сохранением мелкой кисти и GPU-планированием

Код модели `2c54ebf0`, проверки ресурса `779e3026`, GPU-часы `1cbccd8a`, causal peer harness `96d78df8`. Ветка `agents/728-watercolor-room-integration`. QA opt-in `?qaFastDry=smooth`; default остаётся Б. Push/production не выполнялись. Художественное одобрение требуется.

`front8-detail-flow-v1` сохраняет фронт, бумагу и реконструкцию кисти S2, но перенос контакта широкой кисти считает в одном сохраняемом S4-поле на весь жест. Промежуточные результаты восстанавливаются в S2 при публикациях и перед завершающим приливом группы. Это новая приближённая модель с версией в операции. Вариант smooth использует ту же модель, но GPU fence через восемь проходов позволяет планировщику учитывать реальное GPU-время; пиксели smooth/flow на измеренных сценариях совпали.

Fine1024, кисть380, 12 пересекающихся мазков; timer включает завершение GPU и canonical readback. Samsung Adreno650: Б ~22.1с, detail ~8.4с, flow 7.03с, smooth 8.61с. В последней паре p95 интервала rAF 501.5→50.1мс, max585.1→434.6мс; 13 интервалов >100мс остаются. AMD Renoir: flow1.64→smooth2.63с, p95~167→22.3мс. Это малые выборки, не физическая pen-to-photon latency и не гарантия отсутствия рывков. Offline `setViewport` меняет legacy input transform, но камера рендера в этих тестах остаётся zoom1. Для изменения камеры нужен `setInfiniteCamera`.

Полная комната Samsung: 12 широких мазков трёх цветов через настоящий PointerInput посредством CDP pen events. Все12 операций записались, undo меняет рисунок, redo и перезаход возвращают те же canonical hashes, GL0/no loss/errors[]. p95 rAF рисования50.1мс, Dry33.4мс. Эти интервалы включают служебные чтения; точное время кнопки из них не выводится. Отдельный двухмазковый прогон подтвердил цвет в framebuffer до каждого UP (синий599476пикселей; жёлтый459411), возврат кнопки Dry, redo/reentry exact. Но CDP screenshot второго живого мазка показывает прежний синий кадр вопреки жёлтому в framebuffer. Фактическая своевременная публикация на экран пока НЕ подтверждена; сверка Android screencap подтвердила оба мазка и зелёное пересечение при удерживаемом пере. CDP screenshots остаются устаревшими даже после250мс и не служат доказательством задержки. Оригиналы Android с адресом собственной QA-комнаты сохранены в приватном evidence-каталоге, не в Git. Точная pen-to-photon latency по этому прогону не известна. Камера .35/1/2 не меняла canonical hashes; визуальную резкость при всех зумах это не доказывает. Скриншоты до UP сохранены.

Полная комната AMD с двумя участниками: peer, undo, redo, redoPeer, reentry, context restore exact0/max0; GL0. Первый прогон сравнил peer до доставки операции и показал несовпадение. Harness исправлен: перед сравнением ждём одинаковый head/undo/redo operation ID и затем idle; повтор прошёл. Это исправление проверки, а не скрытие первого результата.

Ни один сценарий не заменяет ручной оценки Ильи. Контекстный смоук пока двухмазковый; долгие сессии и аппаратный ввод стилуса требуют отдельного прогона. Компактные данные лежат в `runs/728-flow-smooth-2026-10-15`.

Дополнительно: специализация обычного сложения полей (mode1 без world fibres) дала точное совпадение 480 GPU-наборов /31,762,560 каналов на каждом реальном GPU. Повторный ABBA полного сценария: Samsung native8296.3/8235→source7828.9/7780.1мс (~5.58% быстрее); AMD native2639.9/2643.8→source2775.3/2638.9мс (~2.47% медленнее, один source выброс). Canonical hashes одинаковы внутри всех четырёх прогонов на каждом GPU. Это не межаппаратная побайтная эквивалентность модели. Native diagnostic использует исходный общий fragment с минимальными uniform/bind для mode1, поэтому измеряется прежде всего цена шейдера, а не все старые CPU-вызовы.

Временные ресурсы: текущие disposable на VPS/ноутбуке и ADB19223 остаются на время продолжающейся ночной проверки; два прежних QA frontend и один backend сохранены. Новые постоянные сервисы не создавались.
