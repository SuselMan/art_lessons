## Что перенесено

Наша кисть, бумага, оптика, перенос пигмента и внутренняя граница сохранены.
Внешний фронт проходит восемь клеток по сумме настоящих стоимостей промежуточных
рёбер, затем выполняет восемь исходных уточнений. Это художественно одобренная
новая модель, а не обещание побайтного совпадения с прежним единичным фронтом.
Для нового режима минимальное поле при масштабе 2 — 768 вместо 1536.
Кэш направлений добавляет 11.25 MiB при 768; уничтожается вместе с проходами.

Сушка выполняет короткие готовые канонические задачи через postTask (fallback
setTimeout), с GPU fence после порции. Ожидающие зависимости остаются на rAF.
Новый ввод возвращает работу к кадровому планированию. Команда сушки сохраняет
прежнюю семантику FIFO/локальной публикации; ticket не позволяет старому завершению
выключить ускорение более новой команды. Это ускорение расчёта, а не замораживание
текущей картинки.

Модель записана в preset мазка: шестое поле `wc@front8-v1`. Пакеты живого штриха,
лог, undo/replay используют записанную версию. Без поля действует legacy; неизвестная
версия отклоняется. Разные модели не объединяются в одну wash identity.
Должны обновиться все читатели до публичного включения нового авторинга.

Полная комната включается только в DEV через `VITE_QA_WATERCOLOR_MODEL=front8-v1`.
Production authoring остаётся legacy. Ни main, ни production не опубликованы.

Воспроизводимый браузерный сценарий: `docs/qa/harness/watercolor-room-front8.cjs`.
Вход через переменные QA_OUTPUT, QA_BASE_URL, QA_ENTRY_URL, QA_ROOM, QA_HOST_STATE.
Нужна свежая одноразовая комната Fine 512x512 и storageState её владельца.
Не коммитить entry/storageState: это приватные доступы. Скрипт закрывает свои
контексты в finally, сохраняет компактный JSON и одну картинку. Сценарий проверяет
два пересекающихся живых мазка, настоящую кнопку сушки, запись версии, совпадение
канонических тайлов участников, undo/redo и перезаход.

Ночью сначала паспорт устройства/GPU, видимость вкладки, SHA, модель и параметры.
Проверять один/два/много широких пересекающихся мазков; новую кисть во время сушки;
синий+жёлтый, каплю в луже, гребёнку, отсутствие треугольников и исчезновения цвета.
Измерять отдельно DOWN→первый видимый пиксель, MOVE/rAF и принятие Dry→завершение;
не смешивать GPU-время с отзывчивостью. Паузы ввода не подменяют быстрые мазки.
Затем два устройства: финальные тайлы/лог, undo/redo, поздний вход, снапшот,
экспорт, потеря/восстановление контекста. При первом расхождении сохранять вход,
SHA, параметры, короткую трассу и минимальные картинки; сначала исправлять его.

## Ресурсы

Один общий QA backend, отдельная QA база в существующем контейнере. Оставлены два
frontend: одобренный standalone и интеграция. Прежний baseline остановлен. Ночные устройства
ещё не проверены. Временные браузеры закрываются; runtime/cache интеграции оставлен
на время проверки и зарегистрирован с TTL. Старые worktree и данные не удаляются.

Паспорт через существующий dev bridge:
`DEV_BRIDGE_PORT=5384 node_modules/.bin/tsx apps/web/scripts/devbridge.ts eval <page> @docs/qa/harness/watercolor-device-passport.js`.
Плавность — существующий `apps/web/scripts/devices/penbench.mjs`; после сценария
забрать паспорт и ошибки повторно. Устройство должно оставаться с активной вкладкой.
