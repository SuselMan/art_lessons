# #759 / #761: клиентские snapshot baseline

17.10.2026, engine regression `index.protectedWaterSnapshot.test.ts`. Runtime source не менялся во время GPU freeze. Эти проверки не заменяют аппаратную сверку жидкости.

## #759 — подтверждённая потеря группового Undo

Первый chunk seq1 → Dry2 → snapshot2 → второй chunk seq3 с тем же author/strokeId → Undo4, адресованный второму chunk. Reader уже знает первый chunk через backfill. OperationLog правильно делает оба chunks undone, но pinned snapshot первого chunk остаётся. SnapshotIO проверяет coverage только target ID второго chunk, отсутствующего в snapshot2. Baseline: FAIL `hasSnapshotFor(L): true`, ожидается false; сравнение реальных pencil pixels предусмотрено после снятия неправильного CP.

Дополнительные границы: cross-layer eraser должен инвалидировать снимок слоя раннего sibling; teacher revoke второго chunk должен сохранить снимок первого; chunks, созданные после управляющего события, не относятся к его изменению.

## #761 — подтверждённая ложная quarantine

Cold snapshot5 уже учитывает Undo4 цели stroke3 и содержит независимую старую краску. Reader получает stroke3, затем отдельной страницей Undo4. Global seq1/2/5 ещё не загружены. Журнал становится правильным (`stroke3=undone`), но слой ошибочно получает `pendingSnapshotHistoryRepairs=[{L,beforeSeq:6}]`. Baseline: FAIL, ожидается отсутствие ремонта правильного snapshot.

Для различения нужны original serverSeq управляющего события и его вид. Local op.seq — индекс журнала, сравнивать его с snapshot watermark нельзя. Pending local controls не имеют serverSeq и всегда требуют fail-closed проверки.

## Защищённая вода: положительный cold-client probe

Snapshot5 после A1/B2/C3/Aundo4/Dry5; reader получает только B/C/Aundo/Dry. Bundo6 правильно запрещает публикацию и не уничтожает неизвестную базу. Bredo7/Cundo8/Dryundo9 остаются в quarantine. После A1 полный refold снимает pin, запрашивает rebuild и сохраняет A как water-only. После Bundo10 A-water исчезает. PASS.

Этот тест использует настоящие SnapshotIO/ledger/OperationLog и перехватывает только fluid-render seam: MockGL не моделирует пигмент. Для #759 pencil-case проверяются настоящие доступные mock raster pixels; фактическая жидкость требует GPU.

## Корректность будущего исправления

Реальным Undo/Redo/Revoke нужно передавать явную причину; sibling expansion только для Undo/Redo, same author/strokeId, до local seq управляющего события. Revoke удаляет только адресованный chunk. Coverage сравнивается с serverSeq этой причины.

Для поздней hydration нельзя выводить правильность снимка лишь по совпавшему state. При неизвестной причине или наличии более поздних/pending history mutations, способных изменить foreign water, сохраняется fail-closed поведение. Проверяемое исключение — положительно установленное старое управляющее событие, уже входящее в watermark снимка.

## Локальный кандидат после GPU release

Реальные управляющие события передаются явно, включая context-loss путь. Для исторического refold отдельный поиск находит последнее валидное адресованное событие и проверяет, что его эффект соответствует текущему состоянию. При отсутствии положительной причины используется fail-closed путь.

SnapshotIO не инвалидирует уже учитывающий подтверждённое событие снимок (`serverSeq <= coveredSeq`). Для hydration это исключение дополнительно запрещено при любом известном более позднем или неподтверждённом history control — зависимая foreign water может измениться без смены apparent state исходного мазка.

Targeted validation: 64 теста / 4 файла PASS, включая обе бывшие FAIL-регрессии, cross-layer eraser, revoke-only-target, future chunks и консервативный отказ при неизвестном новом foreign control. Hardware oracle ещё необходим для жидкости.
