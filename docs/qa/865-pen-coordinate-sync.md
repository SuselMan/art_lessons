# #865: координаты пера после отложенного создания движка

## Причина

В `a4cd11f7e` создание движка перенесено в `afterBoardPaint` (rAF + timer).
`useCanvasViewport` продолжал синхронизировать камеру только при изменении `vp`.
Эффект мог выполниться до появления `engineRef.current`; последующее создание
движка не изменяло зависимости эффекта. Таймер восстанавливал размер backing
store, но не камеру и не её преобразование client→world. Новое перемещение камеры
случайно исправляло состояние. Аналогичное окно было при смене доски.

## Исправление

Оба эффекта получают существующий `engineEpoch`, который увеличивается после
каждого создания движка. Камера и размер синхронизируются для нового экземпляра,
даже если положение/размер viewport не изменились. Начальный размер применяется
непосредственно, вместо отдельного 50-ms polling. Координатные формулы, сохранённые
штрихи, сетевой формат и поведение кистей не менялись.

## Проверка

- Chromium, настоящие React hooks + Camera, отложенный первый экземпляр и его
  замена при неизменном viewport: до исправления камера не инициализировалась
  (0 вызовов). При DPR 1/1,5/2 ошибка контрольной точки составляла соответственно
  36,06/187,95/360,56 мировых единиц; после исправления — 0 во всех шести случаях.
- 58 unit-тестов Camera/cameraMath/pointerTransform/engineWiring прошли.
- Типы web (app/SW/node) и e2e, lint без ошибок, map:check; map:rules — 0 ошибок,
  73 существующих предупреждения.
- Полная регрессия `e2e/specs/penAlignment.spec.ts` проверяет координаты первого
  записанного штриха относительно входного указателя сразу после входа и после
  создания новой доски, без предварительного изменения камеры.

Первые прогоны новой e2e-проверки содержали ошибки самого теста: прямое чтение
`dabs` вместо `strokeDabs` и использование серверных имён размеров вместо
`RoomInfo.width/height`. Они исправлены; исходные логи сохранены в temp.

VPS Chromium использует SwiftShader. Это не физическая проверка пера Surface
или Safari/iPad. Surface доступен по SSH, но текущий пользовательский Chrome не
имеет CDP; его не перезапускали. Доступной dev-страницы iPad нет.

Итог полного сценария: DPR 1 и 1,5 прошли; повтор DPR 2 прошёл после уточнения
допуска до 0,5 CSS px. Исходная разница DPR 2 —0,08445 мировой единицы, то есть
существенно меньше экранного пикселя: размер backing store округляется при
действующем пиксельном бюджете. Это не остаточное видимое смещение пера.
Все три плотности проверены на входе и после смены доски.
