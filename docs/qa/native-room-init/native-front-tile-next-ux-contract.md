# Front tile: качество совпало, существенного ускорения нет

Actual source `bdab5e6f`, одна OFF/ON пара на Surface. Все десять конечных Q8 полей двух операций и RGBA экспорт совпали. GPU first-water material job: 1130,10 → 1112,93 мс; front целиком: 714,60 → 714,47 мс. Плиточным стало 120 из 240 front проходов, только stride=1; 120 других остались исходными. Сопоставленные eligible проходы: 342,82 → 330,30 мс. Это фиксированный порядок, не доказанное причинное ускорение. Wall окна вырос с 1422,7 до 1721 мс, replay — с 4514,1 до 5005,4 мс. Флаг остаётся выключенным; новых shader bench для этого кандидата не нужно.

Следующая цель относится к пользовательскому пути: второй DOWN должен получать настоящий акварельный source, сохраняя материал предыдущего мазка. Ранее измеренные 361 мс ожидания source включали завершение предыдущего материала и publication с queue-prefix ACK; GL import сам занимал около 0,3 мс. Это не доказательство медленных getParameter, не длительность отдельного GPU прохода и не physical pen latency.

Следующий безопасный контракт до реализации: зафиксировать immutable input/read set предыдущего finish/publication, доказать ownership и отсутствие алиасинга при допуске следующего source. Запретить публикацию старого результата поверх нового; сохранить исходный ordered canonical log и все Q8 границы. Проверять два заранее заданных мокрых жеста с фактическим UP→DOWN gap и previousPending, source/FIFO/ACK/publication/display метками, без горячих readback. Конечные роли и экспорт снимать после idle. Замена акварели временным карандашным preview и слепое переставление FIFO неприемлемы. До такого ownership proof новый native source не допускается вне текущей очереди.

Параллельная GL работа по CPU raster и подготовке мазка ближе к текущему продукту; её результаты нельзя приписывать этой native паре. Массовые ROI или новые scheduler caps здесь не внедряются.

## Проверенные зависимости admission

`RoomNativeRuntime.emit` заранее собирает commands, копирует scalars и bounds и берёт отдельный metadata snapshot. `RibbonStrokeScratch.captureFinishMetadata` копирует paints, travel, contacts, foreign sources и dry context. Это подготовленный input, но не отдельный GPU material: `ownerFor` выбирает текущий scratch/tile/target при выполнении и может retire прежнего executor. `emitPrepared` мутирует owner scratch/film/metadata и запускает source/live; `prepareSettle` использует те же owner fields и scratch. `publishWithoutDrain` работает с target.field и GL tile данного executor, а late publish запрещён после retire.

CPU prototype contract проверяет настоящий RoomNativeCentralAdapter/FIFO: следующий source с frozen input остаётся за held material publication; publication читает предыдущую material version и только потом source меняет её. Это dependency/lifecycle proof текущего порядка, не доказательство безопасного COW или реализация раннего source. Никакие runtime scheduling изменения не внесены.

Нужен отдельный read-set/ownership паспорт до COW: previous pressure/mask/coverage/inkLoad/inkColor, planner scratch и target publication snapshot/version; next source write set и его начальный canonical baseline. Размеры физического COW нельзя обещать малыми: один full RGBA8 1536² — 9 MiB, пять таких полей — 45 MiB, без остальных scratch. Копирование целого owner ради уменьшения 361 мс может ухудшить память и GPU очередь. Оценка выигрыша остаётся неизвестной; shader pair этого ожидания не измерял.

Baseline для следующего reviewable QA стенда: source preparation 15+3, paired brush ON, cache+factor ON, film/tile/mode5/identity OFF, quantum8/4мс, scope cap0. Native cache/factor пока задаются owned QA hook, не публичным Room query. URL с одним wcNativeBrushPair не включает их автоматически. Root может использовать существующий controller corpus; новых сервисов/production изменений здесь нет.

## Runtime prototype и явно открытый content gate

Контекст `diagnosticSourceOwnershipAssertions` по умолчанию OFF передаётся в actual executor. Existing-role passport проверяет backend/layer/generation, buffer/field identity, размеры и live field ledger вокруг source encode и planner prepare; publication callback после существующего ACK проверяет passport до GL import. Новых fence/Promise/GPU операций нет. Вновь выделенные во время обычной инициализации роли не объявляются immutable: проверяется только ранее существовавший read set. Прототип не меняет очередь.

Dynamic writer census: `CanonicalFieldBuffer.clear/copyTo/copyRegionInto/upload`; backend clear, upload/encodeUploadRgba, copyField/copyRegion; stamp/ribbon raster attachments; fieldOp/dispatcher storage outputs; paired brush P/C и copybacks; finish/live composite target. Source читает current coverage, inkLoad/inkColor, film strokeInk/strokeColor, inkBase/colorBase, solventLoad/base/film; runningCoverage может выбирать другой coverageFilm. Live composite дополнительно читает original и immutable paper/noise; planner использует current pressure/mask/coverage и scratch, publication — current target.field и GL tile.

`staticInputEpoch` относится к paper/noise, не является revision всех material textures. Поэтому samebuffer.clear сохраняет identity passport, а содержимое меняет: CPU тест явно оставляет contentRevisionProven=false и earlyAdmissionAuthorized=false. Полного immutable byte/readset proof нет — HOLD для раннего admission. Нельзя назвать проходящие reference assertions разрешением COW/reorder.
