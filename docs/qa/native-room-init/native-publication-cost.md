# Публикация native акварели: скалярные границы

DEV-флаг `wcNativeSchedulingObserver=1` включает наблюдение только публикаций с существующим FIFO-паспортом. Паспорт захватывается при вызове публикации; callback после существующего ACK не читает текущий запрос. Владелец задаёт неизменный `ownerEpoch`. При экспорте вне запроса callback отсутствует.

`canvasSubmit` измеряет исходное кодирование и queue.submit. `queuePrefixAck` измеряет исходный onSubmittedWorkDone: это очередь до ACK плюс доставка callback, не эксклюзивное время GPU. `glCanvasImport` измеряет исходный restoreCanvasPixels. `glStateRead` вложен в import и измеряет четыре исходных getParameter; суммы import и stateRead складывать нельзя. Новых GPU вызовов, fences, ACK или Promise нет. При OFF нет диагностических часов/строк. Ошибки report не влияют на исходные ошибки, состояние и очистку. Контроллер сохраняет максимум1024 скалярных строк после input, без записи JSON на каждую публикацию.

Кэш GL состояния в движке не найден. ImageImport/AreaOps напрямую меняют bindTexture/pixelStorei. Поэтому замена getParameter предположенными значениями пока небезопасна: требуется доказанная исключительная область владения и отслеживание всех записей. Полученный большой publish span не доказывает стоимость getParameter.

Материал исполняется в прежнем порядке. Dirty rectangle либо ранний source требуют отдельного byte oracle (включая RGB при alpha0, ориентацию и восстановление GL состояния); здесь они не реализованы.
