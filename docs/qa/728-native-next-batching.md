# #728 — следующие три кандидата batching без fusion

Основание: настоящий Surface submission профиль `temp/fast-watercolor-night/native-grouped-surface-1791419394322.json` (100px) и `native-grouped-surface-1791419910244.json` (400px). Эти записи старше latest static caches; ranking — по сохранившимся местам вызова, новый payoff нужно измерить. CPU encode/submit не GPU time; wall включает весь standalone сценарий и не равен pen latency.

100px OFF: source73 submit/34.4ms CPU encode, live73/5.1ms, prepare1/7.9ms, settle574/52.2ms. ON settle1/18.8ms; wall1118.3→1045ms. 400px OFF: source21/31.3ms, live21/3.1ms, prepare2/13.9ms, settle397/46ms. ON settle2/40.7ms; wall2020→2081.4ms. Следовательно один grouped успех не обещает ускорение каждого размера. Latest combined static cache100 сохраняет author/replay exact и native→legacy43 282/max36; это самостоятельный кандидат, не baseline для этих wall цифр.

1. **Источник и немедленный live composite в одном encoder.** `CanonicalBoundedSceneRunner.prepare` сейчас вызывает два соседних `adapter.runQuantum`: source.execute затем finish.encodeLive. Сохранить оба набора GPU render/copy операций и Q8 targets дословно, но выполнить в одной owner scope; transient buffers удержать до общего queue completion. Для измеренного100 source+live submits146→73, 40042→21. Source material не может быть представлен до завершения composite и сейчас, поэтому GPU dependency та же. Gate: immutable canonical commands/order, source buffers/whole hashes, pointer start and frame timing. Риски — pool CPU side effects и owner cleanup, не формула.

2. **Ограниченное группирование progressive settle между frame boundaries.** `runProgressive` сейчас await frame после каждого original op. Не менять/сливать эти op: выполнять, например, до восьми original closures в одной `runQuantum`, сохраняя все compute dispatches и промежуточные Q8 writes; затем yield. Полные574 ops дали бы до72 groups вместо574 и до72 frame boundaries. Это только арифметический верхний ориентир, не измеренное UI число или обещание ускорения. Включать бюджет/retired check между closures, оставлять настоящий preview composite внутри порядка op и показывать последний завершённый preview на boundary. Gate: original ordered trace, каждый Q8 field, final material, immediate onset, cancel, UI frame budget. Без такого gate нельзя принять перенос preview callbacks: animation изменится, хотя финальные pixels могут совпасть.

3. **Immutable uniform arena и общий retirement ticket на submit.** `runQuantum` создаёт encoder, submit и queue.onSubmittedWorkDone на каждый scope; pass implementations создают uniform buffer/bind group для каждой команды. Для grouped serial job выделить уникальный aligned uniform slot на каждый original draw/dispatch и один staging upload неизменного массива; dynamic offsets/prepared bind groups сокращают повторную CPU сборку и retirement callbacks. Один offset нельзя перезаписывать несколькими queue.writeBuffer до submit: это изменит ранее encoded draws. Точные Float32 bytes, alignment256, per-command resource identity и GPU order должны остаться прежними; отдельный completion ticket освобождает всё только после submit. Gate: uniform byte ledger, submission trace, failure cleanup, field/whole exact. Нужен профиль allocation/bindgroup доли до реализации; по имеющимся encode totals аппаратный выигрыш этого шага неизвестен.

Batching устраняет CPU submissions/сборку, а не физические Q8 операторы. Удалять dispatch, заменять несколько Q8 округлений одним float проходом или менять solver iteration count здесь не предлагается. Если dominant GPU kernel остаётся тем же, одна эта работа не обеспечит крупного wall выигрыша.
