# Большой шаг contact gather, 15.10.2026

База `29545871`, worktree `728-dry-large-step`, ветка `agents/728-dry-large-step`.
Независимый художественный кандидат: симметричный semi-Lagrangian gather вместо
последовательности одноклеточных contact pulses. Подача Г/v4, вода, front,
ремобилизация, диффузия и финальная кромка не изменяются.

После создания v4 engine, до replay:

```js
engine._settlePlan.diagnosticLargeStepGather = 0.75 // бережный
engine._settlePlan.diagnosticLargeStepGather = 1.4  // сильный
engine._settlePlan.diagnosticLargeStepGather = 0    // неизменённый baseline
```

Режим фиксируется при prepare. На каждый записанный контакт выполняются три
шага (по два draw P/C и две copyRegion). Дальность растёт как квадратный корень
радиуса и экспозиции. Четыре bilinear gather-точки идут вдоль потока в обе стороны;
midpoint trace учитывает направление в середине. У каждого sample пять проверок
мокрого пути; вес возвращается в центр при сухой границе. Средний вектор не
нормализуется, поэтому взаимно обратные движения гасят перенос.

Все веса одинаковы для P/C и выпуклы (центр >=0.24), нет отрицательных значений
или переполнения. Это не точное сохранение массы: неоднородное поле потока и
округление RGBA8 могут создавать/терять массу. Нужны сумма P/C до/после и просмотр
смешения, гребёнки, лужи на общей аппаратной проверке. MockGL не доказывает
GLSL-компиляцию или художественный результат. RGB не переносится.

Для широкого контакта число шагов больше не зависит от радиуса/экспозиции.
Фактическое ускорение ещё не измерено; один gather делает больше texture fetches,
чем один старый pulse. Также не сокращены количество записанных контактов и CPU
построение flow. При малом контакте три шага могут оказаться дороже baseline.

Собственные браузеры/сервисы/временные runtime не запускались. Переиспользован
node_modules базы при идентичном lockfile; @grafetto/shared локально перенаправлен
на собственную рабочую копию, её dist собран из её исходников.

Проверки: 111 тестов WatercolorSettlePlan/flowContact прошли, включая finish,
abort и context-loss двух моделей при 0/0.75/1.4; проверяются три шага на контакт,
совместное чтение неизменённых P/C и освобождение scratch. Web typecheck и oxlint
изменённых TS файлов прошли. Аппаратный рендер выполняет управляющая сессия.
