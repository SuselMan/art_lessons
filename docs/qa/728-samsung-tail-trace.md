# #728: Samsung — пауза графического конвейера

Проверка исходного executable `d88bb738`, Samsung SM-T970 / Adreno 650,
Chrome 154, A4 1754×2480, чистая вода, кисть400. Пользовательский стенд
не менялся. Собственный контекст закрыт после проверки.

В корректном повторном trace между animation frames было 950.859 мс.
Внутри этого окна renderer продолжал короткие задачи; максимальное событие
главного потока — 6.129 мс. Композитор зарегистрировал 58 циклов,
56 dropped, один presented all и один presented partial. GPU main выполнил
837 PerformWork polling events. Это свидетельство задержки графического
конвейера, а не JavaScript-задачи длительностью около секунды. Trace не
измеряет длительность конкретного шейдера и не устанавливает виновный проход.

Отдельно, после UI Dry, FunctionCall занимал 294.004 мс, вложенный
GLES2ReadPixels — 268.29 мс, WaitForCmd — 265.99 мс. Чтение снимка произошло
после исходной паузы и не объясняет её. Исправление повторных пустых снимков
проверяется отдельно; первый readback этим исправлением не устраняется.

Прогон: active max19 мс, tail max953 мс; два native ACK, GL error0,
context lost false, visibility visible. Нельзя объявлять весь опыт плавным.
