# Samsung: первый native watercolor внутри обычной Room

Frozen source `2c1d44b9`, Chrome 154, Samsung SM-T970. Сетевой bootstrap через доверенный QA origin; критические HTTP raw SHA engine/index, roomNativeRuntime и roomWatercolorExecutor совпали с frozen manifest. Старые попытки не запускали GPU: сначала экран Dozing, затем TLS interstitial; они не являются rendering failure.

Доверенный повтор прошёл реальный Create A4 и Join UI. Перед рисованием: secure context true, navigator.gpu true, native option true, native runtime ready, canonical queue idle, GL context alive. CDP pen размер40, preset normal:100:100:PB29:round, world300→360/y300 внутри origin-zero tile. Settings через существующие engine setter API, ввод через настоящий PointerInput, дополнительного журнала не было.

После первого штриха появилась настоящая StrokeOperation в существующем журнале, но GPU потерян: GL context lost, canonical task cancelled. При retirement ожидание WebGPU completion отклонилось с `OperationError: A valid external Instance reference no longer exists`. Полный stroke settle/визуальный endpoint не подтвердились; вода→пигмент, dry и undo/redo не запускались. Размер40 smoke не измеряет производительность400.

Readonly Android logcat: 10-08 10:45:07 AdrenoVK/Dawn initialization; 10:45:14 Chromium сообщает `GPU process exited unexpectedly: exit_code=0`. В crash buffer нет текущей QGLC/SIGSEGV stack, только старые SIGTRAP Oct6/7. Compiler, watchdog, OOM или другая driver failure остаются гипотезами. RAM перед прогоном1636MiB, периодический последний отсчёт1744MiB; это не исключает кратковременный GPU memory pressure.

Raw evidence сохранено вне Git: worktree `temp/device-runs/room-native-samsung-2c-trusted-joined/{report.json,failure.png,main.txt,crash.txt}`. Только собственная вкладка закрыта. Chrome/device не перезапускались, cache/cert/router не менялись. Новые Samsung GPU прогоны после потери остановлены.

Следующий gate: локализовать первый failing native pipeline/dispatch без объявления причины заранее. Native auxiliary foreign-water import отдельного последующего commit не входил в этот frozen runtime и не мог вызвать этот первый failure.
