# Нативная акварель WebGPU: границы переноса

Рабочий перенос текущей модели, а не float-PoC с другой физикой. Производственный WebGL остаётся самостоятельным маршрутом. Экспериментальный маршрут должен явно сообщать об отсутствии WebGPU или неподдержанной стадии.

## Уже перенесено

- CPU-фильтр исходных дабов, индексирование записанного wet и доставка воды/пигмента: исходные формулы и состояние жеста выделены без GPU-зависимостей.
- Геометрия канонических полос — прежние 11 float на вершину; отдельные отпечатки и концы — прежний nib SDF.
- Канонический композит с бумажной текстурой и оптическими коэффициентами; viewport отделён от разрешения полей.
- Water front, diffuse, field operations, carry, pigmentColor, cost-domain и resample: отдельные GPU-примитивы с сохранением промежуточных RGBA8-записей.
- Типизированная лента GPU-команд. Она сама не определяет физический порядок операций.

## Следующая необходимая граница

`WatercolorSettlePlan` определяет порядок, итерации, рабочий прямоугольник, масштабы, снимки исходных полей и момент возвращения в слой. Запуск произвольного набора новых шейдеров вместо этого порядка не равен текущей акварели.

Оставшиеся зависимости планировщика от WebGL:

1. Поля/пул/слои используют конкретный `AccumulationBuffer`: копирование, очистка и снимки должны стать контрактами владельца ресурсов.
2. Загрузка flow и чужой воды непосредственно создаёт WebGL-текстуры. Это отдельный контракт загрузки, включая LINEAR, порядок строк и исходные каналы.
3. Scratch сохраняет CPU-состояние и GPU-снимки одновременно. CPU-доставка уже отделена; владение GPU-снимками, отмена и возвращение в пул должны оставаться явными.
4. Normal Room ожидает полный `PencilEngineAPI`, live previews, OperationLog, ACK, undo/rebuild и snapshot. Диагностическая страница отдельного шейдера не доказывает интеграцию комнаты.

Порядок следующей проверки: одинаковый подготовленный command tape → одинаковые входные/выходные поля → весь сухой слой → живой жест/перерисовка → undo/redo → несколько участников. Замер ускорения делается только после проверки одинаковой работы и изображения.

## Ограничения доказательств

Программный GPU подтвердил совпадение контрольного отпечатка и композита. Для полос есть расхождения округления растеризации/смешивания. Проверка field modes включает пока отдельные небольшие примеры; два первоначальных примера оказались без фактического перемещения и требуют усиленных входов. Ни одно из этих наблюдений не означает готовую комнату на WebGPU, художественную оценку или аппаратное ускорение всего движка.

## Состояние интеграции 08.10, ночная работа

Общий планировщик теперь использует типизированные Buffer/Uploads/Passes контракты. Производственный WebGL вызывает те же prepare/finish; нативный CanonicalPlanAdapter кодирует проходы, копии и уникальные staging uploads в прежнем порядке. Минимальный размер production-поля1536 и округление256 сохраняет CanonicalPlanFieldOwner. Компактный64/128 oracle — отдельная проверка, не замена разрешения движка.

Добавлены bounded single-tile CPU scratch metadata и finish owner: источник финального композита — inkDry/colorDry при наличии, иначе inkLoad/inkColor; inkSettled/colorSettled остаются записями основы для планировщика. Сухое отображение поверх бумаги повторяет PAPER_COMPOSE алгебру. Полная native Room API, мокрый display/reveal, concurrent input/ACK, multi-tile, undo/snapshot и hardware full-render parity ещё не реализованы/не доказаны.

На Samsung проверены реальные нативные ресурсные копии, порядок staging и два выхода brush: совпадают. Растровые поля остаются с небольшими аппаратными отличиями (до4уровней в coverage ribbon). Это отдельная незакрытая граница; отсутствие validation errors не равно byte-identical watercolor.
