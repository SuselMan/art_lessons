# WebGL1: проба новой модели материала local-field-v1

11.10.2026, задача #728 «Оптимизация акварели», ветка agents/728-webgl1-review.
База перед прототипом: 32566f50. Это отдельный DEV-лист, а не замена production-движка.
Открывается только на review frontend с VITE_QA_WATERCOLOR_REVIEW=1:
`/watercolor-local-v1`. Комнаты, старые рисунки и Operation Log не меняются.

## Принцип и ожидаемая экономия

Вместо цепочек front/field/settle используется поле 384×384 RGBA8: RGB — оптическая
масса трёх компонентов пигмента, A — вода. Симметричный целочисленный поток между
соседними ячейками переносит пигмент при наличии воды; вода испаряется независимо.
Отображение через exp(-mass) не меняет непрозрачность всего штриха при завершении.
Сухой пигмент неподвижен; добавление чистой воды вновь разрешает перенос.

На кадр обрабатываются максимум 32 отпечатка в ограниченных прямоугольниках,
один проход переноса по полю, один показ и при необходимости копия истории.
UP только ставит checkpoint в очередь. Здесь нет gl.finish, чтения GPU на UP,
цикла досчёта до сухого состояния или зависимости начала нового штриха от settle.
Это сокращает объём и глубину цепочки вычислений по конструкции, но численный
выигрыш относительно production на планшете пока не измерен.
Поле пока обрабатывается целиком: это НЕ доказанная оптимизация активных регионов.

Две рабочие текстуры и до 12 checkpoint занимают около 7.9 MiB, плюс canvas,
служебные ресурсы драйвера и небольшая очередь. Перенос не создаёт текстур на каждом шаге.
Пигмент при нанесении ограничен диапазоном RGBA8; насыщение новой краской может
терять добавляемую массу. Сохранение массы относится к переносу, а не к нанесению.

## Проверено

`gpu-smoke.json`: настоящий WebGL1 API в Chromium/SwiftShader, поле 16²,
24 шага без испарения и 160 с испарением. Суммы каждого RGB-канала до/после
совпадают, вода высыхает до нуля, материал перемещается. Undo очищает образец,
Redo возвращает точные байты. getError=0. UP-time — только CPU вызов end,
не физическая задержка пера или время исполнения GPU.

`ui-smoke.json`, `sample.png`: два перекрещивающихся штриха через события мыши,
отпускание, Undo/Redo, PNG export. Нет ошибок JS или GL. maxSubmissionMs —
CPU submission в программном рендерере; его нельзя выдавать за FPS планшета.
`verify.cjs` запускается через node при установленном playwright (или NODE_PATH
существующей совместимой установки); URL переопределяется WC_PROTOTYPE_URL.

## Ограничения и следующий шаг

Это гипотеза дешёвого материала, а не полноценная физика настоящей акварели.
Нет отдельного осаждения/адвекции/капиллярных потоков, версии комнатного лога,
согласования участников или replay записанной tape. Время высыхания привязано
к шагам rAF; скорость устройства влияет на развитие рисунка. Undo/Redo
замораживают восстановленный checkpoint до следующего нанесения; максимум 11
доступных переходов назад. После перезагрузки рисунок исчезает — нужен PNG export.

Первый критерий: Илья проверяет скорость пера, паузу на UP, мокрые пересечения,
чистую воду и внешний вид. Если отзывчивость стала лучше, дорабатываем художественное
поведение на этом одном стенде. Перед переносом в комнату обязательны фиксированное
время симуляции, детерминированный replay, версия материала и тесты истории/участников.
Нельзя подключать новый расчёт к старым логам без отдельного решения о совместимости.
