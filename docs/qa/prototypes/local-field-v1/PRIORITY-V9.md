# Проба приоритета пера v9

Запрос Ильи 11.10 16:22: совместить нормальную сушку полной модели с
отзывчивым нанесением кисти. Не продолжение отклонённой multiscale-v1.

URL прежнего листа с `?priority=1` включает DEV-only режим.
Поле coarse transport и экспериментальный gradient fibres отключены:
используется полный существующий settle. Native preview остаётся768px.
Новый признак reviewInputPriority разрешён только при watercolorReview в DEV.

Во время локального штриха паузятся канонический FIFO и асинхронные tick
settle. Ввод продолжает наноситься через отдельный WatercolorPresentationRaster.
После UP прежние запросы возобновляются, ни один не удаляется и не заменяется
другой физикой. Явный synchronous complete не изменён.

Ограничения: длительное непрерывное рисование задерживает расчёт канонического
материала и увеличивает очередь. Скорость самого preview пока не оптимизирована.
Возможен переход между предварительным и рассчитанным изображением.
Это проверка конкуренции за GPU, а не доказанный выигрыш задержки на телефоне.
В комнатах режим не включён, онлайн-протокол и replay не меняются.
Байтовая эквивалентность полного результата production в этом ходе не доказана.

40 unit tests FIFO/SettleQueue прошли, включая паузу на8 кадров и завершение
после UP с сохранением порядка. Browser: удержание18 FIFO requests на12 кадров подтверждено на SwiftShader256;
первый запуск не завершил канонический расчёт за30 секунд. Повторный запуск
с отдельным90s deadline завершил расчёт и кнопку Dry без GL/JS ошибок;
см. priority-v9-check.json. Этот результат не доказывает ускорение на устройстве.
Режим по умолчанию остаётся v8, priority включается только вручную query flag.
Новых процессов/зависимостей нет; собственный браузер закрывается в finally.
