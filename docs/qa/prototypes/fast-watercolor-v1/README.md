# Fast watercolor v1 — три художественные гипотезы

Изолированный стенд для выбора картинки Ильёй. Не изменение production/V8.
Exact parity не является целью. Сравнение с V8 не проведено; названия пигментов
обозначают упрощённую общую трёхполосную поглощающую оптику, не точные спектры.

## Общий контракт

112×112 поле материала, 448×448 вывод с билинейной реконструкцией и текстурой
бумаги. Seed 731, строго 100 шагов, условный dt=0.05 с. Wall-clock меняет только
скорость показа. Пигменты хранятся раздельно: жёлтый поглощает синий свет,
синий — красный, поэтому пересечение зелёное. Исходные сцены одинаковые:
два пересекающихся мазка; синяя точка внутри слабо-жёлтой мокрой лужи.
Размер зерна, геометрия кисти и яркость подобраны для сравнения, не взяты из V8.

## A. Капиллярный поток

Консервативный попарный обмен водой и подвижным пигментом по соседям.
Испарение быстрее около общего края воды; пигмент оседает в бумаге и на краю.
У мазков общая вода; отдельные сухие внутренние контуры намеренно не вводятся.
Стоит O(T N²), память O(N²). Плюс: перенос количества, а не blur RGB.
Минус: модель диффузионная, короткие пальцы/подтёки, не полноценная гидродинамика.
Грануляция и необратимое осаждение управляемы. Стабильность параметров пока
проверена только на двух предзаданных сценах.

## B. Пигментные частицы

22% исходного пигмента закреплено как подробное ядро; остальное — по четыре детерминированные частицы на активную клетку и цвет. Частицы двигаются
в бумажном шуме, слабом капиллярном поле и оседают в бумаге; на границе лужи
оседание усилено. Цветовые компоненты смешиваются лишь при реконструкции.
Стоит O(T P + T N²) с P = 3×количество активных цветовых клеток;
память O(P+N²). Это отдельный лагранжев подход без решения поля пигмента.
Минусы: фиксированное поле воды, возможны песчаность и статистически выглядящие
зернистые границы. Частицы не являются физическими крупицами пигмента в масштабе.
Распределение начальной массы ниже порога 0.015 отбрасывается.

## C. Каналы бумаги

Один раз строятся приблизительные расстояния от каждого исходного пигмента
по графу неоднородной бумаги (24 red/black sweep). Расширяющийся фронт и тёмная
кайма реконструируются прямо из расстояния и исходного цвета. Повторного
решения жидкости нет. Цена O(S N²) подготовки + O(T N²) простого вывода,
S=24. Плюс: наиболее дешёвый путь для анимации после подготовки; нерегулярные
фронты образует стоимость каналов. Минусы: НЕ сохраняет массу, не решает
взаимодействие воды, у каждого пигмента своё поле распространения. Поэтому
внутренние цветные каймы возможны — это кандидат на художественное отклонение,
а не доказанный общий физический мокрый контур. Расстояния приближённые,
не Dijkstra. Финальный радиус до 20.8 клетки для точки; менять его без расширения числа
подготовительных sweep нельзя без проверки.

## Измерения и доказательства

node-check.json: VPS Node20, один запуск, без браузера/вывода. Не Samsung,
не сравнение с V8, не коэффициент production-ускорения.

| Модель | Пересечение: подготовка / 100 шагов | Лужа: подготовка / 100 шагов |
|---|---:|---:|
| Капиллярная | 21.8 / 243.3 мс | 26.3 / 399.0 мс |
| Частицы | 25.7 / 478.8 мс | 7.7 / 382.1 мс |
| Каналы | 286.4 / 162.0 мс | 121.7 / 56.7 мс |

Checksum совпал для 100 шагов разом и 20 порций по 5 для всех шести случаев.
Это подтверждает независимость модели от разбиения шагов на этом CPU,
не переносимую побайтовую идентичность разных устройств. Счётчики браузерного
стенда отделяют расчёт от вывода; начальная подготовка доступна в metrics.initMs.

## API / следующий шаг

models.js: createModel(kind, scene, seed); step(n), render(canvas), checksum(),
mass(), initialMass, metrics, tick, done. kinds capillary/particles/channels,
scenes cross/dot. index.html: window.__fastWatercolor.advance(n), snapshot(),
reset(), models, canvases, destroy().

Сначала выбрать глазами полезные черты каждой модели на 0/30/100 шагов и в
анимации. Затем подключать именно native подробное нанесение кисти/оптику,
локальные области и стоимость реального input. Полная кисть, мокрые группы,
новый ввод во время расчёта, undo, комнаты, универсальная сушка, context loss
пока не интегрированы. Web Worker/GPU вычисления — отдельный следующий этап,
не обещанный эффект текущего CPU стенда. Красота и скорость на телефоне
требуют оценки Ильи; скриншоты сами этого не доказывают.

Новых зависимостей, сервисов и постоянных процессов нет.

## Доработка после первых картинок

Первая проба почти не переносила точку. Во второй увеличена длина переноса,
добавлен радиальный адвективный поток точки (A), направленные 7/13-канальные
пальцы с поздним оседанием (B), билинейное распределение частиц, 8-соседний
граф вместо ромба 4-соседей (C). Внутренний край C подавлен общей маской
воды. Это поправки художественных гипотез, не универсальные физические законы.
Количество в A сохранено до float64-погрешности; B теряет до1.1% слабого
жёлтого депозита из-за явного порога; C прибавляет 54.8% синего в сцене точки.
Последнее — существенный художественный риск, а не скрытая оптимизация.

## Итог визуальной проверки второй пробы

Browser сравнение сохранено в measurements.json и cross/dot-{0,30,100}.png.
Ошибок браузера 0; 6/6 повторов дали те же контрольные суммы. Это локальная
проверка браузера VPS, не tablet validation и не утверждение реалистичности.

A: перенос точки заметен, но образует четырёхлучевой крест — осевая анизотропия
четырёх соседей и разделённого направленного потока. Такой рисунок является
артефактом алгоритма, а не желательным акварельным эффектом. Следующий шаг:
симметричный 8-направленный поток с нормированными диагональными весами.
B: перенос и пальцы есть, но картинка сильно зернистая даже с bilinear splat.
Следующий шаг: распределение частиц адаптивным ядром в размере доли клетки,
больше частиц только у фронта и подробный закреплённый native депозит.
C: пальцы точки читаются лучше остальных текущих гипотез, но цена — изменение
количества и грубая реконструкция. Следующий шаг: нормировать итоговую массу
по каждому пигменту и оценить, сохранится ли полезная форма края.

Выбор между кандидатами остаётся за Ильёй. Ни один не объявлен красивее V8.
