# Как получается наше растекание: договор данных

Отдельная статическая QA-страница `flow/anatomy.html`. Существующее сравнение не меняется. Схема объясняет **родной final target**, а не независимые исследовательские модели.

## Основное объяснение

Первый экран объясняет расчёт семью крупными шагами, по умолчанию на примере двух смешивающихся цветов. У каждого шага есть результат и причина вычислительной работы; реальные промежуточные снимки раскрываются по запросу. Технические CPU-интервалы и проверочная обвязка скрыты в подробностях. Число проходов описывает объём работы, но не является долей GPU-времени.

## Два уровня

- «Как получается рисунок»: художественные этапы actual native kernel. Открытый блок показывает вход, действие, выход, действительную промежуточную картинку и ссылки на код.
- «Что добавляет QA-стенд»: подготовка, разбиение на компоненты, отдельные водные задачи, загрузки, объединение, чтение и наблюдение. Эти затраты не выдаются за стоимость художественного эффекта.

На телефоне цепочка вертикальная; кнопки не меньше 48 px. Выбранная деталь раскрывается под блоком; на широком экране находится рядом с цепочкой. Без автоматического движения и горизонтальной прокрутки. Для реальных пар картинок — ползунок и удержание исходного состояния; пальцевое прокручивание страницы сохраняется вне поверхности сравнения.

## Предложенный JSON v1

`schemaVersion`, `title`, `source:{model,revision,shaderSHA}`, `scenes`.

Сцена: `id`, `label`, `inputSHA`, `final` (изображение), `sameFinalTargetSHA`, `tracks`.

Уровень: `id:'native'|'qa'`, `label`, `stages`.

Этап: `id`, `label`, `inputText`, `actionText`, `outputText`, `sourceRefs`, необязательные `beforeImage`/`afterImage`, массив `timings`, `qualification`.

Изображение: `src`, `sha256`, `kind:'field'|'paint-preview'|'material-preview'`, `label`, необязательные `encoding`/`visualization`. Диагностическое поле всегда подписано отдельно от видимого рисунка. Использовать только существующие доказанные снимки; отсутствие — текст «Снимок не сохранён».

Время: `valueMs`, `clock:'cpu-host'|'gpu-timestamp'|'wall'`, `scope`, `seriesId`, необязательные `parentScopeId`/`additiveGroup`, `includes`, `excludes`, `observation`.

Отсутствие времени означает «Отдельно не измерено», не ноль. Сумма допустима только при одинаковых часах/серии, явной группе сложения и неперекрывающихся границах. GPU timestamp, CPU submit и wall не складываются. Время чтения промежуточных снимков и наблюдения показывается отдельно.

## Ограничения фактов

Прежние ~700 мс QA-стенда включают три полноразмерные задачи, в том числе две крошечные компоненты только с водой. Это не стоимость одного native solver. ~147 мс основной компоненты из отдельного повтора не заменяет медиану ~700 мс и не раскладывается между художественными эффектами по числу проходов.

`sameFinalTargetSHA` связывает захваченный final target с контрольным запуском без наблюдения. Диагностическая визуализация поля не является actual paint preview. Снимки и измерения загружаются из подготовленного доказательного пакета; браузер не выполняет модель и не запрашивает GPU.

## Сборка

`node docs/qa/prototypes/native-anatomy-805/build.cjs /путь/data.json /путь/flow/anatomy.html`

Картинки задаются относительно `data.json`. Сборщик проверяет SHA каждого снимка, создаёт hardlink рядом с HTML и встраивает JS. Он не проверяет физическую истинность измерений: эту часть обеспечивает доказательный пакет оператора.

Для `timings` добавлено `kind:'interval'|'cumulative'|'estimated-difference'` (по умолчанию `interval`). Для оценки разности обязательна `qualification`. UI не вычисляет и не суммирует времена автоматически. Нулевая длительность допустима только как настоящее измеренное значение, отсутствие массива означает неизвестность.

Проверка контракта: `node --test docs/qa/prototypes/native-anatomy-805/anatomy-model.test.cjs`.
