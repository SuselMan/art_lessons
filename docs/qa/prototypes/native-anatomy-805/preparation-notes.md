# Подготовка вокруг расчёта: точные границы

Это QA-изоляция независимых мокрых компонент, а не внутренние художественные эффекты модели.

1. **Снимок исходных семи карт.** Копируются P (загрузка/состояние материала), C (цвет/пигмент), coverage, solvent, foreign, original, paper. При 1024² каждая RGBA8-карта занимает 4 MiB: снимок — 28 MiB. Он защищает вход от дальнейшей перезаписи. Результат: неизменяемые CPU-массивы. Время `validate-and-copy-seven-planes`.
2. **Поиск связных водных областей.** Полный проход по 1 048 576 пикселям; мокрым считается solvent.a+foreign.a>0. Соседство по четырём сторонам, диагональ не соединяет. Очередь обходит каждую мокрую область. Результат: номер области для каждого пикселя, список её пикселей, размер, наличие ненулевых каналов C. Время `allocate-labels-and-find-four-connected-water`.
3. **Независимая проверка разбиения.** Ещё один проход по листу плюс по найденным пикселям: проверяются охват всех мокрых пикселей, отсутствие сухих в областях, размеры, отсутствие повторов. Это страховка эксперимента, не визуальный эффект. Результат: подтверждённая карта компонент. Время `independent-partition-validation`.
4. **База общего результата.** Загружается исходный общий C в GPU, копируется в аккумулятор объединения. Результат: фон, на который будут вклеены результаты компонент. Время `merge-base-upload-copy`; это время CPU-вызовов с возможным ожиданием драйвера, не чистое GPU-время.
5. **Материализация каждой области.** Создаётся маска 1 MiB и семь карт по 4 MiB. Original и paper копируются целиком, пять карт материала изначально нулевые; затем пиксели выбранной области переносятся в них. Результат: полноразмерный вход 1024², содержащий материал только этой компоненты. Времена allocation и scatter раздельно. Даже для 1 пикселя выделяются те же размеры; это свойство данного стенда.
6. **Создание отдельного native-источника.** Создаётся RibbonStrokeScratch, берутся GPU-буферы, загружаются P/C/coverage/original/solvent/foreign, сохраняются метаданные кисти/зерна/жеста. Paper берётся из заранее подготовленного ресурса комнаты. Результат: источник, который настоящий native solver воспринимает как обычный вход. `fork-source-allocate-upload`.
7. **Расчёт и вклейка.** Настоящие reset→step→dry, затем C компоненты переводится в общую шкалу и вклеивается строго через её исходную маску. Полноразмерные шейдеры не становятся маленькими от маленькой маски. В прежней метрике compute это всё вместе с зависимым чтением 1 пикселя, а не одна физическая стадия растекания.
8. **Освобождение источника.** Буферы возвращаются в pool, источник уничтожается. `fork-destroy`; драйвер может отложить фактическое освобождение.
9. **Чтение общего C.** Полные 4 MiB RGBA8 возвращаются в CPU. Хеширование после чтения исключено из основного замера. Это не чтение всех карт материала.

`preparationSlices` — непересекающиеся внешние интервалы. `preparationDetails` — вложенная детализация partition/materialize: их нельзя прибавлять поверх внешних интервалов. Ни один такой замер не называется чистым GPU-временем.
