# Пайплайн исходного мазка

Отдельный от растекания разбор настоящего живого watercolor Mini. Статическая страница использует реальные Samsung-замеры, показывает собственное CPU-время без двойного суммирования вложенных вызовов. Обычный CPU-прогон и контроль GPU с барьерами разделены. Чистое аппаратное время GPU недоступно: на Samsung отсутствует EXT_disjoint_timer_query. Это не оптимизированная кисть.

Источник: 94501296 плюс разбиение prepareDelivery из текущего коммита. Ввод: SM-T970, 1024, brush320, water95, pigment34, combomask, calculation=off,morph=off. Три перекрывающихся32-event волны, main иworker. Сборщик отклоняет пропущенный/непринятый мазок; счётчики solver обязаны быть0. Изображения сняты после трёх мазков вне измерения, а не внутри этапов.

Измеренная занятость CPU второго main-мазка526.7ms: sample60.0, drain169.9, deposit54.8, prepareDelivery7.6, остатокpaintDabs106.8, stamp25.9, bands44.7ms. Это суммы всего мазка, не latency кадра. Самое долгое движение26.5ms. Учёт воды~54% измеренной занятостиCPU; GPU-время пока неизвестно.

Упрощение нужно проверять двумя независимыми путями:
- Без художественных изменений: числовой учёт посещённых водных ячеек, повторные обходыCPU-поля и дублирование отображенияraw.
- С художественным сравнением: единая более простая геометрия вместо stamp+bands, упрощённая фактура/цвет исходного мазка. Сначала отделить их от подготовкиmaterial и измеритьGPU; нельзя обещать выигрыш по общему остаткуpaintDabs.

Сборка: `node build.cjs input-report.json output-directory`. Вход иPNG лежат в приватных компактных результатах `project-services/gl1-review/live-brush-805-20261019`. Runtime manifest сохранён вместе с ними. Страница опубликована в существующей галерее, связана с единым хабомGrafetto; нового сервера нет.

`verify.cjs URL output-dir` проверяет320/390/1440, все6комбинаций и12раскрытий, изображения, отсутствиеJS-ошибок/overflow. Временные сборки и собственные вкладки/forward удалены. Исторический raw-only A2 toggle timeout остаётся незакрытой проверкой.

## Контроль GPU

Применяется только по скрытому QA-параметру gpuProfile=sync. Инструмент оборачивает drawArrays/drawElements, копии, clear, texImage/subImage и generateMipmap. До каждой команды gl.finish отсекает предыдущую очередь; после команды второйgl.finish измеряет ожиданиеGPU/драйвера. Эти барьеры сами имеют стоимость. КолонкаGPU показывает completionWaitMs, не чистое время шейдера. beforeWaitMs и submitMs раскрываются отдельно. CPU-столбец контрольного прогона уже включает эти ожидания — складывать столбцы нельзя. Привязка к самой глубокой семантической CPU-обёртке, без вложенныхGPU-запросов/двойного счёта.

Samsung1024контроль6прогонов, solver0. Второйmain:686.3msCPUсбарьерами,45.7msожиданиепосле,64.0msпредварительныебарьеры,10.5msотправка. Второйworker:698.5/47.2/85.3/8.7msсоответственно. Все цифры — за весьмазок. Картыматериала12.3ms,отпечатки10.6,полосы10.7ожиданияпосле(secondmain). Это отдельные входные жесты с той же геометрией и настройками; их времена/эволюция воды не заморожены и побайтное равенство с обычным прогоном не заявляется. Обычныйпрогон остаётся прежним, не заменёнконтрольным.
