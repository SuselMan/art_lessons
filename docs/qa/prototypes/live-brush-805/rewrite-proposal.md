# Перепроектирование исходного мазка — обсуждение 19.10.2026

Статус: предложение, реализации новой кисти нет. Решение Ильи22:37 заменяет прежний план из двух отдельных оптимизаций: перестроить исходный мазок на базе имеющегося движка. Растекание обсуждается и меняется отдельно после исходного следа.

## Зафиксированный объём

- Одна карта воды наGPU. Отказ от впитывания воды кистью и параллельного CPU-поля PaperWetness для новой модели. Простое добавление с насыщением; перенос/раздвигание воды не входит в первый вариант.
- Сохранить прежние правила отдачи пигмента, кроме зависимости от влажности бумаги. Сохранить влияние воды самой кисти, расход по длине, касание, задержку, замедление/поворот. Перед переносом перечислить все paper-wet множители в этих правилах, а не удалить только watercolorWetPull.
- Изменить художественную структуру исходного следа: направление движения должно управлять следами щетины; текущая крупная пятнистость не устраивает.
- Сохранить лог действий/replay/undo/online, детерминированное исходное состояние и совместимость входов для нынешнего растекания. Новая модель должна версионироваться: старые операции не перерисовывать новым алгоритмом.

## Что показывает сравнение исходников маркера и акварели

Оба используют buildRibbonBands/nibGeometry из markerRibbon.ts, один RibbonStrokePainter и общий Raster RibbonPasses. Маркер не использует normalizeDeposit, waterDepletion, cloud/granulation/bristleInk. Акварель имеет coverage, собственныйsolvent, pigment mass иcolour, независимые фильмы/базы и обновления карт. Вакварельном diagnosticBandBatch варианты ink/wet/solvent строятся общим пакетным вызовом, но это не один набор параметров для всех карт и не одинdraw. Дополнительно CPU-поле влажности и сложные правила подачи. Поэтому общая лента сама по себе не объясняет замедление. Свежий marker-vs-watercolor benchmark не проведён: это вывод о структуре кода, не измеренный коэффициент.

Крупная пятнистость: shaders.ts wcCloud/wcSettling/wcFilmBlot получают mottleWp=gl_FragCoord.xy+u_worldOrigin. Поэтому основной рисунок пятен привязан кхолсту. Отдельный hair-field использует across, поэтому неверно говорить, что весь нынешний материал не имеет направления.

## Предложение для прототипа

1. Общая геометрия следа от существующего swept-nib построителя: исходно сохранить наконечник, интерполяцию нажима/наклона,стыки иконцы. Не обещать заранее толькооднулентубезотпечатков: на разворотах/касаниях нужен корректныйконтур.
2. Вершины несут координаты s(длинапути) и v(поперёккисти), локальнуюширину/нажим, дозупигмента иводукисти. Геометрические позиции можно переиспользовать для карт. Порядок перекрытий и соединений требуетотдельнойпроверки.
3. На начало мазка фиксировать воспроизводимый профиль отдачи поперёккисти: широкие/узкие группы щетинок. Seed записанилидетерминированновыведенизоперации. Профильпродолжаетсявдольs, медленноменяется, анеперегенерируетсякаждыйдаб. Просто вращаемаякартинкакаждогоотпечаткаможетсновасоздатьповторыишвы.
4. Нормировать поперечный профиль, чтобы он перераспределял заданную дозу, анепроизвольно менял её. Касание/остановки/поворотыуправляютдозойпопрежнимправилам, независимымотpaperWet.
5. ОдинGPU-water field + необходимыеpigmentmass/colour maps. «Однакартаводы» неозначает «однатекстуранавообще всё». Использовать стабильную stroke-local нормировку, чтобы overlap собственныхсегментовнесоздавалтёмныешвы/лишнююводу.
6. Видимыйживойслед—простойкомпозитпигментаплюснеяркаяиндикацияводы. Ореолы/растекание/крупныемокрыепятнанеподменятьзаранеетяжёлойпроцедуройвнанесении;каждыйэффектпроверятьотдельно. Фактурабумагиможетоставатьсявworld-coordinates:этодругаяфактура,нещетина.
