# Native watercolor front comparison

Три режима одной native цепочки: baseline unit relaxations, prefix4, prefix8.
Кисть, депозиты, пигментная оптика, ремобилизация, градиентный перенос и
inward/rim остаются native. В V8/production новый schedule не включается.
Алгоритм и оговорки подробно в [FAST-FRONT.md](FAST-FRONT.md).

fast-front.js ставит временный monkeypatch только waterFrontStep. Outward
schedule устанавливает DEV callback в плане, который root подключает на стенде.
При шаге4/8 строится кэш суммы native направленных рёбер (16бит/направление).
Четыре парные RGBA8 текстуры и один reusable scratch: дополнительно45MiB
при1536². Подготовка16draw для8 или12для4 входит в стоимость варианта.
Кэш сбрасывается на первомunitpass; последние8unitpass native. Inwardflat/
reliefpasses и все downstreamоператоры native без замены.

Сумма учитывает per-cell floor/climb/feather, покрытие и чужую мокрую плёнку,
а не только разность высот концов. Prefix cost округляется вверх, DITHER
выключается только на packedcache draw с последующим восстановлением.
Граница поля — непроходимая. Ключ кэша включает uniforms/textureidentity;
содержимое coverage/foreign обязано быть неизменным в пределах одного фронта.

Риски: прямые macrosegments могут пропустить частые повороты между долинами;
8finepass исправляют лишь локальный остаток. ИтоговаяC.r остаётсяnativeRGBA8,
поэтому аналитическая upper-bound гарантия точной арифметики после этой записи
нестрогая. Возможны изменение длины пальцев, цвета и наружного/внутреннего
контура. Ровно это должен проверять Илья; никакого заявления «не хуже V8»
до оценки картинки нет.

## Что означает время стенда

Показываемое время от начала нанесения до fence (`gl.finish`) — полное wall time
этого браузера, включая CPU, кодирование/доставку команд, GPUqueuewaiting,
подготовкукэша и downstream. Это НЕ GPUtimestamp, не isolated shaderbenchmark,
не pen-to-pixel и не время Samsung. Сравнение имеет смысл только для одного
фиксированного input/paper/wetprofile/domain на той же машине.

Счётчики stats: cacheBuilds/buildDraws/jumpDraws/nativeDraws/extraBytes.
Коэффициент из числаdraw не равен ускорению полного settle. Сначала надо
дождаться законченного browsercomparison, подтвердить ошибкуGL=0 и оценить
картинки. Undo/комнаты/контекст loss и работа под реальным пером не проверены.

Никаких новых зависимостей или сервисов; dispose восстанавливает исходный
waterFrontStep и удаляет own programs/buffers. Root закрывает QA браузер.

## Повтор капли и пределы измерения

Повтор в отдельном Chromium: V8 12.59 с, prefix4 2.103 с, prefix8 2.019 с.
Первый прогон: 9.08 / 2.010 / 1.914 с. Это два прогона одной небольшой сцены
после создания движка, загрузки бумаги и создания shader programs; этот
подготовительный этап не входил в старые измерения. Полное время запуска
нового браузера оказалось значительно больше измеряемой части; источник
задержки подготовки отдельно не локализован. Теперь UI показывает initMs
отдельно. Нельзя утверждать ускорение полного открытия страницы по этим данным.

В измеренной части пробы капли выигрыш устойчив; речь о SwiftShader и данных
этой сцены. Под аппаратным GPU и большим числом мокрых мазков результат может
быть другим. До человеческой оценки сравнения статус — кандидат, не замена V8.
