# #775: отклонение оптимистических операций и восстановление истории

Baseline: confirmed Pencil → Undo → server reject → unrelated older backfill.
Подтверждённый штрих исчезал из done history, actual pixels стирались,
независимый full replay возвращал пустой слой. Отдельно проверен отказ Redo
на импортированном undone-состоянии без исходной Undo в доступном окне:
простой пропуск rejected-контроля ошибочно возвращал пигмент.

Исправление остаётся внутри движка. `goneReason: reject` отличает локальный
отказ от законного revoke. Rejected-события сохраняют ID и позицию, но не
исполняются и не создают ветвление. При отказе журнал сворачивается заново,
что исправляет также Undo с новым действием до ответа и отвергнутую Revoke.

`controlBefore` фиксируется при append pending-контроля, до apply: только ID,
state и goneReason участников его жеста. Ни bitmap, ни копии операций/журнала
не сохраняются. Для нового pending-действия `branchBefore` сохраняет только фактически
изменённые undone-записи в уже существующем цикле сброса redo; отказ
такого действия возвращает импортированную redo-ветку даже без старой Undo.
Явные известные controls имеют приоритет над этим branch basis при переупорядочении.
Эти неизменяемые скаляры ограничены затронутым жестом или удалённой redo-веткой;
prefix-копии используют те же записи. Протокол и shared-schema не меняются.
Только первый известный контроль может задать исходное resolved-состояние;
более ранний оригинальный контроль имеет приоритет над поздним local basis.

История с авторитетным serverSeq для того же ID и поздний ACK могут отменить
локальный reject. Engine получает изменившиеся состояния и пересобирает их;
обычный ACK не запускает дополнительный refold. Законный gone/revoke для
принятой Undo продолжает действовать, а отказ одного chunk не удаляет
подтверждённого соседа. Historical prefix учитывает тот же initial-state proof. Water-only replay
пропускает rejected-контроли и сохраняет прежний resolved-state fallback
для частичного legacy-окна; новое предположение о времени неизвестной Undo
не вводится. Исследование и проверки — MockGL/CPU, не аппаратный
сертификат. При server reject выполняется O(n) refold; обычный ввод не меняет
художественный solver и не получает нового синхронного GPU solve.

Поздний ACK rejected-control инвалидирует также его прямую цель, даже если
более поздний контроль маскирует разницу raw state: иначе меняется effective
water eligibility, но остаётся старый material-domain. Отдельный тест сравнивает
CPU scratch buffers и storageBounds с независимым accepted-history replay.

Авторитетная страница с тем же ID проходит такую же material-инвалидацию,
как поздний ACK. Rejected pending-controls не считаются неизвестной будущей
мутацией при проверке уже покрытой исторической операции: иначе частичный
snapshot-prefix без seq1/2 ошибочно остаётся в quarantine навсегда.
При material journal-rehydration локальные scalar basis передаются readonly
ссылками вместе с state/reason. Обычные неизвестные/новые accepted-controls
по-прежнему вызывают fail-closed repair.
