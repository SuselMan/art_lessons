# #744: CPU-задержка Undo акварели

Измерен resolver журнала, без WebGL и без GPU-пересборки слоя. Исходный helper:
`2bcc8b37`; fixture: 100/800 мазков по 24 dabs, два автора, 30 поочерёдных undo.
Связный участок и независимые участки измерены отдельно. Node 20.20.2 на VPS.
Запуск из worktree: `node --import tsx docs/qa/harness/744-undo-cpu-profile.mjs <label>`.
Компактные исходные измерения: `temp/wc-runs/undo-cpu-profile-20261017/`.
Baseline снимался с CPU sampling, итог без sampling; показатели зависят от JIT/GC.

| Fixture | Median повторного undo: было → стало | P95: было → стало | Холодный пересчёт 30 undo: было → стало |
|---|---:|---:|---:|
| 100, связный | 3.69 → 1.60 мс | 9.21 → 3.51 мс | 69.9 → 49.7 мс |
| 100, независимые | 5.83 → 0.81 мс | 8.06 → 4.45 мс | 100.5 → 25.3 мс |
| 800, связный | 41.16 → 16.87 мс | 48.50 → 24.64 мс | 841.4 → 470.8 мс |
| 800, независимые | 227.35 → 9.34 мс | 279.72 → 13.20 мс | 5315.2 → 276.4 мс |

Первый undo на 800 мазках: 64.3 → 55.9 мс в связном случае и 294.3 → 49.2 мс
в независимом. Сто повторных чтений неизменённого журнала занимают около 7–8 мс
суммарно: кеш revision продолжает работать. Холодный пересчёт означает новый
хронологический кеш; геометрия оригинальных операций уже могла быть прогрета.

Причина: resolver просматривал все активные компоненты для каждого мазка,
переупаковывал Set их корней и повторно вычислял одну геометрию до трёх раз
на управляющее действие. CPU profile: около 10.2 с в resolveGeometry против
примерно 1 с сборки мусора на совокупном baseline.

Изменения: консервативный пространственный индекс AABB с точной последующей
проверкой прежних капсул, ленивый обход кандидатов, ранний выход после касания
всех активных компонент, union-by-size без копирования геометрии компоненты,
повторное использование результата наблюдающего fold. Декодированные неизменные
свойства операции и геометрия кешируются через WeakMap. Огромные области и
координаты за пределами безопасного шага сетки используют полный обход.

Семантика проверена 2700 сравнениями с исходным resolver на воспроизводимых
историях undo/redo/сушки и разных инструментов. Все результаты совпали.
126 тестов oplog прошли; пять новых проверяют отсутствие пропущенных контактов,
касания на границе ячеек, огромные области/координаты и независимость экземпляров.
GPU-пересборка здесь не ускорена: общую задержку undo нужно измерять отдельно
на настоящем устройстве. Дельты heap в JSON без принудительного GC шумные и не
являются доказательством отсутствия утечки.
