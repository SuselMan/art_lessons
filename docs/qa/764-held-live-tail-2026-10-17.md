# #764: хвост удерживаемого мазка не отправляется после остановки пера

Регрессионный тест проходит через настоящий pointer pipeline. DOWN отправляет
первый пакет; два MOVE за следующие 10 мс накапливают уже нарисованные dabs.
После 100 мс ожидания жест остаётся открытым, но второй пакет не отправляется:
ожидалось 2, получен 1. Остальные 14 peer-live тестов проходят.

Причина: live-интервал равен 60 мс, а проверка срока вызывается только при новом
нарисованном dab. Отложенного flush нет. Каноническая операция не теряется:
хвост приходит при следующем движении или UP. Аппаратный held-tail probe
проводится отдельно; этот документ пока не объявляет его результат.

План исправления: один отложенный flush на жест, без дополнительных операций,
с очисткой таймера при завершении, отмене, потере контекста и destroy.


Аппаратный baseline подтвердился: после 4687 мс паузы автор всё ещё держит перо,
12 dabs стоят в очереди. В дальнем участке следа у автора изменено 426 каналов
(max 100), у каждого из двух наблюдателей — 0. Это отдельный дефект, не ошибка
выбора ROI у первой точки мазка.

Исправление: один таймер на ближайшую границу live-интервала, без новых
операций и без финальной отправки при UP. Первый пакет не ждёт интервала.
Таймер очищается при UP, отмене async-жеста, context loss, destroy и новом DOWN.
Проверки после исправления: 39 тестов в четырёх файлах PASS, включая отсутствие
устаревших пакетов после UP/destroy/context loss; web TypeScript PASS, scoped
oxlint без ошибок. Аппаратный повтор нового исходника запланирован отдельно.
