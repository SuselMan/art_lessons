# Полная замена снимка и сохранение живого мазка

Пачка функционального трека #825: #769 (пустые/разреженные снимки),
#774 (начало удерживаемого мазка), необходимая зависимость #788
(устаревшее восстановление после нового).
База: `1483e4fcb1329ccc425a6e87fb491c3ffd55e4ce`.
Рабочая ветка: `agents/769-snapshot-handover`, runtime и регрессии: `a5022dfee`.

## Поведение

- Снимок заменяет весь слой, включая отсутствующие в разреженном payload тайлы.
  Пустой снимок заменяет и прежний bitmap checkpoint; Undo не возвращает старую
  краску. Сохранён аудит явной прозрачной загрузки на ранее непустой слой.
- Pending local операции и подтверждённый хвост выше покрытия восстанавливаются
  поверх нового baseline. Доказательством покрытия служит serverSeq, а не
  локальный индекс. Записи без серверного порядка не рисуются поверх снимка
  наугад: существующий guarded history repair запрашивает точный префикс и
  запрещает публикацию до восстановления.
- Удерживаемый обычный жест откладывает установку bitmap до физического UP/END.
  Старые пиксели и FBO сохраняются во время жеста. Новые MOVE автора используют
  существующий RAF-путь; живые пакеты peer при ожидающем снимке также планируют
  кадр, даже при пакетном suspendDisplay Room. После handover unrecorded peer
  ink помечается unsettled и восстанавливается после durable операции.
- Promise установки завершается до перехода к распаковке следующего слоя.
  AbortSignal, новый ожидающий снимок, удаление слоя, resize, context loss и
  destroy освобождают tile views и отвергают старое завершение. Покрытие и
  installed audit возникают только при фактической установке.
- Один действующий restore generation привязан к экземпляру движка. Следующее
  восстановление синхронно отменяет предыдущее, балансирует replay gate и
  display depth; старые fetch/decode/preload/rebuild continuation не могут
  установить пиксели или объявить старую комнату готовой. Аудит старой попытки
  забирается до накопления аудита новой. Независимые движки не отменяют друг друга.

Адаптированы сохранённые локальные правки `df38c96e1`, `ec218f986`,
`d91d02ac0`, `58f7e98ef`, `d70e9260d`; соседняя экспериментальная акварель не
переносилась. Контракты сервера, формат снимков и шейдеры не менялись.

## Доказательство до/после

- На исходной базе: 5 FAIL / 2 PASS в двух файлах engine-регрессий пустого
  снимка и held Pencil.
- Исходный reentrant-сценарий с настоящим gzip и engine API: установки `[20,10]`,
  финальный red=41 вместо ожидаемых 202, latestKnownSeq=20 и ни одной ошибки.
  С исправлением устанавливается только seq=20; старый результат не меняет
  пиксели, ready/failure, gate или display depth. Проверяются также старый
  success после нового failure, destroy и отмена исторического preload.
- Три браузерные регрессии до исправления: 3 FAIL (107.4 с); после: **3 PASS
  (134.3 с)**. Разреженный снимок проверяется на реально нарисованных двух
  тайлах; пустой baseline остаётся пустым и после следующего штриха/Undo.
- Оба held-сценария проходят через public restoreRoomState + restoreLatestSnapshot,
  реальную gzip/decode и живой engine в настоящей комнате. Подменяются только
  HTTP-данные fixture и callbacks уведомлений. Фиксируются deferred=true,
  display depth=1 и незавершённый restore до UP.
- Для автора и peer ранний ROI framebuffer сохраняется побайтно, новые MOVE
  меняют более 20 каналов дальнего ROI до UP. Чтение gl.readPixels не вызывает
  принудительный display/export. После UP все декодированные RGBA-байты тайлов
  и их геометрия совпадают с независимым full replay (SHA-256). Page errors=0.
- Браузер: Playwright Chromium, явно выбран SwiftShader на VPS. Физические
  устройства, особенности пера и межвендорная GPU-детерминированность этим
  прогоном не проверены; алгоритмы GPU в этой пачке не менялись.
- Блок Room и смежные engine-проверки: **739 PASS / 71 файл**, 96.51 с.
  Включена реальная распаковка двух слоёв: пока первый held, счётчик=1;
  отмена освобождает views, новый generation распаковывает первый, затем после
  UP второй. Старый второй слой не распаковывается.
- Дополнительно воспроизведена гонка поэтапного checkpoint: первая порция
  сохраняется до снимка, следующая — после него и добавляет устаревший checkpoint.
  Его baseline меняется при установке нового snapshot, поэтому такой шаг теперь
  отменяется. Проверены отсутствие старого checkpoint и пустые пиксели после Undo.
- Четыре прежних fixture, подразумевавших подтверждённые операции, уточнены
  реальными server seq; без них правильный guarded repair блокировал публикацию
  и последующие операции. Их исходные проверки сохранены. Отдельная регрессия
  сохраняет неизвестный порядок и проверяет запрос истории/отказ публикации.
- Unit-тесты дополнительно проверяют marker/smudge FBO, отмену peer, отсутствие
  преждевременных coverage/audit, latest pending replacement и защиту публикации.

## Воспроизведение

При совместимых зависимостях, собранном shared, актуальном изолированном Prisma
client и baked paper:

```sh
npx vitest run apps/web/src/engine apps/web/src/lib/layers --maxWorkers=1
npx vitest run apps/web/src/pages/Room --maxWorkers=1
npm run typecheck
npm run lint:fix
npm run map:check
npm run map:rules
E2E_GL=swiftshader E2E_PORT_OFFSET=769 npx playwright test e2e/specs/snapshotHandover.spec.ts
```

Изолированный стек: API 5260, frontend 6260, Postgres 56260. Production и
базы разработки не использовались. Компактные журналы — в игнорируемом
`temp/snapshot-handover`. Поставка в main в эту локальную проверку не входит;
issue остаются открытыми до слияния и проверки поставки.

## Итоговая проверка и уборка

Полный набор движка на окончательном runtime: **1995 PASS + 1 timeout / 171 файл**
(1996 тестов), 419.38 с. Неизменённый WatercolorSettlePlan.test.ts превысил
стандартные 5 с в half-mixed allocation case (6.046 с) при одновременном QA;
в первом общем прогоне этот файл прошёл. Отдельный повтор всего файла:
**93/93 PASS**, 24.93 с, с прежним timeout. Лимиты тестов не повышались.
Первый общий прогон до уточнения server-seq fixture: 1990 PASS / 4 FAIL;
все четыре исправленных fixture и новая checkpoint-регрессия затем прошли
(27/27), а повторный общий прогон не обнаружил их ошибок.

Полный typecheck (server/web/shared/e2e/scripts), lint:fix, map:check и
map:rules прошли. У линтера остаются прежние предупреждения, у map:rules —
5 предупреждений о старых orphan-файлах, 0 ошибок.

Дополнительный браузерный прогон на финальном runtime со строгим контролем
консоли: оба held-сценария PASS. У sparse-сценария все пиксельные проверки
прошли, но консоль зафиксировала штатный HTTP429 на /thumbnail при частых
заменах (сервер ограничивает загрузки интервалом 3 с). Только этот конкретный
ответ записывается отдельной test annotation; JS/GL/остальные HTTP errors
остаются фатальными. Повтор sparse-сценария с таким контролем: **PASS**, 68.4 с.

Все собственные браузеры/API/frontend остановлены; одноразовые контейнеры
и anonymous volumes удалены. Временные dependency views, изолированный
Prisma runtime и generated shared build убраны. Расходные trace/video удалены
через зарегистрированный QA lifecycle; сохранены компактные журналы и три
снимка исходных дефектов. Исходный worktree и коммиты сохранены.
Main/push/production deploy этой пачки не выполнялись.
