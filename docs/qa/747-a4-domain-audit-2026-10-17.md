# #747: A4 и infinite остаются открытым продуктовым блокером

READONLY-аудит на интеграции после single-rect. Успешный один tile<=1024
не означает workingA41240×1754 или infinite. Guard пока нужен; снимать его
без нового material-domain contract нельзя. Никакого runtime/понижения
resolution/разрыва воды по tile-границам в этом аудите не сделано.

## Конкретный A4 путь и жёсткие предположения

A41240×1754 у `_tileSize` получает1024×1024 cells и четыре resident page tiles.
Источник M70 сейчас привязан к **одному реальному layer tile**:

- controller.accept требует allResident.length===1, origin0, размеры host;
- Layer хранит один tile, scratch ключуется AccumulationBuffer identity;
- present/close/frame копируют целую presentation/goal обратно в tile.buffer;
- canonicalTiles возвращает единственный goal tile;
- awaken требует snapshot.tiles.length===1 и восстанавливает scratch через
  реальный target.resolveForPaint, а не произвольный virtual material buffer;
- NativeTarget.resetFromScratch принимает один tile и ctx, prepare([tile]),
  fullbounds; engine.host.render/changed также захватывают один pagebounds.

Можно собрать actualtiles в единый virtual1240×1754 материал без шва и потом
scatter display/goal обратно. Но painter должен писать в **тотже virtual
scratch-domain**, а не продолжать создавать четыре realtile scratch entries.
Нужен adapter между logical target (layer identity/history) и working target
(virtual tile). Его должны одинаково использовать live/replay/eraser/Dry,
canonical structural copy, snapshots/CPU park/rehydrate и context recovery.
Одноразовый gather после stroke недостаточен: он может собрать декоративные
pixels вместо rawP/C/water и потерять последующие смешивания.

Есть ещё независимый solver hardlimit: NativeTarget передаёт radius40.
Native halfres threshold48, поэтому1240×1754 работает S=1. SettlePlan CAP=
1536*S срезает длинную ось к центру:1754→1536, по109px сверху/снизу.
Просто разрешить большой virtualbuffer оставляет часть мокрой physics вне
расчёта. Менять radius40→48 или S=2 ради прохождения нельзя: это art/modelchange.
Увеличение CAP требует профиля памяти/времени и явного обещания полной области.

## Память: один A4 источник не равен десяти текстурам

ОднаRGBA8 A4 текстура:8,699,840bytes =8.30MiB (8.70MB), не8.7MiB.
Ниже расчёт по allocations, **не аппаратно измеренный пик**:

| Часть | Полноразмерные поля | A4MiB |
| --- | ---: | ---: |
| Raw source minimal original/coverage/P/C/solvent |5|41.5|
| Возможные resting snapshot fields (SPILL список, nullable) |до10|до83.0|
| Controller raw/next/goal |3|24.9|
| Presentation current/next/target/wet/anchor |5|41.5|
| Shared native outP/outC/coverage/contour +backgroundfull +dryCoverage |6|49.8|
| Solver clone original/coverage/P/C/settledP/settledC/solvent |около7|58.1|

SettleField имеет10RGBA8 textures. Для несрезанного поля1280×1792 после256
rounding это ещё87.5MiB; текущий срезанный1280×1536 —75MiB. Low256 background
и contrast/flow дополнительно около2MiB, не весь solver. Minimal source5+
controller3+presentation5+native6+clone7+несрезанный field дают **около303MiB**
уже до actuallayer tiles, мипов, canvas/front/preview, дополнительных inputs,
clone/pool overlap и GL bookkeeping. Это сценарий, а не доказанный нижний пик:
не все временные fields обязаны одновременно жить, но гарантии их безопасного
lifetime reuse сейчас нет. Active film может добавлять ещё несколько A4 полей.

Samsung policy300MiB не покрывается честно одним снятием guard. Shared native
solver и поля считаются один раз, но каждый второй resident source повторяет
свои raw/controller/presentation. Нужны measuredpeak+byte-aware residency,
возможно один большой GPU source с CPU park остальных; это кеш, не autoDry.
CPU budget64MiB тоже не удержит все10A4fields одного источника: journalfallback
должен остаться корректным и не зависать при реальном крае eviction.

## Два настоящих направления

| Направление | Что может дать | Что ещё обязательно |
| --- | --- | --- |
| Whole A4 virtual canonical domain | Одно решение physics без tileшвов, близко нынешнему wholepage моделированию | logical/working adapter, полный extent вместоCAPсреза, lifetime/alias/ROI-memory оптимизация без смены математики, byte-budget residency, gather/scatter rawmaterial; measuredSamsungpeak+latency |
| Tiled canonical ROI с halo | Ограниченный GPU рабочий набор и путь к infinite | world-anchored grids/noise, полный dependencyreach каждого pass, phase-consistent halo exchange, boundarywater/P/C transport и tide, global component-area merge, deterministic scheduling/quantization и реставрация |

У tiled варианта нельзя просто сушить каждый tile отдельно. Stencilфазы должны
читать соседей одной и тойже версии; вода и pigment пересекают границу, третья
линия может объединить два мокрых домена. Halo должен покрыть все этапы,
а не только WET_DIFFUSE_REACH: ContrastPhase использует48px background taps
и глобальную connectedcomponent area, BackgroundMix — coarse-grid diffusion
и spatial flow; контур/transport имеют собственный reach. Component labels
на границах надо объединять до area threshold. Порядок UNORM rounding также
часть target, нельзя произвольно менять последовательность фаз.

Для infinite один whole ROI может расти без границы, особенно при объединении
луж bridgingstroke. Простая обрезка активного viewport теряет материал за ним.
Перестройка ROI не должна менять samplinggrid/шум: нынешний BackgroundMix
flow(uv*worldSize) ориентирован на pageorigin0, сдвинутомуROI нужен явный world
origin. Разделять независимые puddle ROIs можно только после доказательства
непересечения зависимостей **всего** алгоритма, не по видимому bbox пигмента.

## Что действительно потребуется для working A4

1. Выбрать material-domain contract, оставив stored layer tiles отдельной
   cache/display единицей. Это архитектурное решение, ещё не принято.
2. Доказать тотже wholepage physics на обеих сторонах внутренних1024границ,
   включая purewater, bridge, erase drybase, Dryundo, duplicate/merge,
   park/evict/rejoin/contextloss. Без молчаливогоCAPcut/downscale/autodry.
3. На Samsung измерить allocationpeak и latency под300MiB в худшем accepted
   source, concurrentauthor и historyrebuild. Reject должен быть atomic.
4. Сохранить square/rect<=1024 exact baseline, versioned material semantics и
   отдельно решить #748crossGPUcanonical. Его ошибка не исчезнет от tiling.

Ночью архитектуру не проталкиваем незаметно. #747 остаётся OPEN для обычной
A4/infinite комнаты, даже после успешного single-rect и manylayer residency.
Собственных runtime/GPUcontext/fixture ресурсов этим аудитом не создавалось.
