# Следующий GL1 эксперимент: убрать слив предыдущего solver при втором UP

11.10.2026, #728 — оптимизация и проверка акварели. Илья проверил e0ebb102:
ощутимого улучшения нет, особенно заметен тормоз в конце штриха.

В режиме joinedTouch предыдущий solver допускается под следующий совместимый
мазок, но без joinedFinishDeferred его остаток синхронно завершается на UP.
DEV watercolorReview теперь включает уже существующий guarded deferred finish:
следующий finish получает захваченные параметры и владельца scratch, ждёт
естественного завершения старого job, затем запускается в прежнем порядке.
Новые вычисления/публикация не выполняются раньше предшественника. Пакет
оптимизаций первой версии сохранён, baseline и production default не изменены.

Это ограниченный эксперимент: совместимые мазки одного открытого wash/слоя,
обычно одного цвета. Один held successor; третье раннее DOWN, другой цвет,
Dry и некоторые явные запросы по-прежнему могут требовать синхронного drain.
Первый UP и отдельные GPU-операторы также могут тормозить. Полный FIFO/asyncFinish,
новая физика и предварительная публикация не включены.

## Что проверено

96 тестов в пяти наборах PASS: queue, joined touch, deferred finish, async
regressions, DEV/production opt-in guard. Дополнительно добавлена проверка
Undo/Redo во время held finish: порядок журнала, recovery и освобождение владельца.
Повторный запуск deferred finish + DEV guard:14tests PASS. Web typecheck PASS.
Web lint PASS, только прежние предупреждения. Свежий HTTPS smoke на /create без воспроизведения рисунков
Ильи: secureContext=true, review/deferred false в baseline и true в кандидате,
GLerror0, contextLost=false, pageerror нет. Это свежие маленькие отдельные engine,
а не полная аппаратная проверка существующих комнат.

Диагностика direct pointer pipeline, Chromium SwiftShader, Fine64²/кисть8:
OFF: второй UP39.8ms, _completeSettle21.8ms внутри него.
ON: второй UP15.2ms, _finishRibbonStroke1.1ms, held=true; drain внутри UP отсутствует.
Это одиночные CPU wall-clock наблюдения с разной нагрузкой, НЕ процент ускорения,
НЕ pen-to-photon и НЕ прогноз для планшета. Первый UP в ON50.7ms: проблема
полностью не устранена. Артефакт diagnostic.json содержит исходные trace и условия.

Попытки финального GPU readback/Undo/Redo в программном рендерере были остановлены
из-за высокой стоимости; побайтное совпадение нового режима с baseline на реальном
GPU пока НЕ подтверждено. Предыдущий Samsung oracle подтверждал только первую
версию без deferred finish. Ручная проверка Ильи новой версии остаётся необходимой.

## Передача

Отдельно третий быстрый мазок и смена цвета — известные оставшиеся барьеры.
