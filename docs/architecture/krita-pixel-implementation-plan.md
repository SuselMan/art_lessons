# Полная поддержка Pixel Krita: этап реализации

## Принято 3 ноября 2026

Цель — поддержка механизмов Pixel Brush Engine выбранной версии Krita
`bd6e8d061d2f0388c5b10278786cf0fe62e3135f`, а не набор исключений по именам
пресетов. Другие движки и перенос в WASM сейчас не входят в работу.

Сначала пишется связная реализация. Приложение, GPU-стенды, устройства и тестовые
наборы на этом этапе не запускаются. После крупных законченных блоков допустима
проверка компиляции. Отдельный следующий этап — запуск и исправления,
функциональные проверки и измерения на устройствах. Наличие кода не означает
проверенную совместимость.

## Неизменные требования

- Штрих виден другим участникам до отпускания пера. Исполнение порционное,
  состояние мазка сохраняется между порциями.
- Сервер передаёт операции и проверяет допуск; пиксели рисует клиент.
- Записанные результаты вычисления параметров повторяются без повторного
  обращения к перу, часам или случайности наблюдателя.
- Координаты и фаза текстуры относятся к холсту, а не к отдельному тайлу.
- Память, очереди и рабочие области ограничены; границы тайлов не меняют мазок.
- Исторические форматы сохраняют своё значение. Новые возможности не выдаются
  старым клиентам через переинтерпретацию старой версии.

## Последовательность

1. Замкнуть текущий материал image + Multiply: исходная кисть, программа
   параметров, записанные кадры, общий исполнитель и online/history lifecycle.
2. По карте `krita-pixel-coverage.md` закрывать механизмы целиком: формы и
   трансформации, сенсоры и размещение, время, текстуры, цвет и композицию,
   составную кисть. Переиспользовать существующие вычислители и исполнители.
3. Подключить возможности к общему выбору кисти и политике чтения/рисования.
   Не считать механизм законченным, пока он остаётся только утилитой без вызовов.
4. Проверить компиляцию законченного блока, затем продолжить реализацию.
5. После реализации включить быстрый цикл запуска: один стенд, сбор ошибок,
   HMR для UI и перезагрузка с коротким повторяемым сценарием для кода движка.
   Последний пункт пока не реализован и не является действующим сервисом.

## Учёт результата

Для каждого механизма различаются: код отсутствует; код частичен; подключён
сквозной путь; компилируется; поведение проверено. Число файлов, коммитов и
успешных служебных проверок не заменяет этот учёт. Поддержка arbitrary presets
не выводится только из количества кистей исходного набора.
