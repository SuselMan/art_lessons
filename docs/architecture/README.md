# Карта архитектуры

`map.html` — одна самодостаточная страница: открывается двойным кликом, работает без сервера
и без интернета, весит ~250 КБ. Пять вкладок:

- **Структура** — квадраты модулей по слоям. Квадрат — это настоящая папка: первая строка —
  её путь, в скобках — два-три слова о том, что это (`pages/Room (экран комнаты)`). Клик
  открывает панель: за что модуль отвечает, из чего состоит, в какую папку-модуль он входит
  и какие подмодули у него есть, кто на него опирается и на кого опирается он, какие ADR и
  issues его объясняют, какие правила он нарушает и с чем у него совпадает код. У больших
  плоских папок там же — **группы карты** с пометкой «группировка карты, в коде её нет».
  Синие связи входят, оранжевые выходят, красные идут против порядка слоёв, пунктир — импорт
  только типов.
- **Исполнение** — что живёт, когда программа запущена (вкладка, движок, GPU, IndexedDB,
  процесс Node, Postgres, внешние сервисы), и что они шлют друг другу. На каждой стрелке —
  типы сообщений, а цвет и штрих линии показывают силу контракта: *связан* (одна таблица
  типов проверяет обе стороны, как у сокетов), *назван* (обе стороны берут тип из shared, но
  каждая сама), *с одной стороны* (тип только у одной стороны или каст), *без типа* (байты,
  чужой API). Описание — `runtime.yaml`.
- **Потоки** — что происходит во времени: штрих от пера до чужого экрана, вход в комнату
  и восстановление картинки, отмена в четыре руки. Каждый шаг кликается в свой модуль или
  группу.
- **Здоровье** — нарушения архитектурных правил, повторяющийся код между модулями, самые
  крупные модули и файлы, ни на что не ссылающиеся файлы.

- **Понимание** — что из архитектуры Илья может объяснить сам (#628): покрытие по уровням
  дерева тем (обзор → подсистемы → механизмы → детали), доля кода и доля правок в понятых
  модулях, что изучать дальше и какие часто меняемые модули никто не понимает. Данные —
  `understanding.yaml`, правило — `.claude/rules.md` → «Понимание архитектуры». Чип
  «понимание» красит модули на «Структуре» по тому же статусу.

Имена типов и функций в тексте любой вкладки (`Operation`, `Dab`, `appendOperation`, модели
Prisma) подчёркнуты точками: клик показывает объявление прямо из кода и ссылку на строку (#632).
Сниппеты снимаются при сборке и только для того, что карта упоминает; если у имени несколько
объявлений (`Room` — проводной тип и модель Prisma), показаны все.

## Модули и слои (#642)

Карта показывает проект **как он есть**: ничего из того, что на ней нарисовано, не
придумано поверх кода.

- **Модуль — это папка с `README.md`.** Любая папка в `apps/`, `packages/`, `scripts/`, `e2e/`,
  где лежит README с шапкой. Его id — путь папки от корня репозитория
  (`apps/web/src/pages/Room`); на карте он подписан путём без `apps/web/src/` (или без
  `apps/` / `packages/`) и словами из шапки в скобках.
- **Папка без README принадлежит ближайшему модулю выше.** `stores/slices/` — часть
  `stores`, `engine/testing/` — часть `engine`.
- **Вложенная папка со своим README — подмодуль.** Это отдельная карточка; в панели видно,
  куда она входит и какие подмодули у неё самой. Файлы подмодуля родителю не принадлежат.
- **Слой — метка в шапке README**, а не папка. Список слоёв, их порядок и правило «кто кого
  может импортировать» живут в одном месте — `map.yaml` → `parts` и `layers`.
- **Группа карты** — ручная нарезка большой плоской папки (`pages/Room` — 180 файлов,
  `engine/src`, `components`, `stores` и другие; `server/src` и `lib` уже разложены — #649, #648) на смысловые куски, в `map.yaml` → `groupings`.
  В коде её нет, и карта так и пишет. Отдельной карточкой группа не рисуется — только в
  панели своего модуля. На группу можно сослаться по id (`room-net`) из потоков,
  `runtime.yaml` и `understanding.yaml` — клик откроет модуль с этой группой. Когда папку
  раскладывают по подпапкам (#646–#649), группа становится модулем: её текст переезжает в
  README новой подпапки, а запись из `groupings` удаляется.

### Правило слоёв

Слои в `map.yaml` перечислены слева направо в порядке зависимости. Модуль может
импортировать модули **своего слоя и слоёв правее**, но не левее. Сверх того каждая часть
(`parts`: сборка, клиент, движок, сервер, контракт) может импортировать только части из
своего `uses`: клиент не знает сервера и наоборот, движок не знает приложения, контракт —
лист.

Из этого `.dependency-cruiser.cjs` при каждом запуске генерирует по правилу на слой
(`layer-editor`, `layer-state`, …): берёт модули из шапок README и порядок из `map.yaml`,
так что перенести модуль в другой слой — одна строка в его README. Эти правила заменили
четыре ручных (`engine-knows-no-app`, `store-holds-no-ui`, `server-has-no-client`,
`shared-is-a-leaf`) — все четыре были частными случаями того же порядка.

### Как завести модуль

1. Положи в папку `README.md`:

   ```markdown
   ---
   layer: editor                 # обязательно: id слоя из map.yaml → layers
   summary: сокет и outbox       # обязательно: 2–3 слова, до 32 символов — подпись на карте
   adr: [002-collaborative-undo] # по желанию: файлы docs/adr без .md
   issues: [646]                 # по желанию: номера issues с открытыми вопросами модуля
   tags: [сеть, надёжность]      # по желанию
   ---
   # pages/Room/net — сокет и outbox

   Абзац «за что отвечает»: одна-три фразы о том, зачем эта папка существует. Карта берёт
   первый абзац после заголовка — это главное, что в ней написано.

   ## Заметки

   - Каждый пункт этого списка — заметка на карте: известный долг, грабли, «сначала прочти».
   - Всё остальное в README (другие разделы, примеры, команды) карта не читает — пиши как
     обычную документацию.
   ```

   Другие поля в шапке — ошибка (`map:check` назовёт опечатку). Слоя, которого нет в
   `map.yaml`, тоже быть не может: новый слой — осознанная правка `map.yaml`, а не побочный
   эффект.

2. Если папка отрезает кусок от большой плоской папки, у которой есть группы карты, —
   перенеси текст группы (`owns`, `notes`, `adr`, `issues`) в новый README и удали группу из
   `map.yaml` → `groupings` (или сузь её `files`). Если на группу ссылались `id` в
   `runtime.yaml`, `understanding.yaml` или потоках — замени ссылку на путь новой папки.
   `map:check` покажет каждую устаревшую ссылку и каждый glob, который больше ничего не
   находит.
3. `npm run map:check`, `npm run map:rules`, `npm run map`. Если `map:rules` нашёл импорты
   против слоёв, которых раньше не было видно (кусок уехал в другой слой), — это либо
   ошибка в выборе слоя, либо настоящий долг; второй — в базу (см. ниже) и в #650.

Папка без собственного README ничего не стоит: её файлы просто остаются в модуле выше.
README нужен тогда, когда у папки есть своя ответственность, которую стоит видеть на карте.

## Как оставить на экране только нужное

Три способа проредить карту, они складываются друг с другом:

| Что | Как | Отменить |
| --- | --- | --- |
| Свернуть слой целиком | клик по заголовку столбца | клик по свернувшейся полоске |
| Оставить модуль и его связи | «только соседи» / «соседи ×2» в панели модуля | ещё раз ту же кнопку, или Esc |
| Убрать один квадрат | «скрыть» в панели модуля | «показать всё» слева внизу |
| Оставить только найденное | ввести запрос в поиск → «оставить найденное» | «показать всё» |

Поиск ищет по пути папки, подписи, описанию, группам и файлам. Сколько модулей показано — в
пилюле слева внизу, там же кнопка возврата. Заголовок частично проредённого слоя показывает
`3/4`. Ссылка на скрытый модуль в боковой панели нарисована тускло и по клику возвращает его
на экран. Набор скрытого лежит в `localStorage` и переживает перезагрузку — если карта
открылась «неполной», это он.

## Из чего она собрана

| Половина | Откуда берётся | Может ли протухнуть |
| --- | --- | --- |
| Связи, размеры, дубли, история правок, нарушения правил | `dependency-cruiser`, `jscpd`, `git log` — пересчитывается каждый раз | нет |
| Модули: слой, подпись, «за что отвечает», заметки, ADR и issues | `README.md` в папке модуля, руками | да — поэтому есть `map:check` |
| Слои и правило импорта, группы карты, бюджеты, потоки | `map.yaml`, руками | да — поэтому есть `map:check` |
| Разрез «Исполнение», карта понимания | `runtime.yaml`, `understanding.yaml`, руками | да — сверяются с кодом в `map:check` |

## Команды

```
npm run map         пересобрать map.html
npm run map:check   упасть, если код и карта разошлись
npm run map:rules   упасть на новом нарушении слоёв или другой архитектурной границы
```

Последние две стоят в CI (`ci.yml` и `deploy.yml`) рядом с typecheck/lint/test.

## Что делать, когда CI ругается

**`map:check` упал: файл вне любого модуля.** Появилась папка верхнего уровня, над которой нет
ни одного README (например, новая папка прямо в `scripts/`). Положи в неё `README.md` по
образцу выше. Если новые файлы легли внутрь существующего модуля — ничего делать не нужно,
они уже его.

**`map:check` упал: ошибка в описании модуля.** В шапке README нет `layer` или `summary`,
слой не объявлен в `map.yaml`, подпись длиннее 32 символов, неизвестное поле, после шапки нет
абзаца. Сообщение называет файл и поле.

**`map:check` упал: группы карты.** Glob в `map.yaml` → `groupings` больше ничего не находит
(код переехал), файл попал в две группы сразу, или поток / `runtime.yaml` /
`understanding.yaml` ссылается на модуль или группу, которых нет. Файл в модуле с группами,
не попавший ни в одну группу, — не ошибка: он показан «вне групп», `map:check` только
напоминает об этом.

**`map:check` упал на бюджете.** Файл перерос свой потолок длины из раздела `budgets` в
`map.yaml` (#493). Сейчас потолок есть у одного файла — `Room/index.tsx`: его месяц резали на
хуки, а новые фичи за тот же месяц добавили в него примерно столько же, сколько вынесли. Новое
клади рядом — хуком или модулем в `pages/Room/` — и оставь в `index.tsx` только вызов. Если
без этого действительно никак, подними `maxLines` отдельной строкой и напиши в коммите почему:
смысл правила в том, что рост становится решением, а не случайностью.

Работает как храповик и в обратную сторону: вынес код — опусти `maxLines` в том же изменении.
`map:check` сам подсказывает, когда запас от потолка перевалил за сотню строк.

**`map:rules` упал на `layer-*`.** Модуль импортировал модуль из слоя левее своего или из
части, которую его часть не `uses`. В сообщении — какие слои ему можно. Три честных выхода:
развернуть импорт (обычно — вынести общее вправо, туда, откуда его могут брать оба); если
модуль на самом деле живёт не в том слое — поменять `layer` в его README и сказать об этом в
коммите; если слой не тот у целой группы модулей — поменять порядок в `map.yaml` отдельным
коммитом с объяснением.

**`map:rules` упал на другом правиле.** Пересечена граница, которую мы объявили в
`.dependency-cruiser.cjs` руками, — например, что-то снаружи движка импортировало
`engine/src` напрямую, минуя `engine/index.ts`. Либо чини импорт, либо, если граница больше не
та, меняй правило осознанно и отдельным коммитом.

### Существующий долг

54 известных нарушения лежат в `.dependency-cruiser-known-violations.json` и не роняют CI —
они видны на вкладке «Здоровье»: 23 импорта против слоёв (`layer-*`, разбор — #650), 13
прямых заходов в `engine/src` мимо фасада, 14 циклов и 4 ни на что не ссылающихся файла
(последние два — предупреждения). Это сознательный выбор: гейт должен ловить новое, а не
требовать разгрести старое одним заходом. Когда починишь часть — пересними базу:

```
npx depcruise-baseline apps packages > .dependency-cruiser-known-violations.json
```

## Ограничения, о которых честно

- Группы карты — наше решение, а не факт из кода: это разбиение плоской папки, которое
  существует только в `map.yaml`. Поэтому страница везде подписывает их «группировка карты»,
  и поэтому их цель — исчезнуть, когда папку разложат по-настоящему.
- `map.html` коммитится. Он собирается из репозитория, но лежит в git, чтобы карту можно было
  открыть, не запуская ничего. Пересобирай его, когда правишь README модулей, `map.yaml` или
  когда картина заметно изменилась.
- «Исполнение» нарисовано руками, но сверяется с кодом строже потоков: `map:check` падает,
  если событие сокета или REST-ручка есть в коде, но нет в `runtime.yaml` (и наоборот), и если
  тип, подписанный на стрелке, нигде не объявлен. Не проверяется только сила контракта —
  её выставляют руками.
- Потоки нарисованы руками. `map:check` следит только за тем, что упомянутые в них модули и
  группы существуют, — не за тем, что описание шага всё ещё правда.
