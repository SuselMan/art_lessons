# Карта архитектуры

`map.html` — одна самодостаточная страница: открывается двойным кликом, работает без сервера
и без интернета, весит ~250 КБ. Три вкладки:

- **Структура** — квадраты модулей по слоям. Клик открывает панель: за что модуль отвечает,
  из чего состоит, кто на него опирается и на кого опирается он, какие ADR и issues его
  объясняют, какие правила он нарушает и с чем у него совпадает код. Синие связи входят,
  оранжевые выходят, красные идут против порядка слоёв, пунктир — импорт только типов.
- **Потоки** — что происходит во времени: штрих от пера до чужого экрана, вход в комнату
  и восстановление картинки, отмена в четыре руки. Каждый шаг кликается в свой модуль.
- **Здоровье** — нарушения архитектурных правил, повторяющийся код между модулями, самые
  крупные модули и файлы, ни на что не ссылающиеся файлы.

## Как оставить на экране только нужное

Пятьдесят семь квадратов сразу — это карта местности, а не рабочий стол. Три способа
проредить её, они складываются друг с другом:

| Что | Как | Отменить |
| --- | --- | --- |
| Свернуть слой целиком | клик по заголовку столбца | клик по свернувшейся полоске |
| Оставить модуль и его связи | «только соседи» / «соседи ×2» в панели модуля | ещё раз ту же кнопку, или Esc |
| Убрать один квадрат | «скрыть» в панели модуля | «показать всё» слева внизу |
| Оставить только найденное | ввести запрос в поиск → «оставить найденное» | «показать всё» |

Сколько модулей показано — в пилюле слева внизу, там же кнопка возврата. Заголовок частично
проредённого слоя показывает `3/4`. Ссылка на скрытый модуль в боковой панели нарисована
тускло и по клику возвращает его на экран. Набор скрытого лежит в `localStorage` и переживает
перезагрузку — если карта открылась «неполной», это он.

## Из чего она собрана

| Половина | Откуда берётся | Может ли протухнуть |
| --- | --- | --- |
| Связи, размеры, дубли, история правок, нарушения правил | `dependency-cruiser`, `jscpd`, `git log` — пересчитывается каждый раз | нет |
| Названия модулей, «за что отвечает», заметки, ссылки на ADR и issues, потоки | `map.yaml`, руками | да — поэтому есть `map:check` |

## Команды

```
npm run map         пересобрать map.html
npm run map:check   упасть, если код и карта разошлись
npm run map:rules   упасть на новом нарушении архитектурной границы
```

Последние две стоят в CI (`ci.yml` и `deploy.yml`) рядом с typecheck/lint/test.

## Что делать, когда CI ругается

**`map:check` упал.** Появился файл, который не описан ни одним модулем. Открой `map.yaml`,
допиши его в подходящий модуль — или заведи новый и напиши в `owns` две фразы о том, зачем он
нужен. Две фразы — это и есть вся цена поддержки карты. Он же ругается на обратное: glob,
который больше ничего не находит (код переехал), и файл, который claimed двумя модулями.

**`map:rules` упал.** Пересечена граница, которую мы объявили в `.dependency-cruiser.cjs` —
например, что-то снаружи движка импортировало `engine/src` напрямую, минуя `engine/index.ts`.
Либо чини импорт, либо, если граница больше не та, меняй правило осознанно и отдельным
коммитом.

### Существующий долг

39 нарушений, которые были на момент заведения карты, лежат в
`.dependency-cruiser-known-violations.json` и не роняют CI — они видны на вкладке «Здоровье».
Это сознательный выбор: гейт должен ловить новое, а не требовать разгрести старое одним
заходом. Когда починишь часть — пересними базу:

```
npx depcruise-baseline apps packages > .dependency-cruiser-known-violations.json
```

## Ограничения, о которых честно

- Модуль — это набор globs, а не папка. Это позволяет разрезать `pages/Room` (сто файлов)
  на осмысленные куски, но означает, что разбиение — наше решение, а не факт из кода.
- `map.html` коммитится. Он собирается из репозитория, но лежит в git, чтобы карту можно было
  открыть, не запуская ничего. Пересобирай его, когда правишь `map.yaml` или когда картина
  заметно изменилась.
- Потоки нарисованы руками. `map:check` следит только за тем, что упомянутые в них модули
  существуют, — не за тем, что описание шага всё ещё правда.
