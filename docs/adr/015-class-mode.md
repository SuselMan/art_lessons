# ADR 015: Работа в классе — личные доски учеников

## Статус

**Принято**, эпик #595, релиз-трек #314 §11. Реализовано в ветке `agents/595-class-mode`;
отличия от первоначального текста — в §10.

Заведено 24.09 по итогам поиска первых пользователей (#592): школы ведут групповой
урок в две фазы — демонстрация на общем холсте и самостоятельная работа, где у каждого
своё место, а учитель обходит и правит. Вторую фазу сейчас делают в Miro, где нет
нажима (`docs/COMPETITORS.md`). Решения Ильи по продукту — в комментарии к #595:
видимость чужих работ — настройка урока; учитель правит и аннотациями, и прямо в работе;
личная доска стартует пустой, но источник стартового содержимого — параметр.

Строится целиком на досках (ADR 014). Всё, что там сказано про `lessonOf`, каналы
сокета и переключение, здесь не повторяется.

---

## §1. Контекст

Сценарий урока, который закрываем:

1. Учитель объясняет на своей доске, ученики следуют (есть, ADR 014).
2. **Учитель раздаёт задание** — каждый ученик оказывается на своей чистой доске.
3. Ученики рисуют, **учитель видит сетку всех работ**, заходит к любому, правит
   аннотациями или прямо в работе, идёт к следующему. Ученик может **поднять руку**.
4. Учитель **показывает одну работу всем** — групповой разбор.
5. **«Все ко мне»** — класс возвращается на доску учителя. Работы остаются у учеников.

Что уже есть и на что опираемся (проверено по коду 24.09):

- Доска = `Room` с `lessonId`; свой лог, undo, снапшоты, `RoomThumbnail`. Социальное —
  у урока через `lessonOf`. Каналы сокета: урока и доски.
- `ownerId` у доски есть, но это копия владельца урока (`boardRoutes.ts:132`): своего
  владельца у доски нет. Ролей в комнате две, `owner | member`, вычисляются при входе
  (`rooms.ts:1001`). Учитель = владелец урока.
- Аннотации (#508–#511) — операции лога доски, рисуются SVG-оверлеем и **никогда** не
  попадают в пиксели слоёв, снапшоты, экспорт и превью (`shared/src/index.ts:1427`).
  То есть правка учителя поверх работы, не трогающая работу, уже есть.
- Превью: клиент запекает раз в 100 операций и при размонтировании движка
  (`snapshotSync.ts:60, :177`). Путь дорогой: полный композит, `readPixels` всего холста,
  PNG полного размера, декод, уменьшение, повторное кодирование. **Сокет-события о новом
  превью нет** — лента досок видит только то, что было на момент входа
  (`BoardStrip.tsx:42`). Лимита частоты на загрузку превью нет (`rateLimit.ts:42`).
- Все события досок уходят в канал урока, то есть **всем участникам** (`BoardNotifier`).
  Для досок, которые ученикам видеть нельзя, это не годится.

## §2. Модель данных

Две новые сущности: **задание** (группа личных досок одного раунда) и **личная доска**
(доска с владельцем внутри задания).

```prisma
model Assignment {
  id          String         @id @default(cuid())
  lessonId    String
  lesson      Room           @relation("LessonAssignments", fields: [lessonId], references: [id], onDelete: Cascade)
  name        String                         // «Задание 1» по умолчанию
  order       Int
  seed        AssignmentSeed @default(blank) // чем засеять личную доску
  seedBoardId String?                        // для seed = copy_board, не в MVP
  createdAt   DateTime       @default(now())
  endedAt     DateTime?
  boards      Room[]         @relation("AssignmentBoards")
  @@index([lessonId, order])
}

enum AssignmentSeed { blank  copy_board }  // copy_board — после релиза

enum ClassVisibility { teacher_only  class }

model Room {
  // ... всё из ADR 014
  assignmentId       String?           // != null ⇔ личная доска
  assignment         Assignment?       @relation("AssignmentBoards", fields: [assignmentId], references: [id], onDelete: Cascade)
  boardOwnerId       String?           // владелец личной доски (ученик)
  // только у урока (lessonId = null):
  activeAssignmentId String?           // идущее задание; null — задания нет
  spotlightBoardId   String?           // «показать всем»; null — нет
  classVisibility    ClassVisibility @default(teacher_only)
  @@unique([assignmentId, boardOwnerId])
}
```

Инварианты, проверяются сервером:

- `assignmentId != null` ⇔ `boardOwnerId != null`, и у такой доски `lessonId != null`.
- Одна личная доска на ученика в задании (`@@unique`).
- Идущее задание одно на урок. Новое задание раздаётся, только когда предыдущее
  закончено («Все ко мне»).

### Почему задание — отдельная таблица, а не флаг на доске

За урок бывает несколько заданий («куб», потом «цилиндр»). Работы одного раунда
нужно показывать сеткой вместе, а работы разных раундов не смешивать. Ученик,
пришедший посреди задания, должен получить доску именно этого раунда. Всё это —
вопросы к группе, а не к отдельной доске. Имя, порядок и `seed` тоже принадлежат
раунду.

### Почему `seed` в модели уже сейчас

Решение Ильи: стартуем с пустой, но оставляем пространство для манёвра. Засев копией
доски учителя — это существующая процедура форка одной комнаты (ADR 014 §5,
`forkRoutes.ts`), вызванная для каждой личной доски. Если поле будет с первого дня,
его добавление — это новое значение enum и одна ветка при создании доски, без
миграции данных.

## §3. Права

| Действие | Кто |
|---|---|
| Раздать задание, закончить, «показать всем», сменить `classVisibility` | учитель (владелец урока) |
| Видеть личную доску (превью, `join_room`, `GET /thumbnail`, `/snapshots`) | учитель; владелец доски; остальные ученики — только при `classVisibility = class` |
| Рисовать и аннотировать на личной доске | учитель и владелец доски |
| Поднять и опустить руку | свою — любой ученик; любую — учитель |

Проверка рисования — одна новая ветка в `getOperationRejectReason` (`rooms.ts:1448`):
если у доски есть `boardOwnerId` и пишет не он и не владелец урока — `board_not_yours`.
Ставится **до** короткого замыкания для владельца, чтобы порядок гейтов читался сверху
вниз. Остальные гейты урока (закрыт, заморожен, замок слоя) действуют как везде:
заморозка урока останавливает и личные доски. Это полезно («карандаши на стол»).

Проверка видимости — одна функция `canSeeBoard(userId, board)`. Её зовут `join_room`,
REST-маршруты содержимого и **адресная рассылка** (§4).

После «Все ко мне» личная доска **остаётся открытой для владельца**: работу можно
закончить после урока. Это же мостик к домашке (#317): «взять в работу» с личной доски
уже форкает текущую доску (ADR 014 §5).

## §4. Сервер: события и адресная рассылка

### Адресная рассылка

Всё, что касается конкретной личной доски (её создание, превью, переименование),
нельзя слать в канал урока при `teacher_only`: ученики получили бы чужие id и превью.
Заводится помощник `emitToBoardViewers(lesson, board, event, payload)`:

- `classVisibility = class` или доска общая (не личная) → `io.to(lessonId)`, как сейчас;
- иначе → сокеты учителя и сокеты владельца доски. Реестр урока знает участников и
  их сокеты, отдельные socket.io-каналы на пользователя не нужны.

`room_state.lesson` собирается так же, для получателя: общие доски, свои личные и
остальные личные, если их можно видеть.

### События

| Клиент → сервер | Кто | Эффект |
|---|---|---|
| `assignment_start { name? }` | учитель | Создаёт `Assignment` и личные доски всем ученикам, которые сейчас в уроке (одна транзакция). Пишет `activeAssignmentId`. Шлёт `assignment_started` в канал урока, а каждому ученику — его `board_created`. |
| `assignment_end` | учитель | Пишет `endedAt`, обнуляет `activeAssignmentId` и `spotlightBoardId`, шлёт `assignment_ended`. |
| `set_spotlight { boardId \| null }` | учитель | Пишет `spotlightBoardId`, шлёт `spotlight_changed`. `boardId` — только личная доска идущего задания. |
| `set_hand_raised { raised, userId? }` | ученик — о себе; учитель — о любом | Флаг на участнике в памяти (не в БД), `participant_hand_changed` в канал урока. |
| `set_class_visibility { value }` | учитель | Пишет колонку, шлёт каждому пересобранный `lesson_state`: набор видимых досок меняется у всех. |

| Сервер → клиент | Канал |
|---|---|
| `assignment_started { assignment }`, `assignment_ended { id }`, `spotlight_changed`, `participant_hand_changed`, `class_visibility_changed` | урок |
| `board_thumbnail_updated { boardId, updatedAt }` | адресно (`emitToBoardViewers`) |

**Ученик, пришедший посреди задания.** `join_room` урока видит `activeAssignmentId`.
Если у ученика нет личной доски в этом задании, она создаётся лениво — так же, как при
раздаче. Отсутствующим на уроке доски не создаются: в сетке нет пустых плиток за тех,
кого нет.

**Переход учителя на личную доску — обычный `join_room`, не `set_active_board`.**
`activeBoardId` по-прежнему значит «доска урока, на которой учитель ведёт», и указывает
только на общие доски. Иначе вход после конца задания и перезагрузка ученика попадали
бы на чужую работу.

### `board_thumbnail_updated` чинит и старую дыру

Событие шлётся после любой загрузки превью, не только личного. Лента обычных досок
тоже начинает видеть чужие превью вживую. Это закрывает «принятую дыру первого
среза» из `BoardStrip.tsx:42`.

### Лимит частоты на превью

`POST /thumbnail`: не чаще одного раза в 3 с на доску. Лишнее отвечает 429, клиент
молча пропускает. Это первый лимит на этом маршруте (#324 оставлял его открытым), и
сетка «класс» — первый сценарий, где частые загрузки ожидаемы.

## §5. Дешёвое живое превью

Сетке нужны превью раз в несколько секунд с планшета, который в это время рисует.
Существующий путь (§1) для этого слишком дорогой: `readPixels` всего холста и два
PNG-кодирования на планшете дают заметную паузу. Пре-продакшн правило из
`.claude/rules.md` — делаем правильный путь, а не реже зовём дорогой.

**`engine.bakePreview(maxSide = 320)`:** композит слоёв рендерится сразу в маленький FBO
цепочкой уменьшений в 2 раза на GPU (бокс-фильтр, шейдеры WebGL1). Каждый шаг сохраняет
зерно и тон, без алиасинга одного большого шага. `readPixels` ≤ 320×320 (≈400 КБ RGBA),
затем `canvas.toBlob('image/webp', 0.8)` с откатом на PNG. Тот же метод заменяет
внутренности `uploadThumbnail`: у превью досок и у сетки один путь.

**Когда печь.** На личной доске при идущем задании:

- **перо в покое ≥ 1.5 с** после последнего pen-up — во время штриха никогда;
- с прошлого превью были операции (своими или учителя);
- с прошлого превью прошло ≥ 5 с;
- плюс существующие триггеры: каждые 100 операций и размонтирование.

Превью — локальная картинка на устройстве, и между устройствами оно может чуть
расходиться. Это не противоречит правилу кросс-девайсного детерминизма из
`.claude/rules.md`: превью не содержимое холста, а его снимок, и на общий холст оно не
влияет.

**Цена.** 20 учеников × ~30 КБ WebP раз в ≥ 5 с — в худшем случае ~120 КБ/с входящего
на сервер и 4 upsert-а `RoomThumbnail` в секунду. Учителю уходит 20 событий по ~60 байт
плюс перезапрос только изменившихся плиток. Приемлемо на текущем VPS, мерить в e2e.

## §6. Клиент

### Куда следует ученик

`followTarget` (`lib/boards.ts:93`) расширяется. Для ученика в режиме следования:

```
spotlightBoardId
  ?? (activeAssignment ? myBoardIn(activeAssignment) : null)
  ?? activeBoardId
  ?? lessonId
```

Учитель, как и раньше, не следует. Ученик, ушедший с цели руками, выходит из
следования и видит чип. При задании в чипе «Вернуться к своей работе», при разборе —
«Учитель показывает работу Маши», иначе — прежний «учитель на доске N».

### Стор

`roomSlice` получает `assignments`, `activeAssignmentId`, `spotlightBoardId`,
`classVisibility`, `handRaised: Set<userId>`. `BoardSummary` получает
`ownerId?` и `assignmentId?`. Личные доски **не** попадают в ленту досок (при 20
учениках она стала бы бесполезной) — у них своя сетка.

### Интерфейс учителя

- **«Раздать задание»** — в ленте досок, рядом с «+». Необязательное имя,
  стартовое содержимое (в MVP только «пустая доска»).
- **Сетка «Класс»** — полноэкранный оверлей с плитками. Плитка: превью, имя, точка
  «на уроке», поднятая рука, «обновлено N назад» (из `updatedAt` превью). Сначала
  поднятые руки, потом по имени. Кнопки на оверлее: «Показать всем» (с выбором
  плитки), «Все ко мне».
- **На личной доске ученика** — верхняя полоса «← Класс · ‹ Маша › · Показать всем».
  Стрелки листают учеников по порядку сетки — «обойти класс». Инструмент при входе
  переключается в режим аннотаций, переключатель «править в работе» рядом: правка
  поверх — поведение по умолчанию, правка в пикселях — осознанное действие.
  При выходе исходный инструмент возвращается.
- Вход на личную доску — полный вход на доску (ADR 014 §4), но доска стартовала
  пустой и содержит одно задание, так что загрузка короткая.

### Интерфейс ученика

- При раздаче ученик в режиме следования оказывается на своей доске. В ленте — общие
  доски и одна плитка «Моя работа».
- **Рука** — кнопка в верхней панели на всё время урока, не только на время задания.
- Когда на его доске учитель — баннер «Учитель смотрит вашу работу» (из `boardId`
  участников, уже есть).
- При `classVisibility = class` — та же сетка «Класс», только для просмотра. Зайти на
  чужую доску можно, рисовать нельзя (сервер отвечает `board_not_yours`, клиент
  показывает её как закрытую, `editingBlocked`).
- Телефон — только просмотр, как в ADR 014.

### Настройка урока

`classVisibility` — поле во вкладке настроек комнаты (`SettingsPanel`) рядом с
инструментами, и в форме создания урока. По умолчанию `teacher_only`: начинающим
показывать работу всем неловко, открыть можно в любой момент.

## §7. Форк и шаблоны

- **Форк урока из «Моих уроков»** (ADR 014 §5) копирует только общие доски. Задания и
  личные доски — работы учеников конкретного занятия, в шаблон они не входят.
- **«Взять в работу»** с личной доски форкает её, как любую текущую доску. Ученик
  уносит свою работу домой.

---

## §8. Что откладываем

- **Окно с доской учителя у ученика** (картинка в картинке). Нужен второй вид на чужую
  доску без второго полного движка. Кандидат — поток превью из §5 доски учителя с
  более частым обновлением. Отдельная задача после релиза.
- **Засев копией доски учителя** (`seed = copy_board`). Модель готова (§2).
- **Удаление и переименование заданий**, просмотр сетки прошлых заданий. В MVP сетка
  показывает идущее задание. Прошлые работы доступны ученику, но не учителю в
  интерфейсе — только через данные.
- **Отдельный слой «Правка учителя»** для правки в пикселях. В MVP учитель пишет в
  текущий слой ученика, его операции — его, и undo ученика их не отменяет (ADR 002).
- **Со-преподаватели** (#90): учитель = владелец урока, модель прав расширяется одной
  функцией `isTeacher`.

## §9. Разбиение

Порядок снизу вверх, каждый шаг проверяется отдельно:

1. **Shared + Server: схема и права** — `Assignment`, поля `Room`, инварианты,
   `canSeeBoard`, `board_not_yours` в `getOperationRejectReason`, видимость в
   `join_room` и REST содержимого, фильтр форка урока.
2. **Server: события** — раздача (с ленивым созданием для опоздавших), конец задания,
   spotlight, рука, `classVisibility`, `emitToBoardViewers`, `room_state.lesson` для
   получателя, `board_thumbnail_updated`, лимит на `POST /thumbnail`.
3. **Engine: `bakePreview`** — уменьшение на GPU, WebP, замена внутренностей
   `uploadThumbnail`, триггер «перо в покое». Замер паузы на планшете до и после.
4. **Web: стор и следование** — новые поля, `followTarget`, чипы, обработка событий,
   живые превью в ленте досок.
5. **Web UI учителя** — «Раздать задание», сетка «Класс», полоса на личной доске
   с обходом, режим аннотаций по умолчанию, «Показать всем», «Все ко мне».
6. **Web UI ученика** — «Моя работа», рука, баннер, просмотр сетки при `class`,
   настройка в `SettingsPanel` и в создании урока.
7. **e2e**: учитель и два ученика → раздача → оба рисуют → превью доходят до учителя →
   учитель правит у первого аннотацией и в работе → рука второго → «Показать всем»
   второго → «Все ко мне» → работы на месте. Опоздавший ученик получает доску.
   При `teacher_only` ученик не может открыть чужую доску ни через сокет, ни через REST.

## §10. Что изменилось при реализации

- **Одно событие `lesson_state` вместо `assignment_started`, `assignment_ended`,
  `spotlight_changed`, `class_visibility_changed` и адресного `board_created`.** Каждое из
  них меняет набор досок, которые получатель вправе видеть, а этот набор у каждого свой.
  Сервер после раздачи, «Все ко мне», показа всем, смены видимости и создания доски
  опоздавшему шлёт каждому сокету урока его собственный `LessonState`. Отдельно остались
  `participant_hand_changed` (канал урока) и `board_thumbnail_updated` (адресно).
- **`assignment_start` с подтверждением** (`AssignmentStartResult`): `not_owner`,
  `already_running`, `server_error` — кнопке учителя нужен ответ.
- **`set_active_board` не принимает личную доску** — иначе визит учителя к ученику стал бы
  перелистыванием для всего класса (§4).
- **Раздача, «Все ко мне» и показ всем включают следование** у всех учеников, в том числе
  у ушедших на другую доску: это зов учителя ко всем. Смена видимости и доска опоздавшего
  следование не трогают.
- **Живое превью печёт один клиент на доску**: её ученик, а пока его на доске нет — учитель.
- **`classVisibility` в настройках** живёт во вкладке «Инструменты» комнаты и формы создания.

## §11. Пересмотр 24.09: список заданий и «где сейчас класс»

После первого показа Ильи. «Все ко мне» *заканчивало* задание, и вернуть класс к
работе было нельзя, а на уроке это обычный цикл: собрал всех, разобрал ошибку, отправил
дорисовывать. Отдельная кнопка «Класс» в шапке читалась как ещё один режим, а не как
часть урока.

**Модель.** Задание больше не заканчивается — у урока есть *список заданий*, каждое —
один холст на ученика. Класс в каждый момент в одном из двух мест:

- **«Все у меня»** (`activeAssignmentId = null`) — класс на доске учителя, старый режим;
- **«Все на задании X»** (`activeAssignmentId = X`) — каждый на своём холсте задания X.

Учитель переключает место одним событием `set_class_location { assignmentId | null }`:
«Все ко мне» — `null`, «Вернуть всех сюда» у задания в списке — его id. «Новое задание»
(`assignment_start`) создаёт холсты и сразу отправляет туда класс. Ученик, у которого
холста в этом задании нет (опоздал, пропустил раунд), получает его в момент, когда класс
туда отправляют. `Assignment.endedAt` больше не пишется; колонка остаётся, данных в ней нет.

«Показать всем» работает поверх любого места: показывать можно личную доску любого
задания урока. Смена места показ снимает.

**Интерфейс.** Вкладка «Участники» правой панели становится «Классом»:

- сверху — места: «Все у меня» и список заданий, у текущего отметка, у остальных
  «Вернуть всех сюда»; ниже — «Новое задание»;
- дальше — участники: рука у поднявшего (учитель опускает её нажатием), для учителя —
  переход к холсту ученика в текущем (или последнем) задании;
- поднятые руки считаются в бейдже вкладки вместе с очередью на вход;
- ученику та же вкладка показывает доску учителя и свои холсты по заданиям;
- большая сетка работ остаётся и открывается из панели кнопкой «Все работы» у задания.

Кнопка «Класс» в шапке, «Раздать задание» и «Моя работа» в ленте досок убраны: лента
снова только про страницы урока.
