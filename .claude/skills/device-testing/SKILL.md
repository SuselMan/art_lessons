# Тестирование на устройствах

Цель — мерить и проверять на тех устройствах, на которых Илья рисует, а не
рассуждать о них. Главный инструмент — **мост отладки дев-сборки**
(`apps/web/scripts/devBridgePlugin.ts`, клиент `src/dev/devBridge.ts`). Любая
страница дев-сервера здоровается через HMR-сокет Vite, а с этой машины в неё
можно выполнить код и забрать ответ, предупреждения и исключения. В
прод-сборке моста нет.

## Устройства

| Устройство | Браузер / GPU | Как достаём |
|---|---|---|
| Galaxy Tab S7+ | Chrome, Adreno | мост; плюс adb + CDP (см. `.claude/tablet-debugging.md`) |
| iPad | Safari 16, Apple GPU, ~3 ГБ | только мост: удалённого инспектора без мака нет |
| Surface | Chrome на Windows, Intel Iris Xe | мост |
| Ноутбук | Chrome с настоящим GPU (playwright headed) | мост; `scripts/devices/laptoppeer.mjs` |

Однократная настройка айпада (сертификат дев-сервера, автоблокировка) — в
`.claude/tablet-debugging.md`, раздел «iPad».

## Перед началом

1. Дев-сервер из **этой** ветки, с `--host`: мост и сессия (токен, адрес) —
   `apps/web/node_modules/.devbridge/session.json`. Своя ветка → свой
   изолированный стенд (см. память про изолированный стенд QA), не дев-сервер
   Ильи.
2. Экран ноутбука включён: `DISPLAY=:0 xset dpms force on; xset -dpms; xset s off`.
   Погасший монитор троттлит headed Chrome почти до нуля — «загрузка висит
   десять минут» бывало именно от этого.
3. Android: `adb shell svc power stayon true` на время замеров, в конце —
   `false`.
4. Илья открывает на устройствах любую комнату этого сервера. Дальше всё
   делается отсюда:

```sh
B="npx tsx apps/web/scripts/devbridge.ts"
$B clients                           # кто подключён: id, UA, адрес, экран
$B eval <page> '<js>'                # выполнить; ответ — JSON
$B logs <page> --follow              # warn/error/исключения страницы
$B eval <page> '__devNavigate("/room/<id>")'   # увести в другую комнату без диалога «покинуть?»
```

`<page>` — id страницы, часть её адреса (id комнаты надёжнее всего) или часть
UA. **Safari на айпаде представляется маком** («Macintosh»), `ipad` его не
найдёт.

## Порядок работы

1. **Паспорт каждого устройства**: GPU (`WEBGL_debug_renderer_info`), размер
   холста, DPR, `maxTouchPoints`, расширения. Цифры без паспорта не сравнить.
2. **Отдельная свежая комната** для замеров. Старая тестовая комната с
   огромным заливом делает каждое досыхание максимальным, и цифры уже ни с чем
   не сравнимы. Комнату, которую создал и тут же бросил headless-браузер,
   сервер считает несуществующей: создавать её надо живым участником —
   `laptoppeer.mjs` или формой `/create` на самом устройстве через мост.
3. **Плавность на одном устройстве**: `node apps/web/scripts/devices/penbench.mjs <page> 400 8 300 3`.
   Штрих генерируется внутри страницы через обработчики PointerInput движка —
   так же, как настоящее перо, — и считаются интервалы кадров. Альбомная
   ориентация, камера без поворота: повёрнутый холст выключает частичную
   перекомпоновку и стоит целых кадров.
4. **Все устройства сразу**: запустить ноутбук участником, увести остальных в
   его комнату и гонять сценарий:

```sh
node apps/web/scripts/devices/laptoppeer.mjs &            # создаёт комнату, пишет id в temp/device-runs/laptoppeer.room
room=$(cat temp/device-runs/laptoppeer.room)
for p in <android> <ipad> <surface>; do $B eval $p "__devNavigate('/room/$room')"; done
node apps/web/scripts/devices/multitest.mjs $room android=<id> ipad=<id> surface=<id> laptop=<id>
touch temp/device-runs/laptoppeer.stop                    # отпустить ноутбук
```

   Сценарий: все рисуют одновременно в одном слое вразброс, потом в двух
   слоях, потом в одном месте мокрым по мокрому; undo одного участника и
   «Высушить всё» другого; последние штрихи. После каждого раунда слои всех
   устройств сравниваются выборкой 48×48. Затем часть устройств
   перезагружается, и сравнение повторяется. Отчёт —
   `temp/device-runs/multitest-*.json`.
5. **Что считать провалом**: разные картинки одного слоя на разных
   устройствах (сверх шума разных GPU — единицы уровней); картинка, которая
   меняется после перезагрузки или undo; вкладка, которая перезагрузилась
   сама (сверяй `performance.timeOrigin` до и после — так Safari сообщает,
   что убил процесс по памяти); ошибки и `[invariant]` в `logs`; кадры дольше
   100 мс.
6. **Разбор рывка**, если он есть. Сначала выясни, чья это задача: long
   animation frame (`PerformanceObserver` `long-animation-frame` —
   `scripts[]`, `renderStart`) и размер кучи по кадрам
   (`performance.memory` в Chrome). Скрипт короткий, отрисовка поздняя, куча
   упала — это сборка мусора, а не GPU. Время GPU по шагу — `gl.finish()`
   вокруг шага. На планшете долгая синхронная работа дольше ~45–85 с рвёт
   сокет по ping timeout.

## После

- Отпустить устройства: `svc power stayon false`, остановить `laptoppeer`.
- Цифры, устройство и условия (ориентация, размер комнаты) — в отчёт Илье и в
  ADR фичи. Без условий цифры ничего не значат: сегодняшние «8 просевших
  кадров» оказались повёрнутым холстом в портрете.
- Ловушки, найденные в этот раз, — в `.claude/tablet-debugging.md` и в память.
