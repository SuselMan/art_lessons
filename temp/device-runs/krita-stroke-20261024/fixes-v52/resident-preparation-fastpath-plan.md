# Resident/idle metadata-only preparation: separate next plan

Scope is five existing production paths: TiledLayerBuffer.ts (PreparedLayerTargets), RibbonScratchPool.ts (RibbonScratchAcquisition), CanonicalLayerTargets.ts wrapper, CanonicalFrameExecutor.ts, CanonicalWashLayerCoordinator.ts. Tests in existing layer/pool admission, binding and executor files. No BrushGlBatch/BrushGlState/Pass/shader edits, registry or new scheduler.

Add atomic takeResident(index) -> actual target/buffer | undefined to the SAME prepared plan entries/held arrays. Undefined means only a valid missing allocation; closed/stale/index failures still throw. Pool taken failures still throw; layer existing take and new resident take remain repeatable against the same validated pinned target (no new layer taken ledger). Layer returns the already pinned exact resident identity after shared epoch/ledger/geometry validation, with no allocation/recovery/draw lease. Pool atomically transfers an already claimed idle buffer and marks its existing taken bit; a genuinely missing slot stays untouched and reserved. Factor index/current-plan validation with take(), including current storage validation of any held idle buffer so stale metadata never becomes allocation authority. No extra map or readiness cache. ContextStorageOwner validation is metadata-only. Wrapper forwards the operation through its existing owned-scratch map; explicit transfer/cancellation semantics stay unchanged.

Executor consumes resident/idle metadata steps without GL-state capture, checking the SAME existing turn clock after accepted steps. On the FIRST undefined/missing slot it enters the normal runBrushGlTurn(TEXTURE0), calls existing allocating take once, and returns; still at most one allocation per advance. All original-copy/local-clear steps and every pixel draw keep their existing full GL capsules and strict leases/certificates. A warm frame can reach those operations without wasting one frame/capture per metadata-only take; no general GL state guard is omitted from any GL-writing operation. Metadata failure remains fail-closed and all owners are retired, never converted into an allocation retry.

Coordinator uses the same operation on the current PresentationWork/Entry one-position plans. Stable/derived resident takes can proceed as metadata within that advance; a missing target takes the captured allocating branch once then yields. Two genuinely missing targets still need separate accepted allocation turns. Existing revision dirty union, pin cleanup before poison and all-attempt rollback remain.

Tests-first: actual healthy resident layer and idle pool take emits NO GL calls (including status/error/clear), no additional physical reservation, exact identity transfer once; undefined missing take emits no GL/mutation. Closed/taken/stale-epoch/stale-ledger reject rather than fallback. Same sparse bounds and64capacity unchanged. Warm executor capture/query count drops while pixel/draw order/opacity/epoch/leases remain exact; cold64tile witness still <=one allocation per advance. Warm coordinator stable+derived can fold in one ordinary captured pixel turn, cold pair still separate; mid-work invalidation/cancel/loss and hostile foreignunit5 survive. Counter comparisons use actual owner implementations, not a fabricated readiness boolean.
