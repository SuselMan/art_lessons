# Cooperative physical handoff: proposed narrow implementation

Actual HEAD after cc3d9b30e/100c287c9: no prepareCanonicalLayerFrame symbol exists in apps/packages. Executor enqueue reserves numeric upper bounds through reserveTransient, then paint uses resolveForPaint and scratch.acquire. Pool.prepareAcquisition already reserves only missing physical bytes and claims idle matches without GL allocation. Layer.withPaintTargetRects reserves only missing direct bytes but allocates the whole union synchronously. retainTargets and TileRebuildSession explicitly forbid surviving method/turn boundaries.

## Exact proposed production paths

1. buffers/TiledLayerBuffer.ts: factor existing validated sparse-union planner and add preparePaintTargetRects(rects). Returns bounded layer-owned metadata transaction (max64), not targets/GL leases. Prepare validates geometry, storage owner and current resident identities, pins those identities using the SAME retainedTargets bookkeeping, reserves missing direct bytes in existing ContextStorageOwner, allocates nothing. take(index) materializes at most ONE direct tile with that reservation, publishes only after successful clear, adds a resident pin before any subsequent resolution/eviction. withTarget(index, callback) is synchronous: current identity/storage validation, normal draw retention, no retained GL state. close releases all metadata pins and remaining reservation exactly once; materialized authoritative layer tiles remain owned by layer. No new global/handle registry. Existing synchronous APIs remain compatible; reuse shared validation/reservation helpers to avoid drift.

2. dabs/CanonicalLayerTargets.ts: introduce prepareCanonicalLayerFrame wrapper around actual layer transaction plus scratch.prepareAcquisition. Capture authoritative layer buffer+epoch from caller, bound source positions and pool requests, reserve metadata via existing CPU owner. No second physical numerical reservation: requests correspond only to actual new raw locals (plus originals for exclusive mode), target transaction only direct layer bytes. Existing pool allocations remain normally pool-owned after take. Wrapper close is all-attempt/first-error, returns untaken idle claims, never deletes foreign buffers. No new scheduler/queue.

3. dabs/CanonicalFrameExecutor.ts: keep existing <=8 frame queue and <=64 gesture tile map. After all metadata/source/admission validation, attach the bounded physical plan to existing Work. Replace numeric target/wash physical reserveTransient charges with the two real transactions (retain any explicitly documented logical engine fence separately, never count it as ContextStorageOwner bytes). Before painting, a cursor takes at most one missing direct tile OR one missing scratch per cooperative step, checks time after that accepted unit and yields at4ms; never eager take64. A wash pair may need two turns. Only after all pieces of the next wash tile exist, perform copy/clear in a synchronous runBrushGlTurn, publish WashTile and paint. No target draw lease, BrushGlTurn or GL state survives advance. New scratch locals stay owned by the existing bounded Work/washed-tile ownership until transfer; cancellation releases all taken buffers and closes untaken plan. Revalidate currentLayer identity/epoch and service/storage epochs before each step and before pixels. Work.releaseMetadata and fail/cancel close their plan idempotently before poison/rebuild can clear layer. No speculative cursor/ordinal advancement.

## Historical recovery boundary (explicitly NOT solved by bounded allocation)

rebuildTile() synchronously replays historical content before returning a TileRebuildSession; keeping that session across turns violates its current contract and can retain scratch GL resources. A single evicted request is therefore NOT a bounded operation today. Narrow first implementation must reject evicted-required plans BEFORE claims/reservations/pixels with an explicit recovery-required result/error; resident and genuinely new sparse targets are supported. Caller must perform existing trusted recovery outside this cooperative path before resubmission. This is a preparation slice, not full active-editor admission. Do not silently recover inside take, recreate one historical replay per tile, or claim a4ms bound. Supporting cold evicted history requires a separate reviewed existing-rebuild cursor change, beyond these three paths.
