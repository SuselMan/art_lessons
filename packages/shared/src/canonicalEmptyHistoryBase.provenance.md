# Complete empty-history prefix metadata (pure data only)

`CanonicalEmptyHistoryBaseV1` is a closed five-scalar schema for the reviewed small complete-prefix domain. No protocol field, server emission, client owner or engine activation is added by this module. A missing snapshot, numeric cut or locally empty log is not evidence that DB history is complete. The actual server read owner must separately verify every indexed global row through a captured durable cut, including a terminal empty query; the original client room owner must retain its current lifetime and exact tail identity before any execution.

`verifyCanonicalEmptyHistoryBase` accepts atoms from ONE existing `prepareCanonicalRecordedAttachment` call. That preparer already validates and bounds the normalized source dictionary, bytes and frames. One immutable capability object is interned per original-user/stroke. This verifier requires the SAME capability reference for that whole gesture, thereby fixing the complete snapshot (layer, brush, pigment, composition, material, budget and raster profile), not just the mask source. Equal-but-distinct page resources cannot substitute for one complete attachment. This is a local preparation invariant, not proof against arbitrary local JS manufacturing data.

The verifier checks global authoritative sequences exactly1..cut, unique IDs, room/epoch/read placement, materialV2 procedural frame-only domain and existing decoded cross-frame prefix/fence law. Interleaved authors may share a stroke ID. Open prefixes stay open; no end fence or count is invented. Controls, close, image, unknown and other writers remain outside this readiness domain. The existing1024-binding/64-capability/4MiB preparation envelope bounds initial readiness, not product lifetime compatibility.

Tests use actual shared source-bound preparation, not a fake execution owner: closed/accessor-safe metadata, cut0, interleaving, ordinal/phase/end/source changes, global holes/duplicates and unsupported writers. They do not prove missing entire DB gestures; actual indexed-query receipts belong to the server owner. Metadata copying grants no append, replay or layer publication authority.
