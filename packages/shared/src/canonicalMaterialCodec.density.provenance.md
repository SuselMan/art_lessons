# Closed seeded-density default-auto coverage contract

Coverage `neon64-f32-fma-seeded-density-v1` is structurally allowed ONLY under
existing genericSC V2 raster arithmetic. It is not a new compositor or a runtime
execution grant. No server policy/default, engine consumer or UI is activated.
The profile means existing neon base coverage, then committed visible quantized
A8 density cursor using an independently request-owned Taus88 stream. Seed tuple:
JSON([profile, originalGestureId, descriptorSha256, 'primary', cumulativeDrawOrdinal]),
Qt5 UTF16 QString hash, then existing KritaRandomSource initialization. This is
Grafetto deterministic behavior, not installed Krita applicator seed identity.
Current engine seed helper remains uncommitted WIP awaiting its actual consumer.

SourceData already represents density/randomness in finite[0,1]. The new explicit
DATA-ONLY extraction branch permits density[0,1]/randomness0; old extraction still
requires density1. Pin keys do not change. Profile-aware static normalization
preserves original density (static -0 normalizes0); old static callers stay closed.
Gaussian and soft profile unions are not widened. New data output still reports
rasterReady:false. Trusted source bindings continue to require original descriptor
verification and allowed outer composition; the packet never supplies authority.

Packed V2 auto layout remains96 bytes. Coverage code4 applies ONLY to default-auto
circle/rectangle tags; code1..3 stay unchanged. Density is reconstructed from the
validated trusted PRIMARY source pin, not guessed from shape or defaulted1. Initial
code4 contexts reject all mask sources and masked frames; all draws must be primary.
The pin must have matching code4 profile and full source/geometry checks must pass.
Changing valid trusted pin metadata is outside packet-level authentication: callers
must retain original verified descriptor identity; a pure codec cannot independently
prove that an arbitrary caller-provided descriptor SHA attests its numeric fields.

New-profile recipe dictionary identity includes density. Because different accepted
draw ordinals require distinct random masks, full base+density work and conservative
output volume are charged PER PHYSICAL DRAW, even when definitions deduplicate.
Density<1 adds one per-pixel stage before existing16Mi recipe-work capacity; density1
adds no stage/RNG. Existing image/auto profiles retain unique-definition accounting,
old costs/bytes and all limits. No clipped-draw work waiver, new quota or image plane.
Output plane dimension/storage bounds are unchanged; this accounting does not claim
simultaneous allocation of all generated outputs.
