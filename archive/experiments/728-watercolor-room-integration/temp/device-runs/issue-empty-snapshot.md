Ночной QA #745, найдено при расширении reconnect-проверки #767.

SnapshotIO.restore накладывает только пришедшие tiles, но предварительно не очищает прежний буфер. Пустой снимок [] оставляет старые пиксели сразу; частичный новый набор tiles оставляет старые пропущенные участки. Если новый снимок содержит только прозрачный tile, visible pixels стираются, но _pinSnapshotCheckpoint выходит без замены старого fromSnapshot CP — последующая пересборка может вернуть старый рисунок.

Ожидание: снимок заменяет состояние слоя полностью, включая пустоту. Новый пустой baseline должен иметь актуальный coveredSeq; pending tail и последующий Undo должны сохранять корректное покрытие. Существующий explicit-transparent upload audit и guarded history repair должны пройти без регрессий.

Подготовка регрессий и локального исправления идёт в рамках ночной интеграции, без push/deploy. Release track #314.
