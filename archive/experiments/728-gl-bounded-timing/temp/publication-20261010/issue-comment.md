### Ручная проверка WebGPU — неудовлетворительный результат

Илья после просмотра Samsung: «webgpu стенд я посмотрел — работает очень плохо». Это отрицательный human gate, не завершённая/готовая оптимизация.

Стенд: `agents/728-native-current`, `5c479178`, native DEV ON. Secure context/navigator.gpu/native initialization были подтверждены, но **этого недостаточно для проверки рисования**. При закрытии сервер показал повторяющийся runtime error: `DEV WebGPU Room supports exactly one actual 1024 origin-zero tile` (RoomNativeRuntime.consume). Для ручного просмотра был ошибочно создан обычный лист A4 1240×1754, который выходит за ограничения этого native прототипа. Ошибка подготовки стенда признана; нельзя приписывать весь отзыв только этой ошибке или утверждать качество модели по инициализации. Полноценный multitile остаётся открытым блокером.

### Дальнейший процесс

Параллельные самостоятельные исследовательские потоки не возобновлять. Сначала вместе с Ильёй выбрать одно направление и конкретный пользовательский сценарий; затем идти одним потоком: небольшое изменение → необходимые проверки → ручная валидация Ильёй → решение о следующем шаге. Критерий новой художественной WebGPU-модели не обязан быть полной пиксельной копией WebGL1; для оптимизации неизменённой модели эквивалентность остаётся полезным контролем. WebGPU текущего прототипа не считается готовым по результату ручной проверки.

Собственный manual WebGPU frontend остановлен; его ADB reverse/CDP forwarding и карточка сервиса удалены. Общий QA backend и чужие стенды не затрагивались.
