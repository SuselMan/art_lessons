# Эксперимент: пространственный перенос пигмента

Исходник: HEAD11ee5ab6, отдельная ветка agents/324-live-spread-morph.
Демо: http://127.0.0.1:8794 (VPS loopback; существующие стенды не менялись).

Сделан density transport: 900000 квантильных частиц переносят поглощение RGB
между реальными wet/dry PNG, промежуточная плотность получается splat. Никакого
подмешивания сухого RGBA в промежуточные кадры справа нет; слева корректный
premultiplied crossfade для контроля.

Два воспроизводимых случая: плотный зигзаг листа6 и пересечение листа9.
У зигзага движения p50=1.65px, p95=7.21px, max29.98px. На последовательности
видно изменение внутреннего рисунка одновременно с движением формы.
На пересечении p50=2.15px, p95=8.78px, но максимум354px. Визуально это
порождает ложные тонкие дорожки в белой области. **Этот алгоритм отвергнут для
интеграции**: глобальная CDF не знает, каким мазкам/пигментам принадлежат области.

На t=0/1 обе колонки Canvas побайтно равны. Конечный dry PNG скопирован
побайтно, SHA совпадает с исходным. Однако это не гарантия идеальной плавности:
реконструкция непосредственно перед endpoint даёт среднюю ошибку <1/255,
p99=9/255 и максимальную 58 (зигзаг)/88 (пересечение). Основная причина —
ресэмплинг острых краёв. Это нельзя скрыть заявлением «конечныйPNG тотже».

Playwright на VPS (только Canvas2D UI, не device-WebGL) прошёл оба случая,
слайдер/endpoints, ускорение до2сек, обычную8сек анимацию. Console/pageerrors=[];
endpoints=[true,true]; normal=1000; accelerated=1000. Видео и скриншоты вtemp/qa.
Samsung, Vega и пользовательская страница не использовались.

Вывод: масса должна перемещаться, а не просто появляться. Для следующего
производственного кандидата correspondence нужно получить локально из текущего
переноса на мокрой связной области (либо из его поля движения), применять к
одной видимой текстуре и ограничивать исправления плотности. Нельзя применять
глобальный opticalflow/CDF к целому слою: цвета и несвязанные мазки склеиваются.
Данная ветка добавляет только offline demo; canonical physics/undo/replay не тронуты.
