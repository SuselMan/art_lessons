# Перенос плотности вместо проявления

Изолированный offline эксперимент #324. Мокрый и сухой захваченные PNG из
`../transition_preview/assets` переводятся в массу пигмента по среднему поглощению
RGB над белой бумагой. Одинаковые детерминированные квантили выбирают 900 000
частиц в каждом распределении. Вертикальная маргинальная CDF и горизонтальная
условная CDF задают соответствие (Knothe transport). Частицы движутся между
этими координатами; их спектр/общая масса меняются, но сухая картинка не
подмешивается на месте. Плотность промежуточного кадра получена forward splat.

Это **не физическая модель**, не optical-flow crossfade и не готовый real-time
renderer. Глобальное соответствие может ошибочно перемещать пигмент между
несвязанными частями и смешивать цвета. Для движка нужно локальное соответствие
по мокрой связной области и текущим промежуточным полям, не CPU readPixels.
Проба сознательно проверяет сначала видимое качество пространственного переноса.

Запуск в отдельном dev-venv с numpy/Pillow:

```
python build.py <output-assets>
```

Скопировать `index.html` в каталог рядом с `assets/`, в который записаны кадры.
Сервить этот каталог обычным статическим HTTP. Две сцены, слайдер 0–100%,
проигрывание 8 секунд, ускорение оставшегося движения до 2 секунд.

При t=0/t=1 показываются исходные PNG, скопированные побайтно. Подсчёт ошибок
последнего реконструированного кадра хранится в cases.json: он выявляет возможный
скачок при замене реконструкции точным endpoint. Нельзя выдавать этот endpoint
контракт за доказательство плавности последнего кадра; смотреть численную ошибку.
Исходные сухие изображения, engine, checkpoints, Operation Log, undo/replay
и пользовательский стенд не меняются. Артефакты содержат animated WebP и timeline.

## Результат 05.10.2026

Зигзаг: медиана перемещения1.65px, p95=7.21px, максимум30px.
Пересечение: медиана2.15px, p95=8.78px, максимум354px; видны ложные тонкие
дорожки через белую бумагу. Глобальный CDF-кандидат **отвергнут для интеграции**.
Это рабочий comparison-прототип для проверки принципа пространственного движения.

Headless Canvas2D QA обоих случаев: console/pageerrors=[], ускорение2сек и
обычное8сек завершились, Canvas обоих вариантов при t=0/t=1 побайтно равны.
Проверка не использует WebGL/Samsung и не доказывает performance на планшете.
Реконструкция endpoint до замены точнымPNG: mean<1/255, p99=9/255,
max58/255 на зигзаге и88/255 на пересечении. Требуется решить ошибку
ресэмплинга/острых краёв, чтобы не было локальных скачков в конце.

## Второй эксперимент: local_build.py / local.html

Correspondence ограничен участками48×48px с четырьмя перекрывающимися
смещениями сетки. В каждом участке связные компоненты endpoint-support
обрабатываются отдельно. Если прямая траектория выходит из мокрой маски,
BFS задаёт кратчайший четырёхсвязный путь внутри компоненты. Перед рисованием
плотность обрезается маской, поэтому следов через пустую бумагу быть не может.
Маска в этом offline демо — объединение пигмента endpoint PNG с замыканием
мелких отверстий, **не настоящая карта воды движка**.

Статическая остаточная ошибка splat-реконструкции на endpoint интерполируется
отдельно, чтобы не оставлять последнюю замену с ошибкой до88/255. Это небольшая
коррекция деталей/ресэмплинга поверх пространственного переноса, а не claim о
полностью физической или полностью advective анимации. Основное цветовое поле
переносится частицами; изменение общей массы в клетке не объясняется водой.
Четыре смещения смягчают клеточные швы; не гарантируют их полного отсутствия.

Запуск: `python local_build.py <assets-dir>`; рядом разместить `local.html` под
именем `index.html`. Тот же интерфейс,65кадров,8секунд, ускорениедо2секунд.
Сухой endpoint показывается оригинальным PNG. История операций и shader source
не изменены. Это кандидат на визуальную оценку, не готовая интеграция.

`circulation.py <assets-dir>` дополняет локальный morph отдельно переключаемой
художественной циркуляцией. Низкочастотное curl-поле амплитудой до4px с envelope
sin(pi*t) двигает детали внутри мокрой маски и возвращается в ноль в конце.
Скорость/масса здесь не взяты из реального водяного solver: это презентационный
вариант, которому нужна отдельная субъективная оценка. Он может создавать
неправдоподобное обратное движение; его нельзя выдавать за физику растекания.
HTML интерполирует соседние заранее рассчитанные кадры для непрерывного rAF,
а не переключает65кадров ступенями. Неподвижныйdry не является основным слоем
в промежуточной анимации; интерполяция соседних движущихся кадров — техническая
временная реконструкция.
